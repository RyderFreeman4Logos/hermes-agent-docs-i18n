# 桌面设计系统

适用于 Electron 桌面应用（`apps/desktop`）的设计规范。在添加任何组件、叠加层或样式之前，请先阅读本文档。核心原则为：**功能专一、使用符号而非硬编码值、采用扁平布局而非嵌套框结构**。若您打算直接使用原始颜色、临时阴影、定制按钮，或为控件硬编码 `px-*` 值——请立即停止，因为已有对应的基础元素可供使用。

## 设计原则

1. **扁平布局，无嵌套框**。禁止使用多层卡片结构，面板内也不得设置分隔边框。应通过留白和细线进行分组，绝不可使用嵌套的圆角框。
2. **无边框 + 阴影实现层次感**。叠加层应依靠 `shadow-nous` 效果与 `--stroke-nous` 细线来呈现，而非依赖硬边界。
3. **功能对应单一基础元素**。每个功能应对应一个基础元素：一个 `Button`、一组控件变体、一个 `SearchField`、一个 `Loader`、一个 `ErrorState`。应直接使用这些基础元素，而非自行创建分支。
4. **使用符号而非硬编码值**。在组件中应引用 CSS 变量（如 `--ui-*`、`--shadow-nous`、`--theme-*`），绝不可直接使用十六进制颜色值或临时指定的 rgba 值。
5. **样式定义在基础元素中**。不同变体与尺寸应分别定义内边距、圆角、颜色及边框样式。调用处只需传递 `variant`/`size` 参数，无需通过 `className` 覆盖来重新指定这些属性。

## 表面与层次感

所有叠加层、对话框和提示信息（如启动失败提示、安装提示、通知、模型选择器、入门引导、提示框、更新信息以及基础 `Dialog`）均遵循以下规则：

```
shadow-nous           /* downward-weighted, layered contact→ambient falloff */
border-(--stroke-nous) /* currentColor hairline, theme-adaptive */
```

这两者均为 `src/styles.css` 中的 CSS 变量——只需在一处进行调整，所有组件便会自动继承该设置。  
请勿为每个叠加层单独添加 `shadow-[…]` 或 `border-(--ui-stroke-secondary)` 等一次性样式；若需更改层级效果，只需修改对应的变量值即可。

## 轮廓与颜色变量

| 变量名 | 用途 |
| --- | --- |
| `--ui-stroke-primary…quaternary` | 从深到浅的细线样式 |
| `--ui-stroke-tertiary` | 面板内分隔线及列表细线的默认样式 |
| `--stroke-nous` | 叠加层的细线样式（与 `shadow-nous` 搭配使用） |
| `--ui-text-primary / -secondary / -tertiary` | 文本层次颜色 |
| `--ui-bg-quaternary` | 按钮的柔和填充色（用于次要按钮） |
| `--chrome-action-hover` | 静态控件悬停时的填充色 |
| `--theme-primary`, `--ui-accent` | 品牌主题色/强调色 |

切勿直接硬编码 `border-gray-*`、`bg-white`、`text-black` 等值。`BrandMark` 组件中的白色背景是唯一允许的固定背景色（因为品牌标识需要固定的背景）。

## 按钮——单一组件

所有按钮的样式均来自 `src/components/ui/button.tsx`。只需选择 `variant` 和 `size`，**不得**传递 `h-*`、`px-*`、`py-*` 或图标尺寸相关的覆盖值。

**变体类型：**  
- `default`（主色调按钮）  
- `destructive`  
- `secondary`（柔和填充色的非主色调按钮，默认样式）  
- `outline`（透明背景，带 1px 内凹边框，无填充和阴影）  
- `ghost`  
- `link`  
- `text`（无边框的行内按钮，用于“取消”“清除”等操作）  
- `textStrong`（加粗下划线的行内按钮，用于“更改”“打开日志”等操作）

**尺寸类型：**  
- `default`  
- `xs`、`sm`、`lg`  
- `inline`（与文本对齐，无边框，适用于嵌入在标题或句子中的按钮；可替代 `h-auto px-0 py-0`）  
此外还有图标尺寸系列：`icon` / `icon-xs` / `icon-sm` / `icon-lg` / `icon-titlebar`

**注意事项：**  
- 文本按钮为正方形（无圆角），尺寸由内边距和行高决定（无固定高度）。仅有图标按钮具有统一的 4px 圆角。  
- SVG 图标会继承 `size-3.5` 的尺寸（在 `xs` 尺寸下为 `size-3`），无需重新设置图标尺寸。  
- 当按钮需要以链接或 Slot 的形式渲染时，可使用 `asChild` 实现多态化。

## 表单控件

- **`controlVariants`**（位于 `src/components/ui/control.ts`）是 `Input`、`Textarea`、`SelectTrigger` 等控件的通用样式基础。新的文本输入控件均基于此构建。  
- **`SearchField`**——无边框，聚焦时显示下划线，宽度自动调整。这是唯一的搜索输入框。请勿为其添加边框或封装在带边框的面板中；空列表会隐藏其搜索框。  
- **`SegmentedControl`**——用于处理少量互斥选项的场景（如颜色模式、工具调用显示方式、使用周期等），可替代传统的单选按钮组或药丸式布局。  
- **`Switch`**（尺寸为 `xs`）——仅包含基础样式及 `aria-label` 属性，无带边框的文本包裹层。

## 布局

- **内边距：** 使用 `PAGE_INSET_X`（位于 `src/app/layout-constants.ts`）设置页面两侧的内边距；使用 `PAGE_INSET_NEG_X` 可将子元素向边缘偏移。请勿在页面中直接硬编码 `px-6`/`px-8` 等值。  
- **主页/详情页叠加布局：** 采用 `OverlaySplitLayout` 结合 `OverlaySidebar`/`OverlayMain` 的结构。任务调度、用户资料等功能均基于此布局实现，无需重新构建标题栏外壳。  
- **行布局：** 使用 `ListRow`（定义于 `primitives.tsx`）来排列标签、描述和操作内容。这种布局为扁平式且左对齐，不会因每行添加内边距而影响标题的对齐效果。  
- **除非列表确实需要分隔线，否则不要在行与行之间添加分隔线**；优先使用适当间距。若确实需要分隔线，可使用单条 `--ui-stroke-tertiary` 颜色的细线即可。

## 反馈状态及空状态/错误状态/加载状态

- **加载中：** 使用 `Loader` 组件（位于 `src/components/ui/loader.tsx`），通过动画化的数学曲线或 ASCII 图形（长操作时使用 `lemniscate-bloom` 动画）来显示加载状态。切勿直接显示“Loading…”这样的文字。  
- **错误状态：** 使用 `ErrorState` 组件搭配标准的 `ErrorIcon`（无背景色方块），即可统一呈现 React 边界错误、对话框内错误以及启动失败提示等场景。请传递标题和描述对应的节点，以便 Radix 的 `DialogTitle`/`Description` 组件能够正常显示，从而提升无障碍体验。  
- **日志显示：** 使用 `LogView` 组件——无背景色，仅有细线边框，内边距紧凑，字体为小型等宽字体。所有需要展示原始日志的地方均应使用该组件。  
- **空状态：** 使用 `EmptyState`/`EmptyPanel` 组件，无需自行实现居中的空状态界面。

## 图标与品牌标识

- 图标集统一使用 `Codicon`，不得在代码中混用不同的图标库。  
- 品牌标识为 `BrandMark` 组件（位于 `src/components/brand-mark.tsx`），即白色背景上的圆形品牌标志“nous-girl”，边缘经过柔和圆角处理，亮色和暗色版本外观一致。该图标已取代了旧版本中分散在各处的 Sparkles 图标，适用于首页、引导流程及关于页面等场景。请在关键的品牌展示位置使用此图标，切勿再次引入装饰性的星星或闪光图标。

## 动画效果

- 动画过渡应快速且实用（控件动画时长约 100 毫秒）。对于除淡入淡出之外的动画效果，需尊重用户的 `prefers-reduced-motion` 设置。  
- 多元素依次退出的动画序列（例如引导流程中的“矩阵式”淡出效果）应先让各个元素逐个消失，然后再整体淡出背景——外层容器的淡出效果应适当延迟，以避免遮盖内部的动画。切勿让全局淡出效果抢在细节动画之前完成。

## 国际化

- 所有面向用户的字符串内容均需通过 `useI18n()` 函数处理（位于 `src/i18n/context.tsx`），JSX 中不得直接出现硬编码的字符串。  
- **需同时更新所有语言版本**，包括 `en`、`ja`、`zh`、`zh-hant`。如果在 `en.ts` 中修改了字符串而未同步更新其他语言文件，就会导致样式异常（如标点符号位置错误、标签显示不一致等问题）。请确保这四种语言版本的标点符号和语气风格保持一致。

## 状态管理（TypeScript）

状态管理的风格与项目中的 TypeScript 规范保持一致（详见根目录的 `AGENTS.md` 文件）：

- 共享的、跨组件的状态应使用小型 **nanostores** 管理，避免通过 prop 逐层传递。每个功能模块负责管理自身的状态，共享状态则存储在 `src/store` 中。  
- 渲染组件通过 `useStore` 订阅状态，而非渲染相关的操作则通过 `$atom.get()` 读取状态。  
- 每个钩子仅负责单一的特定任务，避免过度复杂化。  
- 状态持久化功能应与对应的状态变量放在一起管理，保持路由结构的简洁性。  
- 公共属性推荐使用 `interface` 定义；可基于 React 原生类型进行扩展（如 `React.ComponentProps<'button'>`、`Omit<…>`）。

## 可操作性设计

- 在组件底层（如按钮、下拉菜单/选择框）应默认设置 `cursor-pointer` 属性，无需在每个使用位置单独硬编码。  
- 全局焦点环样式需统一重置；标题栏中的操作按钮没有激活背景状态。  
- 按下 `Esc` 键可关闭所有可关闭的叠加层或对话框（安装向导和引导流程除外）；关闭按钮应使用 X 图标，而非“Close”文字。

## 添加新功能前的检查清单

- [ ] 是否可以复用现有的基础组件（如 `Button`、`SearchField`、`SegmentedControl`、`ListRow`、`Loader`、`ErrorState`、`LogView`），而非重新创建？  
- [ ] 是否使用了变量（如 `--ui-*`、`shadow-nous`、`--stroke-nous`）来管理样式，避免了直接使用原始颜色或一次性设置的阴影效果？  
- [ ] 是否没有通过 `className` 覆盖基础组件的内边距、尺寸、圆角或边框样式？  
- [ ] 叠加层是否使用了 `shadow-nous` 和 `border-(--stroke-nous)`，而非硬编码的边框样式？  
- [ ] 布局是否为扁平式——没有嵌套卡片结构，也没有不必要的行分隔线？  
- [ ] 新增或修改的字符串内容是否已同步更新到所有四种语言版本中？  
- [ ] `cursor-pointer`、焦点环以及 `Esc` 键关闭功能是否正常工作？
