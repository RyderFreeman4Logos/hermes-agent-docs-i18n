# 不同输出目标对应的引用格式

账本系统不限制格式：`sources.py render --style ...` 用于生成区块内容，而该文件则规定区块应放置的位置以及内联标记的样式。

## Markdown / 聊天回复格式

在句子后直接添加内联格式的 `[n]`，并在文末以块级格式呈现：

```
## Sources

[1] https://example.com/a — Page title
[2] https://example.com/b
```

`--style plain` 选项会为聊天回复生成简洁的 `Sources:` 标题，因为在这些场景中使用 Markdown 标题只会造成视觉干扰。

## 通过 LaTeX 生成 PDF（`latex-pdf-report` 技能）

建议使用 `--style footnotes` 选项，并在首次使用时将每个 ID 映射为 `\footnote{}` 格式；或者保留数字标记并生成尾注部分。若需要类似参考文献格式的报告，`--style bibtex` 选项会以 `source<N>` 作为键值创建 `@misc` 类型的条目，可通过 `\cite{source3}` 进行引用，再由 BibTeX 自动渲染参考列表。

切勿混用两种格式：要么使用数字 `[n]` 加上“来源”部分，要么使用 `\cite{}` 结合 BibTeX。在同一文档中同时使用两种编号系统只会让情况变得更糟。

## Word 文档（.docx，`docx` 技能）

在供人工编辑的正文文档中，建议使用真正的脚注而非行内括号——审稿人通常期望看到 Word 格式的脚注。可将记录 ID 保留为脚注编号，这样即便基于 Markdown 的真实源文件进行 `verify` 操作也能正常工作，随后再从该 Markdown 文件生成 .docx 文档。

## 幻灯片（.pptx，`powerpoint` 技能）

在列表项中直接使用行内 `[n]` 标注，最后用 `--style plain` 选项生成一个“来源”幻灯片。切勿在正文列表项中放入网址——这会破坏布局，且在投影展示时也无法点击。

## 表格文件（.xlsx）

需添加一个包含 ID 的 `source` 列，同时通过 `render --style plain` 生成一个“来源”工作表。请勿将网址粘贴到数据单元格中。

## 维基/多页输出（`llm-wiki`、Obsidian）

每页的“来源”模块中，来自同一账本的标识符会在各页面之间共享。由于这些标识符代表着账本的身份，因此`[7]`表示在维基的任意位置都指向同一页——正是这种一致性，使得无需在同一个构建版本的不同页面之间重置账本。

## 研究论文

此类任务可交由`grounded-citations`技能处理。首先使用`--style bibtex`选项将内容导出为`references.bib`文件，随后再让该技能进行引用验证（它会通过搜索`.bib`文件中的`\cite{...}`格式来确认引用是否正确）。账本的职责仅限于生成经过验证的URL条目，而会议格式的规范则属于该技能的处理范畴。

## 代码与配置文件

生成的代码中不应包含引用信息。如果需要记录代码的来源信息，应将其写在提交消息、PR正文或文档标题中，而非散布在代码注释里。
