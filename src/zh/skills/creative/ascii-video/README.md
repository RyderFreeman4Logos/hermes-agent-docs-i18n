# ☤ ASCII视频生成

可将任意内容渲染为彩色ASCII字符视频。支持输入音频、视频、图片、文本或纯数学公式，输出MP4/GIF/PNG格式的视频序列。每个字符单元均支持完整RGB色彩显示，默认分辨率为1080p 24fps，无需GPU支持。

该功能专为[Hermes Agent](https://github.com/NousResearch/hermes-agent)设计，也可用于其他各类编程智能体。标准代码库位于此处，可通过PR同步至[`NousResearch/hermes-agent/skills/creative/ascii-video`](https://github.com/NousResearch/hermes-agent/tree/main/skills/creative/ascii-video)。

## 功能简介

这是一项能够指导智能体从零开始构建单文件Python ASCII视频渲染器的技能。智能体将掌握完整的处理流程：网格系统、字体光栅化、特效库、着色器链、音频分析以及并行编码。它负责编写渲染器代码，运行该程序并生成视频。

输出结果为真正的视频文件，而非终端转义码。视频帧由彩色字符网格构成，这些字符网格会与预光栅化的字体位图组合在像素画布上，再经过着色器处理后传递给ffmpeg进行进一步处理。

## 模式类型

| 模式 | 输入 | 输出 |
|------|-------|--------|
| 视频转ASCII | 视频文件 | 该视频内容的ASCII风格再现 |
| 音频响应型 | 音频文件 | 基于频率带、节拍和能量值生成的视觉效果 |
| 生成型 | 无 | 基于数学公式生成的程序化动画 |
| 混合型 | 视频 + 音频 | 带有音频响应型叠加效果的ASCII视频 |
| 歌词/文本 | 音频 + 定时文本（SRT格式） | 带有特效的卡拉OK风格文本显示 |
| TTS旁白 | 文本引用 + API密钥 | 包含打字效果及合成语音的旁白视频 |

## 处理流程

所有模式均遵循相同的6阶段处理流程：

```
INPUT --> ANALYZE --> SCENE_FN --> TONEMAP --> SHADE --> ENCODE
```

1. **输入阶段**：加载原始素材（用于生成内容时则无需输入）。  
2. **分析阶段**：提取每帧的特征。音频方面会进行6频段FFT分析、RMS值计算、频谱质心检测、平坦度分析、通量计算，以及基于指数衰减的节拍检测；视频方面则会提取亮度、边缘信息与运动特征。  
3. **场景功能**：直接输出像素画布。该功能可组合不同密度的字符网格、数值/色调场以及像素混合模式，所有视觉效果均在此阶段生成。  
4. **色调映射**：采用基于百分位值的自适应亮度归一化处理，并为每个场景设置独立的伽马值。黑色背景上的ASCII字符天生偏暗，线性乘法无法解决此问题，而该机制可有效改善。  
5. **阴影渲染**：通过`ShaderChain`（包含38个可组合的着色器）以及`FeedbackBuffer`来实现基于空间变换的时间递归处理。  
6. **编码阶段**：将原始RGB帧传递给ffmpeg进行H.264编码，随后对多个片段进行拼接，并同步处理音频数据。

## 网格系统

字符在固定大小的网格上渲染，通过叠加不同密度的网格来营造深度感。

| 大小 | 字体 | 1080p分辨率下的网格尺寸 | 适用场景 |
|------|------|------------------------|----------|
| xs | 8px | 400×108 | 高密度数据展示区 |
| sm | 10px | 320×83 | 雨滴、星场效果 |
| md | 16px | 192×56 | 默认平衡型 |
| lg | 20px | 160×45 | 易读文本 |
| xl | 24px | 137×37 | 大标题 |
| xxl | 40px | 80×22 | 极简巨型字体 |

在`sm`与`lg`两种网格上渲染同一场景后进行屏幕混合，可产生自然的纹理干涉效果；粗糙字符间的间隙能显现出细节。大多数场景会使用两到三种网格。

## 亮度场生成器（21种）

亮度场是构成视觉效果的核心元素，每种生成器都会产生一个范围在[0, 1]之间的二维浮点数组，将每个网格单元映射为对应的亮度值。

### 三角函数型（12种）

| 字段 | 描述 |
|------|------|
| 正弦场 | 多层正弦波叠加产生的干涉效果，适用于通用背景 |
| 平滑噪声 | 基于Perlin噪声的多倍频正弦波近似实现 |
| 环形场 | 同心圆环结构，由低频振动产生波动感 |
| 螺旋场 | 对数螺旋结构，可调节螺旋臂的数量与紧密程度 |
| 隧道场 | 无限深度的透视效果（基于距离的倒数映射） |
| 漩涡场 | 扭曲的放射状图案，角度随距离变化 |
| 干涉场 | 多个正弦波叠加产生的摩尔纹效果 |
| 极光场 | 水平方向的流动色带 |
| 波纹场 | 从可配置源点向外扩散的同心圆波 |
| 等离子体场 | 多个不同方向与速度的正弦波之和 |
| 菱形场 | 菱形或方格图案 |
| 噪声/静态场 | 每帧每个网格单元的随机闪烁效果 |

### 噪声型（4种）

| 字段 | 描述 |

### 模拟型（4种）

| 字段 | 描述 |

包含7种带符号的距离场基本形状（圆形、矩形、环形、线条、三角形、星形、心形），并支持平滑的布尔运算组合（并集、交集、差集、平滑并集/差集），可实现无限平铺。可渲染为实心填充或发光轮廓。

## 色调场生成器（9种）

可独立于亮度为每个网格单元确定颜色：固定色调、角度映射的彩虹渐变、距离梯度、时间循环旋转、音频频谱质心映射、水平/垂直渐变、等离子体变化，以及感知均匀的OKLCH彩虹渐变。

## 时间连贯性

## 混合模式与构图

提供20种像素混合模式，用于叠加不同画布内容：正常混合、正片叠底、减色混合、乘法混合、屏幕混合、叠加混合、柔光混合、硬光混合、差值混合、排除混合、彩色溢出混合、颜色烧录混合、线性光混合、鲜艳光混合、针状光混合、硬混合、变亮混合、变暗混合、颗粒提取混合、颗粒合并混合。同时支持sRGB与线性光混合模式。

**反馈缓冲区**：实现时间递归效果——每一帧都会与上一帧经过变换后的版本进行混合。提供7种空间变换：放大、缩小、顺时针/逆时针旋转、上下平移、镜像反射。还可为每帧添加色调偏移，以生成彩虹色轨迹。每个场景可单独配置衰减速度、混合模式与透明度。

**遮罩功能**：提供16种遮罩类型，用于空间合成：形状遮罩（圆形、矩形、环形、渐变遮罩）、程序化遮罩（任何亮度场均可作为遮罩，还包括文本模板）、动画遮罩（光圈开合、擦除、溶解效果）、布尔运算（并集、交集、差集、反相）。

**过渡效果**：包含交叉渐变、方向擦除、放射状擦除、溶解效果、故障切割效果。

## 场景设计模式

通过特定的构图模式，让场景看起来更有意图性，而非随机生成。

**层次结构**：背景层（营造朦胧氛围，使用高密度网格）、内容层（主要视觉元素，使用标准网格）、强调层（稀疏的高光点，使用低密度网格）。这三种层次各有功能，而非相互竞争的独立图层。

**方向参数变化曲线**：每个场景的核心参数都会在其持续时间内逐渐增加、加速或逐步形成。采用基于进度的公式（线性、缓出、阶梯式显示）来替代无目的的`sin(t)`振荡。

**场景概念**：场景围绕视觉隐喻构建（如出现、下降、碰撞、熵增等），并据此选择合适的层次结构、调色板与反馈机制。场景名称并非依据其产生的视觉效果而定。## 组合技术

包括反向旋转双系统、波浪碰撞、渐进式破碎（沃罗诺伊单元随时间不断增多）、熵效应（几何结构被反应-扩散过程逐渐占据），以及错开层级叠加（逐步增强式的内容构建）。

## 硬件自适应

系统会自动检测CPU核心数、内存容量、操作系统平台以及ffmpeg版本，进而调整工作进程数量、分辨率和帧率。

| 模式 | 分辨率 | 帧率 | 适用场景 |
|------|--------|------|----------|
| `draft` | 960x540 | 12 | 检查时间与布局 |
| `preview` | 1280x720 | 15 | 查看效果预览 |
| `production` | 1920x1080 | 24 | 最终输出 |
| `max` | 3840x2160 | 30 | 超高分辨率需求 |
| `auto` | 动态检测 | 24 | 根据硬件条件与时长自动调整 |

当预估渲染时间超过1小时时，`auto`模式会自动降低输出质量。内存不足的系统则会自动降级为720p分辨率。

720p分辨率的渲染时间约为上述数值的一半，而4K分辨率则约为四倍。

## 常见问题

**亮度问题。** ASCII字符在黑色背景上表现为小型亮点，大部分帧像素为背景色。直接使用线性的`* N`缩放方式会导致高光部分被裁剪且整体色调过暗。建议改用带有场景特定伽马值的`tonemap()`函数。默认伽马值为0.75，用于日晒效果的场景为0.55，用于海报化处理的场景为0.50。

**渲染瓶颈。** 用于合成字体位图的逐单元Python循环，其运行速度约为每帧100-150毫秒。若不使用Cython或C语言编写该部分代码，则难以避免此瓶颈。其他所有操作都应通过向量化处理实现，利用NumPy库操作。在效果处理函数中若对行或列使用Python循环，将会严重降低性能。

**ffmpeg死锁问题。** 在长时间运行的编码过程中，切勿将`stderr`设置为`subprocess.PIPE`模式，否则缓冲区在存储约64KB数据后进程就会挂起。应将标准错误输出重定向到文件中。

**字体单元高度问题。** 在macOS系统上，Pillow库的`textbbox()`函数会返回错误的高度值。建议使用`font.getmetrics()`方法来获取字体的“上升高度”与“下降高度”。

**字体兼容性问题。** 并非所有Unicode字符都能在所有字体中正确显示。系统会在初始化时对字体调色板进行验证，无法显示的字符会被 silently移除。
