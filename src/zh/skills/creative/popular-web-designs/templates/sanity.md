## 1. 视觉主题与氛围

Sanity的网站是一个面向开发者的内容平台，其设计风格类似夜间指挥中心——色调暗沉、结构严谨、层次分明。整个界面都建立在近乎纯黑的背景上（`#0b0b0b`），这种设计更像是为终端用户打造的工具的固有状态，而非简单的“深色模式”切换。与大多数内容管理系统中使用的柔和粉彩和插图不同，Sanity强调产品本身的特性：结构化的内容需要结构化的展示平台。

其独特的字体风格为waldenburgNormal——这是一种具有独特几何感的无衬线字体，字母间距极小（在显示尺寸下为-0.32px至-4.48px），使得标题呈现出高度精炼、经过精心设计的视觉效果。当标题字号设为112px且字距为-4.48px时，文字看起来几乎如同机器加工而成——就像精确切割的钢制字母。代码和技术标签则采用IBM Plex Mono字体，形成了两种不同的风格：一种具有编辑内容的权威感，另一种则体现开发者的专业性。

Sanity的独特之处在于其单色暗色调与鲜艳饱和度的强调色之间的巧妙搭配。其中性色系从纯黑开始，通过严格控制的灰度渐变过渡（`#0b0b0b` -> `#212121` -> `#353535` -> `#797979` -> `#b9b9b9` -> `#ededed` -> `#ffffff`），没有暖色或冷色的倾向，只有纯粹的、无色彩偏色的精准感。在这种严谨的背景之下，霓虹绿（display-p3绿色）和电蓝色（`#0052ef`）如同黑暗控制室中的信号灯般格外醒目。橙红色的操作按钮（`#f36458`）则为整体冷色调体系增添了唯一的暖色点缀。

**核心特征：**
- 以近乎纯黑的背景（`#0b0b0b`）作为默认的视觉环境——这不是某种“深色模式”，而是该平台的核心标识
- 使用waldenburgNormal字体，并在显示尺寸下设置极小的负字距，从而打造出精心设计的字体风格
- 纯粹的无色彩灰度体系——没有暖色或冷色倾向，只有纯粹的中性感
- 鲜艳的强调色：在暗色背景上使用霓虹绿、电蓝色（`#0052ef`）和珊瑚红色（`#f36458`）
- 主要按钮呈药丸状（半径为99999px），而次要操作按钮则采用柔和的圆角矩形（3-6px）
- IBM Plex Mono字体用于技术内容，与用于编辑展示的字体形成对比
- 暗色区域为全屏显示，内容则置于有明确最大宽度的容器中
- 所有交互元素在悬停时都会变为电蓝色（`#0052ef`），形成统一的“激活”信号

## 2. 色彩方案与用途

### 主品牌色彩
- **Sanity Black**（`#0b0b0b`）：作为主要的背景色和主导色。并非纯黑，但颜色已极为接近，给人以绝对黑色的感觉。是整个视觉标识的基础。
- **Pure Black**（`#000000`）：用于需要最大对比度的场景、深层叠加效果以及某些边框装饰。
- **Sanity Red**（`#f36458`）：主要的操作按钮颜色及品牌强调色——一种温暖的珊瑚红色，用作主要的行动号召颜色。用于“开始使用”按钮及核心转化节点。

### 强调色与交互色
- **Electric Blue**（`#0052ef`）：整个系统中通用的悬停/激活状态颜色。按钮、链接及所有交互元素在悬停时都会变为此蓝色。同时也被用作焦点环和激活状态的`--color-blue-700`颜色值。
- **Light Blue**（`#55beff` / `#afe3ff`）：用于强调背景、徽章以及浅蓝色表面的次要蓝色变体。
- **Neon Green**（`color(display-p3 .270588 1 0)`）：一种鲜艳的广色域绿色，用作成功状态及高级功能亮点的`--color-fg-accent-green`颜色值。在sRGB模式下则回退为`#19d600`。
- **Accent Magenta**（`color(display-p3 .960784 0 1)`）：一种鲜艳的广色域品红色，用于特殊强调场景。

### 表面色与背景色
- **Near Black**（`#0b0b0b`）：默认页面背景及主要表面色。
- **Dark Gray**（`#212121`）：用于卡片、次要容器、输入框背景以及基色背景之上的一些轻微叠加层的较高层级表面色。
- **Medium Dark**（`#353535`）：用于在暗色层次之间创造深度的第三级表面色及边框颜色。
- **Pure White**（`#ffffff`）：用于倒置布局区域、浅色文字以及特定按钮表面。
- **Light Gray**（`#ededed`）：用于倒置/浅色区域以及轻微背景染色的浅色表面色。

### 中性色与文本色
- **White**（`#ffffff`）：在暗色背景上的主要文本颜色，确保最佳可读性。
- **Silver**（`#b9b9b9`）：暗色背景上的次要文本、正文内容、柔和描述及占位符文字。
- **Medium Gray**（`#797979`）：用于元数据、时间戳以及非重点内容的第三级文本颜色。
- **Charcoal**（`#212121`）：在浅色/倒置背景上的文本颜色。
- **Near Black Text**（`#0b0b0b`）：在白色/浅色按钮表面上的主要文本颜色。

### 语义化颜色
- **Error Red**（`#dd0000`）：用于表示破坏性操作、验证错误及严重警告——一种纯度极高、饱和度极高的红色。
- **GPC Green**（`#37cd84`）：表示隐私/合规状态的绿色。
- **Focus Ring Blue**（`#0052ef`）：用于无障碍功能的焦点环颜色，与交互色相同。

### 边框系统
- **Dark Border**（`#0b0b0b`）：暗色容器上的主要边框——几乎不可见，旨在保持极简的视觉效果。
- **Subtle Border**（`#212121`）：暗色背景上输入框、文本区域及卡片边缘的标准边框颜色。
- **Medium Border**（`#353535`）：用于需要更明显边界以突出分隔的元素。
- **Light Border**（`#ffffff`）：用于倒置/浅色元素或需要对比分隔的按钮的边框颜色。
- **Orange Border**（`color(display-p3 1 0.3333 0)`）：用于突出显示/特色元素的特殊强调边框。

### 设计原则
- **超大负字距**：当标题字号达到72px及以上时，会使用较大的负字母间距（-2.88px至-4.48px），从而营造出极为紧凑、精心设计的视觉效果，使Sanity的字体风格有别于那些较为宽松的编辑类字体。
- **单一字体，多种用途**：waldenburgNormal既用于编辑展示内容，也用于功能性UI文本。其字重范围较窄（大多数情况下为400-425，仅小型标签为500-600），从而保持整体风格的一致性。
- **OpenType特性控制**：在字体应用中会刻意使用各种OpenType特性，包括在标题尺寸下使用`"cv01", "cv11", "cv12", "cv13", "ss07"`，在正文文本中使用`"calt" 0`，以此根据不同场景微调字符显示形式。
- **标题紧凑，正文宽松**：标题的行高为1.00-1.24（极为紧凑），而正文则采用1.50的行高。这种对比形成了清晰的视觉层次。
- **技术标签使用大写**：IBM Plex Mono格式的代码图注及小型标签通常会应用`text-transform: uppercase`属性，并搭配紧密的行高，从而为技术元数据营造出“系统输出”的视觉风格。

## 5. 布局原则

### 空间系统
基准单位：**8px**

| 符号 | 值 | 用途 |
|------|------|------|
| space-1 | 1px | 极细的间隙，类似边框的间距 |
| space-2 | 2px | 最小的内部内边距 |
| space-3 | 4px | 组件内部的紧密间距 |
| space-4 | 6px | 小型元素的间隙 |
| space-5 | 8px | 基准单位——按钮、输入框及徽章的内边距 |
| space-6 | 12px | 组件间的标准间隙，按钮的水平内边距 |
| space-7 | 16px | 区块内部的间距，卡片之间的间距 |
| space-8 | 24px | 大型组件的内边距，卡片内部的较大间距 |
| space-9 | 32px | 区块的较大内边距，容器间的分隔距离 |
| space-10 | 48px | 大型区块的垂直间距 |
| space-11 | 64px | 主要的区块分隔距离 |
| space-12 | 96-120px | 标题区域的垂直内边距，最大的区块间距 |

### 网格与容器
- 内容最大宽度：约1440px（根据断点推断）
- 页面两侧分隔距离：桌面端为32px，移动端为16px
- 内容区块采用全屏背景，内容居中显示且不超过该宽度
- 多列布局：桌面端为2-3列，移动端为单列
- 卡片网格：使用CSS Grid布局，保持16-24px的统一间距

### 空白设计理念
Sanity在设计中采用较大的垂直间距（64-120px）在深色背景上营造出足够的视觉呼吸空间。在各个区块内部，则保持较紧密的间距（16-32px），使信息以密集的形式呈现，同时通过较大的空白区域进行分隔。这种节奏让页面呈现出“滑动式”的视觉效果——每个区块都仿佛是一个独立的聚焦区域。

### 圆角半径标准

| 符号 | 值 | 用途 |
|------|------|------|
| radius-xs | 3px | 输入框、文本区域，以及需要轻微圆角的元素 |
| radius-sm | 4-5px | 次要按钮、小型卡片、标签等 |
| radius-md | 6px | 标准卡片、容器等 |
| radius-lg | 12px | 大型卡片、特性展示容器、表单等 |
| radius-pill | 99999px | 主要按钮、徽章、导航圆形按钮等 |

## 6. 深度与凸起效果

### 阴影系统

| 级别 | 值 | 用途 |
|------|------|------|
| Level 0（扁平） | 无 | 大多数元素的默认状态——依靠纯颜色差异即可营造深度感 |
| Level 1（微妙） | 0px 0px 0px 1px `#212121` | 类似边框的阴影，用于在不显示明显边框的情况下实现轻微的边界效果 |
| Level 2（聚焦状态） | 0 0 0 2px `var(--color-blue-500)` | 用于输入框及交互式元素上的焦点环效果 |
| Level 3（叠加层） | 背景模糊效果 + 半透明深色背景 | 用于导航叠加层、模态框背景等 |

### 深度设计理念
Sanity的深度表现方式几乎完全依赖**色彩差异**而非阴影效果。元素的凸起感通过表面颜色的变化来体现：`#0b0b0b`（底层）→ `#212121`（稍高处）→ `#353535`（更突出）→ `#ffffff`（最上层/反色）。这种设计方式非常适合深色界面，因为在这样的背景下传统的投影效果将不可见。仅有的阴影也采用环形阴影（0px 0px 0px Npx）或模糊背景效果（backdrop-filter），而非偏移阴影，从而保持整体扁平、精心设计的视觉风格。

基于边框的边界划分（1px实线，颜色为`#212121`或`#353535`）是主要的视觉分隔方式，边框的深浅程度经过调整，确保可见但不会过于突兀。该设计避免出现“悬浮卡片”的视觉效果——所有元素都仿佛固定在背景表面之上，而非悬停在其上方。

## 7. 应该做与不应该做的事

### 应该做
- 以无色系灰色调作为整体设计基础——严格保持中性风格，不添加暖色或冷色色调
- 在所有交互式元素上统一使用电蓝色（`#0052ef`）作为悬停/激活状态的颜色
- 对48px及以上大小的显示标题应用极大的负字母间距（-2px至-4.48px）
- 将主要行动号召按钮设计为圆形实心形状（圆角半径99999px），并使用珊瑚红色（`#f36458`）
- 对技术标签、标识及系统元数据使用IBM Plex Mono字体的大写形式
- 通过表面颜色变化（从深色到浅色）而非阴影来体现深度感
- 在深色背景下保持较大的垂直区块间距（64-120px）
- 对显示文本使用包含“cv01”、“cv11”、“cv12”、“cv13”、“ss07”等OpenType特性的字体

### 不应该做
- 不要在中性灰色调中添加暖色或冷色色调——Sanity的灰色均为纯无色系颜色
- 不要使用投影效果来营造凸起感——深色界面需要依靠色彩差异来体现深度
- 不要设置13px到99998px之间的圆角半径——系统规定从12px（大型卡片）直接过渡到99999px的圆形按钮
- 不要在同一个元素中同时使用珊瑚红色行动号召色与电蓝色交互色
- 不要使用过重的字体粗细（700及以上）——系统仅允许11px大写标签使用600粗细
- 在未检查灰度对比度的情况下，不要在浅色背景上放置浅色文字，或在深色背景上放置深色文字
- 不要使用传统的偏移盒阴影——仅允许使用环形阴影（0 0 0 Npx）或基于边框的边界划分
- 不要改变标题的行高——行高范围应为1.00-1.24，显示文本的行高绝不能超过1.5

## 8. 响应式设计行为

### 断点设置

| 名称 | 宽度阈值 | 行为表现 |
|------|----------|----------|
| Desktop XL | >= 1640px | 完整布局，内容宽度达到最大值 |
| Desktop | >= 1440px | 标准桌面布局 |
| Desktop Compact | >= 1200px | 稍微紧凑的桌面布局 |
| Laptop | >= 1100px | 列宽适当缩小 |
| Tablet Landscape | >= 960px | 开始出现2列布局，逐渐向单列过渡 |
| Tablet | >= 768px | 过渡阶段，部分元素会堆叠显示 |
| Mobile Large | >= 720px | 接近平板的布局 |
| Mobile | >= 480px | 单列、堆叠式布局 |
| Mobile Small | >= 376px | 最小支持的宽度 |

### 堆叠策略
- **导航栏**：在宽度小于768px时，水平链接会折叠为汉堡菜单
- **标题字体大小**：在不同断点下，字体大小从112px逐步缩小到72px、48px、38px，同时保持紧密的字母间距比例
- **网格布局**：在宽度约为960px时，从3列变为2列；在宽度小于768px时则为单列
- **卡片网格**：在移动端采用水平滚动方式，而非自动换行（从而保持卡片的宽高比）
- **区块间距**：在移动端，垂直内边距减少约40%（从120px变为64px、48px）
- **按钮尺寸**：行动号召圆形按钮的内边距保持不变，但字体大小会缩小；普通按钮的尺寸则保持固定
- **代码块**：支持水平滚动，同时保持等宽字体格式

### 移动端专属调整
- 全屏区块会填充整个屏幕，内部保留16px的间距
- 所有交互式元素的最小触摸目标区域大小为44px
- 在移动端尺寸下，标题的字母间距会略有减小（负跟踪值不再那么大）
- 图片容器会从固定宽高比变为全宽度显示，高度自动调整

### 修改指南
1. **从深色主题开始**：初始设置背景为 `#0b0b0b`，主文字颜色为 `#ffffff`，次要文字颜色为 `#b9b9b9`。
2. **添加结构框架**：使用 `#212121` 作为卡片背景，`#353535` 作为边框颜色，无需阴影效果。
3. **设置字体样式**：标题使用 Inter（或 Space Grotesk）字体，字距较紧；正文行高为 1.50。
4. **指定颜色规范**：行动号召按钮使用 `#f36458` 颜色，所有悬停及交互状态均使用 `#0052ef` 颜色。
5. **优化间距设置**：基础间距单位为 8px，板块内部间距为 24-32px，板块之间间距为 64-120px。
6. **添加技术标签**：为标签和元数据使用 IBM Plex Mono 大写字体。
7. **最终润色**：确保所有交互元素悬停时都变为 `#0052ef` 颜色，所有按钮均为圆角设计或仅有 5px 的微妙圆角，边框宽度均为 1px 的细线。
