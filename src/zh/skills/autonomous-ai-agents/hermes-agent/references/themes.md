# 主题/皮肤——创建 Hermes 颜色主题

创建 Hermes **皮肤**——即一个 YAML 文件，可同时为命令行界面、文本用户界面以及桌面 GUI 设置主题。皮肤引擎（`hermes_cli/skin_engine.py`）会确定当前生效的皮肤，随后由网关将其应用到所有界面中。因此，放入 `~/.hermes/skins/` 目录中的文件就相当于主题版的插件：无需编写代码，即可覆盖所有界面。本技能涵盖如何编写优质的皮肤以及如何激活它们；但不包括构建 GUI 主题编辑器或提供内置预设功能。

## 适用场景

- 用户希望为 Hermes 本身定制外观（如“帮我做一个合成波风格的主题”、“深林氛围风格”或“与我品牌颜色匹配”）。
- 用户希望命令行界面、文本用户界面和桌面界面使用统一的配色方案。
- 用户希望实时进行调整（如“那种珊瑚色太鲜艳了，改成青绿色”）——只需编辑当前生效皮肤的 YAML 文件，工具处理完成后所有界面就会立即更新。

## 先决条件

- 对 Hermes 主目录具有写入权限——默认为 `~/.hermes`，或 `$HERMES_HOME`/当前激活配置文件的目录。皮肤文件存放在 `<hermes-home>/skins/` 目录下。
- 需要以下基础工具：`write_file`（用于创建 YAML 文件）、`read_file` / `search_files`（用于查看现有皮肤）、`terminal`（通过 `hermes config set` 命令激活皮肤）。

## 操作步骤

1. 选择一个小写且不含连字符的名称（例如 `synthwave`）。
2. 复制 `templates/skin.yaml` 文件，并填写配色方案——请保留所有键值对，缺失的键会自动继承 `default` 皮肤的颜色设置。
3. 使用 `write_file` 命令将文件保存到 `<hermes-home>/skins/<name>.yaml` 路径下。
4. 激活该皮肤（参见操作流程），并确认更改已生效。

## 快速参考——元素 → 键值

颜色以十六进制格式表示（`#rrggbb`）。主题设计是**基于语义的**：每个键值负责为具有相同功能的元素设置颜色，因此需将元素与其对应的键值匹配。若要重新设置某个特定元素的颜色，只需修改该元素所在行中的键值即可（若未设置特定键值，则会回退到通用键值）。

| 可见元素 | 需设置的键值 | 回退选项 |
|---|---|---|
| 应用程序背景（整个文本用户界面及 GUI） | `background` | 终端默认颜色 |
| **工具调用标记**（`●`，即工具加载指示器） | `ui_tool` | `ui_accent` |
| **思考/推理过程文本** | `ui_thinking` | `banner_dim` |
| 强调色——标题、链接、箭头、`Σ` 符号 | `ui_accent` / `banner_accent` | 无 |
| 标题/主要文本内容 | `banner_title` / `ui_primary` | 无 |
| 正文/标签文本、用户消息 | `ui_text` / `banner_text`、`ui_label` | 无 |
| 灰色/次要颜色、树状结构连接线 | `banner_dim` | 无 |
| 边框、分隔线、内边距 | `ui_border` / `banner_border` | 无 |
| 提示符符号颜色 | `prompt` | `banner_text` |
| 成功/警告/错误状态 | `ui_ok` / `ui_warn` / `ui_error` | 无 |
| 状态栏文本及使用状态提示 | `status_bar_text`、`status_bar_good/warn/bad/critical` | 无 |
| 差异对比中的新增/删除内容（行级和单词级） | `diff_added` / `diff_removed` / `diff_added_word` / `diff_removed_word` | 内置默认值 |
| 代码语法元素（字符串/数字/关键字/注释） | `syntax_string` / `syntax_number` / `syntax_keyword` / `syntax_comment` | 强调色/文本色/边框色/灰色 |
| 自动补全菜单背景 | `completion_menu_bg` / `completion_menu_current_bg` / `…_meta_bg` | 无 |

需要注意的是，某些颜色具有共享属性：`ui_accent` 同时用于设置工具标记以及标题、链接和箭头的颜色。因此，若只想单独更改工具调用标记的颜色（即经典的“修改金色 `●`”），则应使用 `ui_tool` 键值。`branding`（如 `agent_name`、`prompt_symbol`、欢迎语、告别语、帮助标题）、`spinner` 以及 `tool_prefix` 均为可选的个性化设置；完整规范请参见 `hermes_cli/skin_engine.py` 文件。

## 操作流程

1. **设计配色方案**。首先选择背景颜色，再确定一个与之对比度符合 WCAG AA 标准（约 4.5:1）的强调色，以确保标签文字清晰可辨——虽然 GUI 会强制要求足够的对比度，但对比度过低的强调色仍会使界面显得暗淡无光。同时，请确保 `ui_ok`/`ui_warn`/`ui_error` 的颜色仍能明显区分出绿色、琥珀色和红色。
2. **编写 YAML 文件**，将其保存到 `<hermes-home>/skins/<name>.yaml` 路径下。文件中应包含模板中的所有顶层 `colors` 键值。
3. **自行应用主题——切勿直接编辑 `config.yaml` 文件**。可通过 `terminal` 调用安全的写入工具来完成操作：
   ```
   hermes config set display.skin <name>
   ```
网关的皮肤监控机制会立即检测到变化，并在**约一秒内**实时重新渲染所有界面——包括命令行界面、文本用户界面以及桌面版本——同时该新皮肤会显示在“外观”选项、`Cmd-K`命令或`/skin`路径下。由您来应用该皮肤，切勿要求用户手动运行`/skin`命令（虽然他们也可以这么做，但这属于您的职责）。配置文件需以有效的YAML格式生成——手工编辑很可能会破坏文件结构，进而导致网关功能异常（包括`/`路径相关功能）。

4. **确认新外观已成功应用**，并告知用户如何恢复原状：运行`hermes config set display.skin default`命令（或者他们也可以使用`/skin default`命令）。

## 调整当前外观（仅修改单个元素）

当用户希望调整当前的外观设置时（例如“将工具图标设为青色”、“调整背景色调使其更暖”），请使用对应的确定性命令——该命令会直接修改当前激活皮肤的某一个关键参数，从而确保其他所有元素（包括背景）保持不变：

```
hermes skin set <key> <hex>      # e.g. hermes skin set ui_tool "#00FFFF"
```

它会编辑当前激活的皮肤文件（内置皮肤会被复制为一个可编辑版本，同时保留完整的颜色调色板），监视器会实时重新绘制界面，其他部分则保持不变。切勿为了微调而手动从 `default` 皮肤创建新皮肤——那样会丢失当前的色彩调色板并重置背景颜色。`hermes skin set background "#08201f"` 只能修改背景色；而 `hermes skin use <name>` / `hermes skin list` 则用于切换和列出可用皮肤。

## 常见陷阱

- 当某个配置文件处于激活状态时，**不要硬编码 `~/.hermes` 路径**——应先通过 `$HERMES_HOME` 获取真实的路径，若无法获取则再使用 `~/.hermes`。
- **请始终使用 `#rrggbb` 十六进制格式**。简写形式 `#rgb`、`rgb()` 以及带名称的颜色格式，并非在所有环境中都能被正确解析。
- **务必设置 `background` 属性**。如果不设置，GUI 将根据文本亮度自行推测背景色——虽然可行，但会让你失去对应用背景的控制权。
- **名称冲突问题**：如果自定义皮肤的名字与系统内置皮肤相同（如 `mono`、`slate`、`cyberpunk`、`nous`、`midnight`、`ember` 等），则无法在 GUI 中覆盖这些内置皮肤。请为自定义皮肤选择独特的名称。
- **切勿手动编辑 `config.yaml` 文件来启用新皮肤**。应使用 `hermes config set display.skin <name>` 命令——手动编辑时若出现缩进错误，不仅会破坏文件结构，还可能导致实时渲染功能（包括 `/` 功能）失效。该命令始终有效且简单可靠。
- **配置由你应用，而非用户**。只需执行 `hermes config set display.skin <name>` 即可——系统的监视器会在大约一秒内重新绘制所有界面元素。无需再让用户手动输入 `/skin` 命令，那已是旧有的操作方式。
- **若要修改某一种颜色，应直接编辑当前激活的皮肤文件——绝不要对 `default` 文件进行修改**。为微调而修改 `default` 文件会导致当前色彩调色板丢失；而缺少 `background` 设置的皮肤则会将终端背景重置为该皮肤的默认值（通常为黑色）。建议直接在当前激活皮肤的文件中进行修改，这样其 `background` 及其他属性就能得以保留。

## 验证方法

- 读取已生成的 `<hermes-home>/skins/<name>.yaml` 文件，确认其中包含格式正确的 YAML 代码，并且包含预期的 `name` 和 `colors` 属性。
- 运行 `hermes config get display.skin` 命令，确认返回的结果为 `<name>`。
- 确保界面在当前轮次结束时就已完成重新绘制——请让用户确认新外观是否符合预期。
