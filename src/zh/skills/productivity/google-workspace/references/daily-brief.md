# 每日简报（Gmail + 日历）

基于 Gmail 和 Google Calendar 生成面向行动的当日或次日简报。当用户请求获取晨间简报、了解“日历上有哪些安排以及哪些邮件需要处理”、准备会议，或是查看明天的截止日期和冲突信息时，可调用此参考文档。核心的 SKILL.md 文件负责定义相关命令，而本文档则规定了简报的编写流程。

致谢：该工作流由 Ben Barclay（benbarclay）贡献。

## 流程说明

### 1. 确定日期与身份信息

确认 Google 账户、时区以及目标本地日期。应使用账户时区下的明确半开时间区间 `[day_start, next_day_start)`，而非模糊的“今天”筛选条件——因为账户时区与机器时区往往存在差异。一旦确定了精确的 UTC 时间区间及本地时间范围，此步骤即完成。

### 2. 获取日历事件

检索范围内的所有日历事件，包括已确认和暂定的会议、全天活动、差旅/占用状态、位置/视频链接、组织者信息以及参与者状态。同时识别连续事件之间的时间冲突以及不合理的差旅间隔。当所有分页数据均已获取，并且已刻意排除被拒绝或取消的事件后，此步骤即完成。

### 3. 获取相关的 Gmail 邮件线程

在限定的近期时间范围内进行搜索，同时查找与会议参与者、邮件主题、项目以及明确截止日期相关的邮件（操作符说明请参见 `gmail-search-syntax.md`）。完整读取所有相关邮件线程。切勿将所有未读的新闻邮件都纳入简报中。只有当某封邮件会改变准备工作、任务优先级或后续行动时，才将其包含在简报中。此步骤即完成。

### 4. 将邮件与会议关联

通过主题引用、参与者地址、公司/域名、活动标题以及项目上下文进行匹配。将模糊匹配视为建议而非事实——仅共享一个关键词并不足以建立关联。需提取相关文档、未解答的问题、预读链接以及需要做出的决策。当每场会议都有准备事项或明确标注“无准备需求”时，即视为完成。

### 5. 撰写摘要

请按以下顺序操作：

1. 会议日程概览
2. 时间冲突与衔接紧张的会议
3. 需要准备的会议
4. 紧急邮件与截止日期
5. 用户需跟进的事项
6. 等待他人处理的任务
7. 数据覆盖问题或连接器故障

排序时应依据影响程度和时间紧迫性，而非消息数量。当每项内容都明确标注了准备要求、截止日期、冲突情况或跟进原因时，即视为完成。

### 6. 提供有限的操作选项

只有在向用户展示相关操作后，才能起草回复、设置日历占位或添加任务——简短的请求并不等同于修改系统的授权。应使用主技能的命令来执行已获批的操作，随后再向用户确认执行结果。当每项获批的操作都对应了具体的 Google 对象 ID/链接以及正确的时间和接收者信息时，即视为完成。

## 常见误区

- 将账户时区与机器时区混淆。
- 将全天性日程隐藏在有时间限制的会议之下。
- 将暂定会议误认为是已确认的会议。
- 仅凭一个共享关键词就将邮件与会议关联起来。
- 在用户仅要求生成摘要时创建日历事件。

## 验证

- [ ] 需明确说明所覆盖的时间段及日历范围，或指出其中的空白期。  
- [ ] 所有的准备事项、截止日期以及冲突情况都必须关联到具体的事件或线程。  
- [ ] 任何变更都必须在经过呈现与审批后方可实施；已获批的修改内容还需被重新读取确认。
