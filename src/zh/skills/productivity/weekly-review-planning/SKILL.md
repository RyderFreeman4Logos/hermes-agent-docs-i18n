# 每周回顾与规划

在用户选定的系统中执行定时的每周重置操作。这是一项具体的重复性任务，而非通用的工作效率提升方法——`weekly-review`自动化蓝图会通过cron作业来调度它。

## 适用场景

- “帮我进行每周回顾。”
- “我之前承诺了哪些事项，有哪些正在落后的？”
- “根据我的日历、任务和笔记规划下周的工作。”
- “找出那些久未处理的项目和待办事项。”
- 当达到预定时间时，系统会自动触发每周回顾。

**不适用于**：每日简报（请参考`google-workspace`的每日简报功能）或单一收件箱分类处理（`email-inbox-triage`）。

## 执行步骤

### 1. 设置系统与时间范围

确认时区、回顾周期、规划时间跨度、权威的任务/项目存储库、日历、收件箱以及允许的写入操作。默认设置为仅查看推荐内容或草稿，而非直接修改数据。当所有潜在的数据冲突都有明确解决方案后，此步骤即完成。

### 2. 查看日历信息

加载`google-workspace`或相应的日历连接器。首先查看已完成周内的会议与承诺事项，接着查看接下来1-2周的截止日期、差旅安排、准备工作及时间安排。同时记录过去事件所衍生的后续行动以及未来可能出现的冲突。当回顾内容与规划范围均覆盖完整后，此步骤结束。

### 3. 清理临时收件箱内容

请查看任务收件箱、笔记（如 `obsidian`、`notion`）、标记过的邮件（由 `email-inbox-triage` 负责按主题进行分类处理），以及其他已指定的信息收集点。将每项内容转化为下一步行动、项目、待处理、已安排、以后处理、参考、归档或删除等处理建议。在范围获得批准之前，不得对任何内容进行修改。当所有未处理事项都被清点并明确记录后，即视为完成。

### 4. 整理正在进行中的项目

针对每个项目，需明确期望的结果、下一步行动、负责人、截止日期、阻碍因素、最近一次有意义的活动记录以及相关来源链接。对于那些没有下一步行动、错过截止日期、存在重复记录或状态矛盾的项目，需进行标记。当所有正在进行中的项目要么有明确的处理方案，要么被明确暂停时，即视为完成。

### 5. 审核待处理事项与承诺事项

找出用户做出的承诺以及他人尚未完成的事项。为这些事项提出包含具体日期和沟通渠道的跟进计划。切勿将沉默视为任务已完成。当每项待处理事项都有负责人以及明确的复查/跟进日期时，即视为完成。

### 6. 制定兼顾工作负荷的计划

估算固定的日程安排负担，选定少量每周需完成的目标以及近期的下一步行动。根据事项的重要性、截止日期、依赖关系和所需投入精力对它们进行排序；无需填满每一小时的空闲时间。当计划符合实际工作能力，并且明确了那些需要延后处理的工作内容时，即视为完成。

### 7. 应用已批准的更新

仅在获得批准的情况下，才可更新任务/项目信息、设置日历占用提醒、归档已处理完毕的事项，以及起草跟进邮件。需从数据提供方重新读取所有已修改的记录。当经验证的更新内容与审核总结一致时，即视为完成。

## 输出格式

1. 已完成的任务与已落实的承诺  
2. 过期或存在风险的项  
3. 待处理/需跟进的事项  
4. 拖延或状态模糊的项目  
5. 下周的成果规划及时间限制  
6. 待批准的修改建议  
7. 覆盖范围缺失处  

## 常见误区  

- 仅根据任务清单进行规划，未考虑实际时间安排。  
- 将所有未完成的任务都视为高优先级继续推进。  
- 为没有后续行动的计划标记为“进行中”。  
- 悄悄删除或重新安排个人承诺事项。  
- 将他人的沉默误认为是任务已完成。  

## 验证要点  

- [ ] 已涵盖已完成周及规划周期的内容，或明确说明了存在的缺失部分。  
- [ ] 所有标记为“拖延”/“待处理”的项都能追溯到具体的记录、事件或讨论线程。  
- [ ] 未经批准不得修改任何任务、事件或备注；所有已获批的修改均已重新读取确认。  
- [ ] 规划内容需明确列出被推迟的事项，而不仅仅是已选定的事项。
