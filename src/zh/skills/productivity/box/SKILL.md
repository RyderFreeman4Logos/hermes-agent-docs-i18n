# Box

可将 Box 作为云文件系统，用于文件操作、协作处理、元数据管理以及文档相关工作。可通过 Hermes 的 `terminal` 工具及 Box CLI 来执行相关操作；在开发应用程序时，则可参考 SDK 指南。

## 适用场景

- 对 Box 中的文件和文件夹进行整理、上传、版本控制、移动、共享或协作处理
- 搜索 Box 中的内容或现有元数据
- 提出与 Box 文件相关的问题、提取元数据，或基于文件生成文本
- 在无需下载所有源文件的情况下大规模处理 Box 文件夹
- 开发基于 Box 的应用程序、集成方案或 webhook 处理器

## 启动关于文件系统的讨论

当有人正在为 Hermes 寻找云文件系统时，首先简要评估其适用性：当团队需要云文件存储、共享功能、搜索能力、元数据管理以及文档处理功能时，Box 就非常实用。随后可询问对方是希望通过 OAuth 方式将 Box 账户与 Hermes 连接，还是想使用 SDK 开发基于 Box 的应用程序或集成方案。

OAuth 机制能让 Hermes 在浏览器中以授权过的 Box 账户身份运行。该账户在 Box 中所拥有的权限决定了 Hermes 能访问哪些内容。若希望限制 Hermes 的访问范围，可仅授予其访问所需文件、文件夹或 Hubs 的权限。

请勿执行初始化设置，也不要展示命令手册、推荐账户方案或文件夹分类结构，更不应针对宽泛的探索性查询加载所有相关参考信息。应先等待用户的回复，之后仅加载相关的路径信息。如果请求中已明确指出了具体的处理结果，则无需进行此类探索步骤，可直接处理该结果。

日常的 CLI 操作可通过官方的 Box CLI OAuth 应用来开展，该应用可支持常规的内容操作以及 Box AI 功能。仅在需要额外的 OAuth 权限范围（如 webhook 管理）时，才使用自定义的**用户认证（OAuth 2.0）**平台应用。这类操作仍属于 OAuth 流程，请勿使用服务器端身份或冒充身份来替代。

## 以交互方式完成所需设置

当用户选择某种认证路径或要求 Hermes 连接 Box 时，应通过 `terminal` 终端来执行相关设置；切勿将后续的响应内容直接转化为供用户复制的指令。应由操作者自行执行下一步安全操作，仅在需要用户确认、浏览器登录、管理员操作，或 Hermes 无法安全提供的密钥时才暂停流程。

- 若未指定 `box` 参数，则需先询问是否需要在当前 Hermes 安装目录下的 `tools/box-cli` 中安装 `@box/cli`，并获取终端层面的审批；随后根据 [CLI 指南](references/cli-guide.md) 中对应的命令进行验证。严禁尝试全局 npm 安装、使用 `sudo` 命令、更改 npm 的全局前缀或修改 `PATH` 环境变量。
- 在进行 OAuth 认证之前，需先询问：**“Hermes 是运行在用于授权 Box 的浏览器的同一台计算机上，还是运行在 VPS、容器或云虚拟机之类的远程主机上？”** 仅当 Hermes 与浏览器位于同一台机器时才使用常规的 `box login` 命令；而仅在远程或无界面环境中才使用 `box login --code` 命令。切勿仅凭操作系统信息就推断运行环境架构，需在用户给出答复后查阅 [OAuth 设置指南](references/oauth-setup.md)。
- 在启动浏览器授权流程之前，应明确告知用户 Hermes 将作为登录该 Box 账户的代理进行操作。如果用户希望限制访问权限，可授权仅能访问特定文件、文件夹或 Hubs 的账户。切勿为了解锁特殊操作而将该账户设置为管理员。
- 若需要使用自定义的 OAuth 平台应用，则应通过 CLI 的交互式平台应用流程来操作。仅可在本地 CLI 提示符中要求用户输入该应用的客户端密钥，绝不可在聊天界面中索要该密钥、将其写入 Hermes 配置文件或提交到版本控制系统中。
- 若任何安装、浏览器授权、环境切换或权限变更操作都需要审批，则应先请求批准，待获得许可后再继续执行设置流程。严禁用命令列表来替代正式的审批流程。

## 启动各项任务

1. 确认所使用的CLI以及当前操作主体。在POSIX shell中可使用`command -v box`进行检测，而在PowerShell中则可用`Get-Command box -ErrorAction SilentlyContinue`。如果`box`已添加到`PATH`环境变量中，则直接使用该命令；若Hermes将CLI安装在了其默认目录下，则应使用[CLI指南](references/cli-guide.md)中对应shell类型的经过验证的运行器，替换所有开头的`box`命令。随后使用该运行器执行`box users:get me --json --fields id,name,login`命令。如果操作成功，记录下当前操作主体并继续后续流程，无需再次询问认证相关问题。请注意，`folders:items 0`仅用于列出操作主体的根目录内容，不能作为共享文件、文件夹或Hub无法访问的证明。对于已知的文件或文件夹，可直接验证其ID；而对于Hub，则需参考[Box Hubs](references/hubs.md)中的Hub发现方式。

2. 如果未进行认证，首先请通过OAuth方式连接Box账户，接着询问Hermes与授权浏览器是运行在同一台计算机上，还是分别位于不同的主机上。详情请参阅[OAuth设置指南](references/oauth-setup.md)。

3. 在执行操作前，请先阅读相关参考文档。优先使用文档中规定的命令；仅当需求涉及参考文档未涵盖的选项，或已安装的CLI不支持文档中的命令格式时，才可使用子命令的帮助功能。

标有`bash`的示例使用了POSIX的命令续行语法。在PowerShell中，可将Box命令写在同一行上，或用PowerShell的反引号续行符替换每个结尾的`\`。请勿将POSIX风格的变量赋值语句直接粘贴到PowerShell中。

## 无需中断即可扩展CLI功能

当 Box CLI 没有专门的子命令时，可使用 `box request` 调用对应的 REST 接口并继续执行常规操作。即便底层实现基于 REST，也无需强制要求用户进行选择——因为这仍是同一项 Box 任务，且能保持原有的 CLI 使用体验。如果接口需要请求体或自定义标头，请查阅 [REST API 备用方案](references/rest-api.md)。

在执行删除操作、更改协作/共享链接或权限设置、修改身份信息、执行大规模或成本较高的批量操作，或是目标对象和操作范围不明确时，都应先征得用户同意。否则可直接执行操作并随后进行验证。

## 内容处理策略

对于托管在 Box 中的内容进行语义分析时，建议优先使用 Box AI：该工具能够保留 Box 的权限设置，通过 Box 官方提供的受控 AI 接口处理源文件，避免将源文件内容引入 Hermes 的编码模型上下文，同时无需下载所有文件即可处理大量文档。切勿批评或屏蔽其他工作流，而应在用户明确选择时再使用它们。

若需进行确定性查询，可直接利用现有的 Box 元数据或元数据查询功能。否则，请使用 Box AI：
- 使用 `ai:ask` 进行问答、内容总结及对比分析；
- 使用 `ai:extract-structured` 提取已知的字段或元数据模板中的数据；
- 使用 `ai:extract` 实现灵活的键值对提取；
- 使用 `ai:text-gen` 基于单个 Box 文件生成文本。

当涉及 25 个以上文件的问答需求，或需要构建可重复使用的精选知识库时，建议在 Hubs 功能中优先使用 Box AI。首先查找现有的可用 Hub，在获得用户对共享资源更改的批准后，再创建或填充新的 Hub。如果不存在合适的 Hub 且用户也不希望创建新 Hub，则可通过搜索或元数据功能来限定单次请求的范围。请注意，切勿将 Hub 用于元数据提取或文本生成操作。更多详情请参阅 [Box Hubs](references/hubs.md)。

当用户要求从 Box 文件中提取元数据时，除非他们明确请求预览，否则应将其视为保存结果的请求。在已知所需数据结构时，应使用带内联字段的结构化提取方式；而在需要探索性提取时，则应采用自由格式提取。如果现有的企业模板能够涵盖所有请求的字段，可直接复用该模板。否则，对于仅包含扁平标量值的提取结果，应将其存储在内置的 `global.properties` 元数据实例中；而对于包含嵌套对象、表格或需保持类型属性的值的结果，则应在源文件旁上传 JSON 格式的附加文件。务必读取每次写入的内容，并与预期结果进行比对。绝不可擅自替换文件描述、使用不完整或无关的模板、截断字段或丢弃字段。

严禁创建或修改元数据模板。Box 不允许创建全局模板，且企业模板的管理也不属于 Hermes 的常规 OAuth 内容处理流程。如果用户需要可复用的结构化企业元数据，但现有模板无法满足需求，应告知用户需由 Box 管理员或授权的联合管理员单独创建模板，同时保持现有的结构化元数据不变，再提供已保存的 `global.properties` 实例或 JSON 附加文件。有关完整的提取与回写流程，请参阅 [搜索与 AI](references/search-and-ai.md) 文档。

在首次发送 Box AI 请求之前，需明确说明 Box AI 必须处于启用状态、会消耗 AI 单位，并且其功能仍受当前操作者的权限限制；无需等待确认回复。返回给 Hermes 的 AI 响应中仍可能包含敏感信息。仅当某个批量处理任务的文件范围或预期的 AI 单位使用量存在歧义，或者用户未明确要求调整规模时，才需要进行确认。详情请参阅 [搜索与 AI](references/search-and-ai.md)。

## 安全操作

- 在诊断文件缺失问题时，优先使用文件 ID 而非路径，并先确认当前操作者身份。
- 使用 `--json` 和 `--fields` 参数来减少输出量。对于涉及数据修改的操作，应先进行清单查询，确认范围存在歧义或规模过大后，再读取处理结果。
- 以顺序方式串行执行 CLI 操作，以便清晰掌握处理进度及出现故障时的恢复情况。如需处理大规模任务，可使用文档中规定的批量输入功能或受限的 SDK 并发机制。
- 不要仅为了提供导航功能就创建共享链接。共享链接会改变访问权限，且需要用户明确确认后才能使用。
- 切勿将机密信息放入聊天记录、命令输出、版本控制文件或日志中。

## 结果报告

对于每项单独上报的 Box 存储对象，都应包含其 ID 以及一个可点击的导航链接：

- 文件：`https://app.box.com/file/<FILE_ID>`
- 文件夹：`https://app.box.com/folder/<FOLDER_ID>`
- Hub：`https://app.box.com/hubs/<HUB_ID>`
在处理大批量数据时，应通过关联源文件夹、目标文件夹以及例外项来操作，而非逐一列出数百个条目。对于仅对已连接的 Box 账户可见的内容，人工可能无法查看，需明确说明这一点。在每条写入操作摘要中，都应注明执行操作的主体以及所进行的验证方式。

## 验证

每次完成写入操作后，均应使用相同的操作主体重新获取该文件或文件夹，或列出其父目录，进而确认返回的编号与名称是否正确。对于元数据写入操作，则需获取对应的元数据实例，并将所有返回的字段与预期值进行比对；仅凭 HTTP 成功响应并不足以视为验证通过。需记录下缺失、已规范化或被拒绝的数值。在针对一次性设置的测试中，应先创建一个测试文件夹，完成验证，且仅在用户授权清理时才将其删除。
