# 会话管理助手

通过自然语言指令帮助用户管理会话库：查找与特定主题相关的历史会话、总结相关决策结果、为会话赋予有意义的名称、将复杂任务拆分到多个并行会话中，以及建议对过时会话进行归档或删除——所有操作都可通过简单的语言指令完成，例如：“查找我关于第三季度定价的会话，保留有用的内容，并清理重复项。”

该功能灵感来源于 Perplexity Computer 在 2026 年 8 月推出的基于提示词的会话管理技术：智能体会主动整理并清理用户自己的会话库，且在执行任何操作前都会先展示相应的计划。

## 适用场景

- “关于X，我有哪些会话？” / “我们就X达成了什么共识？”
- “将这些会话重命名为更有意义的名称。”
- “清理我的会话库” / “归档那些过期的会话。”
- “将那个会话拆分出一个专注于Y的后续会话。”
- “按每个工单创建一个独立会话”（详见下文的并行工作流）。

## 两种操作界面

| 任务 | 操作界面 |
|---|---|
| 按主题查找会话、阅读内容、总结决策结果 | `session_search` 工具（基于消息存储的FTS5索引） |
| 按元数据列表/筛选（创建时间、来源、成本、令牌数、工作空间等） | 通过终端使用 `hermes sessions list` / `stats` 命令 |
| 重命名会话 | `hermes sessions rename <session_id> <新名称...>` |
| 批量暂时隐藏（可恢复） | `hermes sessions archive <筛选条件>` |
| 删除会话（不可恢复） | `hermes sessions delete` / `hermes sessions prune <筛选条件>` |
| 在删除重要内容前先导出 | `hermes sessions export --session-id <id> --format md` |
| 在新环境中继续工作 | 使用 `/branch` 命令复制当前会话，或创建全新会话并引用之前的总结内容 |

## 操作步骤

① **发现会话。** 使用包含主题关键词的 `session_search(query=..., limit=5-10)` 命令，并尝试不同的查询表述方式（如功能名称、问题现象、项目名称等）。若需按元数据筛选（例如“来自Telegram且创建时间超过60天的会话”），则可使用 `hermes sessions list --source telegram --limit 50` 命令。

② **按会话进行总结。** 通常只需提供发现结果中的`bookend_start`（目标）、匹配窗口以及`bookend_end`（解决状态）即可——只有当用户要求深入分析决策过程时，才需输出整个会话的完整信息（通过`session_search(session_id=...)`获取）。每项内容应以如下格式呈现：链接（`@session:`形式）——一行目标描述——一行结果描述。

③ **先规划再行动（对任何可能引发数据变更的操作均为强制要求）。** 首先展示计划表：哪些会话将被重命名为何名称，哪些会被归档，哪些建议删除及其原因（如与哪个会话重复、已过时或为空）。等待用户确认后再执行操作。例外情况：若用户明确要求仅进行单次重命名，则可直接执行。

④ **使用最安全的操作方式。**
- 优先选择`archive`（可逆的软隐藏）而非`delete`/`prune`。
- 执行破坏性命令时，务必先使用`--dry-run`选项运行并显示输出结果，待用户确认后再次使用`--yes`选项执行。
- 在删除任何包含有效内容的会话之前，建议提供`hermes sessions export --format md`选项以生成备份。

⑤ **汇报操作情况。** 需说明已执行的重命名操作、已归档的会话数量及撤销方法（归档的会话仍存储在数据库中，可通过`--include-archived`参数查看）、已导出的内容、被跳过的操作及其原因。

## 并行工作流

对于“每个工单一个会话、逐一调查并反馈结果”的方案：请勿尝试启动其他正在运行的会话。应使用 `delegate_task` 按工作流分配任务——每个子代理都会自动在独立的会话中运行——随后再汇总它们的报告。需说明的是，后续可通过 `session_search` 对每次任务分配的对话记录进行检索。

## 常见误区

- **切勿在未进行试运行且未获得当前对话中的明确确认前直接删除会话。** 定期“清理杂项”的权限仅限于提出建议，而非真正删除。
- **`session_search` 能检索内容，但无法查找元数据。** 会话的年龄、成本及来源筛选功能存在于 CLI 中；当查询同时涉及这些条件时（例如“关于定价的旧会话”），需将两者结合使用。
- **标题是 `/resume <title>` 命令识别会话的关键。** 重命名时，请确保标题简短、唯一，且易于添加前缀；若新标题与现有标题冲突，需及时提醒用户。
- **归档 ≠ 删除。** 归档仅会将会话从默认列表中隐藏，实际并未删除。操作时需明确说明执行的是归档操作。
- **跨配置文件会话链接**（`@session:<profile>/<id>`）从其他配置文件无法修改，管理命令仅对当前配置文件的数据库生效。

## 验证

完成清理操作后，重新运行发现查询并执行 `hermes sessions list`，以确认会话库已按计划更新（保留的会话显示新标题，归档的会话已从默认列表中移除）。
