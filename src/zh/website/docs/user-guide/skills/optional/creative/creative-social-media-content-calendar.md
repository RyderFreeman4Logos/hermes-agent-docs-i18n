# 社交媒体内容日历

在选定的社交媒体平台上制定详细的内容发布计划。该技能负责管理活动结构、帖子方案撰写、不同平台的适配处理、审核流程以及发布验证；而诸如 `xurl` 这类平台专用技能则负责处理相应的 API 命令。对于没有对应连接器的平台，验证后的内容仅会以已审核的草稿形式交由用户的日程管理工具处理——仅完成提交步骤，而不视为实际已发布。

## 适用场景

- “制定下个月的社交内容日历。”  
- “将此次产品发布转化为适用于X、领英、Instagram和TikTok的帖子。”  
- “起草并安排营销活动计划。”  
- “将这些文章/视频重新加工为适合社交平台的内容。”  

**不适用于**：单次独立的帖子创作（此类场景可直接使用对应平台的专用功能）。  

## 执行步骤

### 1. 明确营销活动的约束条件  
需确定目标、目标受众、宣传信息/产品亮点、使用的平台、时间范围、发布频率、品牌语调、允许或禁止提及的内容、相关链接、跟踪规则、本地化要求以及内容审批与发布权限。只有当每条拟发布的帖子都有明确的商业目的时，此步骤才算完成。  

### 2. 清点所有素材资源  
通过`read_file`和`web_extract`工具收集经过核实的产品信息、新品发布内容、相关文章、媒体资料、经授权的用户评价、品牌资产以及关键日期等。同时标注出各信息的负责方及有效期。只有当发现无依据的宣称或缺失的素材时，才需执行此步骤。  

### 3. 规划内容主题与日历安排  
合理搭配教育类、实证类、产品介绍类、社区互动类、活动相关类、幕后花絮类以及用户讨论类等内容形式。同时需考虑各平台的发布节奏及营销活动的里程碑节点。只有当日期、平台、主题和目标相互协调，形成有序的日历规划而非重复发布的相同内容时，此步骤才算完成。  

### 4. 撰写针对不同平台的创作指南  
针对每条帖子，需明确其吸引注意力的切入点、核心信息、内容格式、文案长度、行动号召、链接地址、素材尺寸与内容要求、无障碍文本说明、标签及提及对象，以及衡量成功与否的指标。不同平台之间应根据实际情况进行调整，而非直接复制粘贴模板。只有当创作者无需依赖额外背景信息即可完成内容创作时，此步骤才算完成。  

### 5. 起草文案并准备相关素材  
开始撰写具体文案，并准备所有所需的视觉及文字素材。

为语音内容加载 `humanizer` 工具；在需要素材时使用 `image_generate` 工具生成视觉内容。在遵循平台规范的同时，确保信息内容的真实性以及活动标识的一致性。当所有日程时段的文案草稿及素材状态均确认无误后，该步骤即告完成。

### 6. 执行编辑与风险审核

检查内容的准确性、语气风格、重复程度、版权/使用权限、无障碍访问性、声明标注、链接指向、时效相关性以及危机应对敏感性。将内容标记为 `draft`（草稿）、`needs review`（需审核）或 `approved`（已通过）；严禁直接从草稿状态发布内容。当每篇帖子都明确标注处理状态及负责人后，该步骤即告完成。

### 7. 安排发布或移交任务

展示已通过审核的内容列表。仅使用平台提供的功能（如 X 平台的 `xurl`）来发布或安排已通过的帖子；对于没有对应连接器的平台，则将已通过审核的完整内容包（包括文案、素材及发布时间）提供给用户的日程安排工具，并将这些时段标记为“已移交”，而非“已发布”。对于实际已发布的帖子，需再次确认其预定发布时间、账号、内容预览以及服务提供商的帖子/任务编号。当日历中每个时段都显示明确的已发布或已移交状态时，该步骤即告完成。

## 常见误区

- 在所有平台上使用完全相同的文案。
- 用低价值的重复性帖子填满发布节奏。
- 发布未经核实的数据、用户评价或未来承诺性内容。
- 将生成的素材准备完成误认为是内容已安排发布。
- 在那些内容仅停留在草稿阶段的平台，错误地标注为“已安排发布”。

## 核实流程

- [ ] 每条帖子均与特定的营销目标及经过核实的声明清单相对应。  
- [ ] 没有从“草稿”或“需审核”状态发布任何帖子。  
- [ ] 已发布的帖子拥有经服务提供商确认的唯一标识，而转交处理的帖子也会被明确标注出来。  
- [ ] 在发布之前，系统会逐一检查相关的权限、授权信息以及披露要求。
