## 关键操作说明 —— 请优先阅读

需使用Python和openpyxl库。请编写公式字符串（如`ws["D20"] = "=B5*B6"`），然后在交付结果之前运行`excel-author`技能中的`recalc.py`辅助工具。

### 核心原则
* **所有计算都必须基于 Excel 公式**——严禁使用 Python 进行数值计算后再将结果硬编码到单元格中。在使用 openpyxl 时，应写入 `cell.value = "=B5*B6"`（公式字符串），而非 `cell.value = 1250`（计算结果）。模型必须具备动态性，能够在输入数据发生变化时自动更新。
* **遵循模板结构**——请按照 `examples/LBO_Model.xlsx` 中的架构或用户提供的模板来组织内容，切勿自行设计布局。
* **使用正确的单元格引用**——所有公式都应引用相应的单元格，绝不能直接输入本应来自其他单元格的数值。
* **保持符号规则的一致性**——需遵循模板所规定的符号规则（有的用负号表示资金流出，有的则用正号），整个模型中必须始终保持一致。
* **分步骤处理，并在每一步与用户确认**——先完整完成一个部分，向用户展示已构建的内容，运行该部分的验证检查并得到确认后，再进入下一部分。切勿一次性构建完整模型后再呈现给用户——后续部分依赖于前面的内容，如果在收益计算完成后才发现“来源与用途”部分存在错误，将不得不重新处理整个模型。

### 公式颜色规范
* **蓝色（0000FF）**：硬编码输入值——即直接输入的数字，不引用其他单元格。  
* **黑色（000000）**：包含计算公式的单元格——任何使用运算符或函数的公式（如 `=B4*B5`、`=SUM()`、`=-MAX(0,B4)`）。  
* **紫色（800080）**：指向**同一工作表**中单元格的链接——直接引用且无需计算（如 `=B9`、`=B45`）。  
* **绿色（008000）**：指向**不同工作表**中单元格的链接——跨工作表引用（如 `=Assumptions!B5`、`='Operating Model'!C10`）。

### 填充颜色方案——专业蓝灰色调（除非用户或模板另有指定，否则默认使用此方案）
* **保持简洁**——仅使用蓝色和灰色作为单元格填充色。严禁使用绿色、黄色、红色或其他复杂配色。专业的杠杆收购模型讲究克制。  
* **默认填充颜色方案：**
  * **章节标题**（“资金来源与用途”“运营模式”等）：深蓝色 `#1F4E79`，搭配白色加粗文字。  
  * **列标题**（“第1年”“第2年”等）：浅蓝色 `#D9E1F2`，搭配黑色加粗文字。  
  * **输入单元格**：浅灰色 `#F2F2F2`（或纯白色）——蓝色*字体*用于标识，填充色仅为辅助。  
  * **公式/计算结果单元格**：纯白色，无填充色。  
  * **关键输出结果**（内部收益率、投资回报率、退出时股权价值）：中蓝色 `#BDD7EE`，搭配黑色加粗文字。  
* **这就是全部的配色方案**：3种蓝色 + 1种灰色 + 白色。如果模板已设定专属颜色，则请遵循模板要求。  
* 注意：上述用于区分输入值、公式及链接的蓝色/黑色/紫色/绿色*字体*颜色，与此处所述的*填充*颜色方案是相互独立的——二者共同构成完整的视觉标识系统。
### 数字格式标准
* **货币金额**：根据模板不同，格式为 `$#,##0;($#,##0);"-"` 或 `$#,##0.0`
* **百分比**：`0.0%`（保留一位小数）
* **倍数**：`0.0"x"`（保留一位小数）
* **MOIC/详细比率**：为保证精度，格式为 `0.00"x"`（保留两位小数）
* **所有数字单元格**：右对齐显示

## 常见问题领域

以下几种计算模式在杠杆收购模型中常常引发问题。遇到时请格外注意：

### 各部分数值平衡
* 当两个数值必须相等时（例如“资金来源”等于“资金用途”），其中一个项目通常用作“填补值”（用于平衡数值）
* 需先确定哪个项目是填补值，再通过差值计算出该数值

### 税务计算
* 税务公式应仅引用相关的收入项和税率
* 不得引用无关的部分（例如债务偿还计划）
* 需考虑亏损是否可形成税收抵免，还是直接被忽略

### 利息计算与循环引用
* 若利息计算涉及受现金流影响的余额，可能会导致循环问题
* 应使用**期初余额**（而非平均余额或期末余额）来打破循环引用
* 正确的计算逻辑为：利息 → 现金流 → 债务偿还 → 期末余额（若利息计算使用期末余额，则会形成循环）

### 债务偿还/现金分配
* 当存在多笔债务时，通常会有优先级顺序
* 现金分配需遵循这一优先级顺序
* 余额不得为负值——需适当使用 MAX 或 MIN 函数进行限制

### 收益率计算（内部收益率/IRR、年化投资回报率/MOIC）
* 现金流的正负号必须正确：投资额为负值，所得款项为正值。
* 若使用 XIRR 函数，则需要对应的日期数据。
* 若使用 IRR 函数，现金流数据应分布在连续的期间内。
* MOIC 的计算公式为：总所得款项 ÷ 总投资额。

### 敏感性分析表
* **请使用奇数尺寸**（如 5×5 或 7×7），切勿使用 4×4 或 6×6。奇数尺寸能确保存在真正的中心单元格。
* **中心单元格代表基准情况**。需围绕模型实际的假设值对称地设置行和列的数值范围（例如，若基准倍数为 10.0x，则数值范围应为 `[8.0x, 9.0x, 10.0x, 11.0x, 12.0x]`）。此时，中心单元格的 IRR/MOIC 值必须与模型实际输出的 IRR/MOIC 值一致——这便是该表格结构正确的证明。
* **需突出显示中心单元格**：采用浅蓝色填充色（`#BDD7EE`）并使用加粗字体，以便直观标识基准情况。
* Excel 的 DATA TABLE 函数可能不兼容 openpyxl 文件——此时应手动编写引用行/列标题的公式。
* 每个单元格显示的值必须各不相同——如果所有单元格的值都一样，说明公式没有正确变化。
* 建议使用混合引用格式（例如，行数据引用用 `$A5`，列数据引用用 `B $4`）。

## 需避免的常见错误

| 错误类型 | 问题表现 | 解决方法 |
|---------|----------|----------|
| 硬编码计算值 | 输入数据变更时模型无法更新 | 始终使用引用源单元格的公式 |
| 复制后单元格引用错误 | 公式指向了错误的单元格 | 检查所有链接，使用合适的美元符号锚定方式 |
| 循环引用错误 | 模型无法进行计算 | 对利息类计算使用期初余额，或打破循环引用 |
| 各部分金额不平衡 | 应该相等的总计数值不一致 | 确保其中一项为差值项（通过公式计算得出） |
| 出现不可能的负余额 | 支出/使用金额超过可用额度 | 适当使用MAX(0, ...)或MIN函数 |
| 内含报酬率/收益计算错误 | 符号错误或数据范围不完整 | 检查现金流的符号，并确保公式覆盖所有期间 |
| 敏感性分析表显示相同数值 | 公式未随输入参数变化 | 检查单元格引用——需使用混合引用方式（如 $A5, B$\4） |
| 迭代计算结果不一致 | 期初数值与上期期末数值不相等 | 核实各期间之间的链接关系 |
| 符号规则不一致 | 加法变为减法或反之 | 全程始终遵循模板规定的符号规则 |

**该技能通过填充正确的公式、规范的格式以及经过验证的计算结果，能够生成符合投资银行标准的企业杠杆收购模型。无论模板结构如何，它都能确保财务数据的准确性以及专业化的呈现效果。**

## 数据来源 —— 首选 MCP，备用网络搜索

下文多处提到“使用 S&P Kensho MCP / Daloopa MCP / FactSet MCP”。这些均源自原有 Cowork 插件环境中的商业金融数据 MCP 工具。在 Hermes 中：

- **如果您已配置了任何结构化的金融数据 MCP**（Hermes 支持 MCP —— 参见 `native-mcp` 技能），则优先使用它们来获取特定时间点的对比数据、历史交易案例及监管文件信息。
- **否则**，可采取以下替代方案：
  - 对于美国市场的监管文件，可通过 SEC EDGAR 网站（`https://www.sec.gov/cgi-bin/browse-edgar`）使用 `web_search` / `web_extract` 功能进行检索；
  - 从公司的投资者关系页面获取新闻稿和业绩演示文稿；
  - 使用 `browser_navigate` 访问交互式数据门户；
  - 使用用户提供的数据（当上下文中缺乏相关数据时，应明确向用户询问）。
- **绝不可编造数据**。如果无法找到倍数、历史案例或文件编号，应将对应单元格标记为 `[UNSOURCED]`，并将其展示给用户。
