## 通用评估维度

所有主流机器学习会议都会从四个核心维度对论文进行评估：

### 1. 质量（技术严谨性）

**审稿人会关注的问题：**
- 论文中的结论是否有充分的理论分析或实验结果支撑？
- 证明是否正确？实验设计是否合理？
- 基准方法是否恰当，对比是否公平？
- 研究方法本身是否可靠？

**如何确保高质量：**
- 提供完整的证明（可在正文中或附录中给出简要说明）
- 选择合适的基准方法（避免使用虚假对比对象）
- 在方法部分同时报告方差/误差范围
- 详细记录超参数的选取过程

### 2. 清晰度（写作与结构）

**审稿人会关注的问题：**
- 论文的结构是否清晰、条理是否分明？  
- 该领域的专家能否复现研究结果？  
- 符号的使用是否一致？术语是否得到明确定义？  
- 论文是否具备独立性？  

**如何确保清晰性：**  
- 全文使用统一的术语  
- 在首次出现时即对所有符号进行定义  
- 提供复现相关细节（附录形式亦可）  
- 提交前请非作者人员审阅  

### 3. 重要性（影响与价值）  

**审稿人会关注的问题：**  
- 研究结果对该领域有何重要影响？  
- 是否会有其他人在此基础上进一步研究？  
- 是否解决了某个关键问题？  
- 其在现实世界中可能产生怎样的影响？  

**如何体现重要性：**  
- 清晰阐述该问题的重要性  
- 将其与更广泛的研究主题联系起来  
- 讨论潜在的应用场景  
- 有针对性地与现有方法进行比较  

### 4. 独创性（新颖性与贡献）  

**审稿人会关注的问题：**  
- 是否提供了新的见解？  
- 与以往的研究有何不同？  
- 其贡献是否具有实质性价值？  

**NeurIPS评审指南中的重要观点：**  
> “独创性并不一定意味着必须引入全新的方法。那些通过评估现有方法而带来新见解，或阐明某些方法成功原因的论文，同样可以具备极高的独创性。”

## NeurIPS审稿人指南  

### 评分系统（1-6分制）

| 分数 | 标签 | 描述 |
|-------|------|-------------|
| **6** | 强烈接受 | 革新性强且无瑕疵，属于提交作品中排名前2-3%的水平 |
| **5** | 接受 | 技术实现扎实，影响力高，能惠及整个社区 |
| **4** | 几近接受 | 工作表现良好，但评估依据有限，倾向于接受 |
| **3** | 几近拒绝 | 虽然基础不错，但缺点多于优点，倾向于拒绝 |
| **2** | 拒绝 | 存在技术缺陷或评估不足 |
| **1** | 强烈拒绝 | 结果已被广泛知晓，或存在未解决的伦理问题 |

### 评审指南

评审人员需严格遵守以下要求：

1. **按当前提交状态进行评估**——而非基于修改后的版本
2. **提供有建设性的反馈**——给出3-5条可操作的改进建议
3. **不应因作者诚实地承认局限性而扣分**——鼓励其正视不足
4. **评估可复现性**——该成果是否能够被验证？
5. **考虑伦理影响**——是否存在潜在的滥用或危害风险

### 评审人员应避免的行为

- 进行肤浅且缺乏依据的评审
- 要求进行不合理的额外实验
- 因作者诚实地承认局限性而对其评分降低
- 以未引用评审人员自己的研究成果为由予以拒绝

### 时间安排（NeurIPS 2025——具体日期请以当年官网为准）

- 提交截止日：5月17日至21日
- 评审期：5月29日至7月2日
- 作者答辩期：7月24日至30日
| 讨论期：7月31日至8月13日
- 最终通知日：9月18日

> **注意**：以上日期为2025年度的安排。请务必查看当年会议官网上的征稿信息。

## ICML 评审指南

### 评审结构

ICML 评审人需提供以下内容：

1. **摘要**——对论文贡献的简短描述
2. **优势**——论文的积极方面
3. **不足**——需要改进的地方
4. **疑问**——需要向作者澄清的问题
5. **局限性**——对文中所述局限性的评估
6. **伦理问题**——任何值得关注的伦理方面
7. **综合评分**——最终推荐意见

### 评分标准

ICML 采用类似但经过校准的 1-6 分制：
- 被接收论文中的前 25%：得分 5-6
- 普通被接收论文：得分 4-5
- 边界情况论文：得分 3-4
- 明确拒收论文：得分 1-2

### 关键评估要点

1. **可复现性**——是否提供了足够的细节？
2. **实验严谨性**——是否使用了多种随机种子及合适的基准方法？
3. **写作质量**——表述是否清晰、结构是否合理？
4. **创新性**——是否具有实质性的贡献？

## ICLR 评审指南

### 开放式评审流程

ICLR 采用开放式评审机制，具体包括：
- 在论文被接收后公开评审意见
- 评审人可查看作者的回复
- 评审人与程序委员会成员之间进行讨论

### 评分体系

ICRL 评审包含以下维度：
- **合理性**：1-4 分制
- **表述方式**：1-4 分制
- **贡献价值**：1-4 分制
- **综合评分**：1-10 分制
- **信心程度**：1-5 分制

### ICLR 特有的评估要点

1. **大语言模型披露**——评审人需评估论文是否正确披露了所使用的大语言模型
2. **可复现性**——特别重视代码的公开程度
3. **互评机制**——作者必须同时担任其他论文的评审人

## ACL 评审指南

### ACL 特有的评估标准

ACL 还增加了针对自然语言处理领域的特定评估维度：

### 语言准确性  
——相关语言表述是否准确无误？  

### 资源文档说明  
——数据集与模型是否配有完善的文档说明？  

### 多语言考量  
——如适用，是否充分考虑了语言多样性问题？

## ACL评审指南  

### 评估标准  
ACL的评审标准与NeurIPS/ICML类似，但也存在一些差异：  

| 评估维度 | 权重 | 备注 |
|----------|------|------|
| **技术质量** | 高 | 方法的合理性及结果的正确性 |
| **重要性** | 高 | 问题本身的意义以及研究贡献的价值 |
| **创新性** | 中高 | 是否提出了新的思想、方法或见解 |
| **清晰度** | 中 | 文章表述是否清晰，结构是否合理 |
| **可复现性** | 中 | 是否提供足够细节以便他人复现实验结果 |

### ACL特有的考量因素

- **更广泛的人工智能覆盖范围**：AAAI涵盖所有类型的人工智能技术，而不仅限于机器学习。涉及规划、推理、知识表示、自然语言处理、计算机视觉、机器人技术以及多智能体系统等方面的论文均属于其收录范围。审稿人未必都是机器学习领域的资深专家。
- **严格的格式要求**：AAAI的审稿人被要求指出格式违规问题。不符合要求的论文可能在正式审阅之前就被直接拒收。
- **应用类论文**：与NeurIPS/ICML相比，AAAI更倾向于接受以应用为导向的研究成果。突出展示出色的应用价值是可行的策略。
- **高级程序委员会**：AAAI设有SPC（高级程序委员会成员），他们负责在审稿人之间进行协调，并提出接受或拒收的建议。

### 评分标准（AAAI评分体系）

- **强烈接受**：远超阈值，具有卓越的贡献价值
- **接受**：超过阈值，虽存在轻微问题但整体贡献良好
- **勉强接受**：处于临界状态，优势略大于不足
- **勉强拒收**：处于临界状态，不足之处多于优势
- **拒收**：未达到阈值，存在严重问题
- **坚决拒收**：远低于阈值，质量极差

## COLM审稿指南

### 评估标准

除常规标准外，COLM的审稿工作还侧重于论文与语言建模领域的关联性。

| 评价标准 | 权重 | 备注 |
|-----------|------|-------|
| **相关性** | 高 | 必须与语言模型领域相关 |
| **技术质量** | 高 | 方法论合理，论点有充分依据 |
| **创新性** | 中高 | 对语言模型有新的见解 |
| **清晰度** | 中 | 表述清晰，结果可复现 |
| **重要性** | 中高 | 对语言模型研究与实践具有影响力 |

### COLM特有的评审考量

- **语言模型聚焦**：评审专家将评估该成果是否有助于加深对语言模型的理解。针对通用机器学习领域的贡献，需要明确其与语言模型的关联。
- **较新的会议规范**：COLM相比NeurIPS/ICML成立时间较短，因此评审标准的统一性较差。建议在投稿时更加谨慎，充分考虑评审专家背景的多样性。
- **借鉴ICLR的评审流程**：其评审流程参照ICLR设计，包括公开评审、作者回复期以及评审专家间的讨论。
- **对“语言模型”的宽泛定义**：涵盖语言模型的训练、评估、对齐、安全性、效率、应用场景、理论研究、多模态能力（以语言为核心时）以及其社会影响等方面。

### 评分标准

COLM采用类似ICLR的评分体系：
- **8-10分**：强烈录用（顶级论文）
- **6-7分**：勉强录用（具有实质性贡献）
- **5分**：处于临界水平
- **3-4分**：勉强拒收（未达到标准）
- **1-2分**：强烈拒收

## 如何提升评审质量

### 遵循丹尼尔·丹尼特的准则

优秀的评审专家会遵循以下原则：

1. **公正地重新阐述观点**——表明你已理解相关论文内容  
2. **列出共识点**——肯定现有方案的优点  
3. **说明自己的收获**——认可他人的贡献  
4. **最后再提出批评**——在充分理解的基础上进行反馈  

### 评审结构最佳实践  

**优秀的评审结构应包含：**
```
Summary (1 paragraph):
- What the paper does
- Main contribution claimed

Strengths (3-5 bullets):
- Specific positive aspects
- Why these matter

Weaknesses (3-5 bullets):
- Specific concerns
- Why these matter
- Suggestions for addressing

Questions (2-4 items):
- Clarifications needed
- Things that would change assessment

Minor Issues (optional):
- Typos, unclear sentences
- Formatting issues

Overall Assessment:
- Clear recommendation with reasoning
```

## 审稿人常见顾虑

### 技术层面顾虑

| 顾虑点 | 如何提前应对 |
|---------|-----------------|
| “基线模型过于弱” | 使用最先进的基线模型，并引用近期研究成果 |
| “缺乏消融实验” | 增加系统的消融研究内容 |
| “未给出误差范围” | 报告标准差或误差值，并说明重复实验次数 |
| “超参数未经过调优” | 记录调优过程及搜索范围 |
| “论点缺乏依据” | 确保每个论点都有相应证据支撑 |

### 创新性层面顾虑

| 顾虑点 | 如何提前应对 |
|---------|-----------------|
| “贡献仅为增量改进” | 清晰阐述与现有工作的差异及创新之处 |
| “与[论文X]类似” | 在“相关研究”部分明确与X的对比 |
| “只是简单的扩展” | 突出其中的非显而易见之处 |

### 可读性层面顾虑

| 顾虑点 | 如何提前应对 |
|---------|-----------------|
| “内容难以理解” | 采用清晰的结构和引导性说明 |
| “符号使用不统一” | 检查所有符号的使用情况，并制作符号表 |
| “缺少详细信息” | 添加可复现性附录 |
| “图表不够清晰” | 为图表添加独立标题，并确保尺寸合适 |

### 实际意义层面顾虑

| 顾虑点 | 如何提前应对 |
|---------|-----------------|
| “影响范围有限” | 讨论更广泛的实际应用价值 |
| “评估数据集过于单一” | 在多个基准数据集上进行测试 |
| “仅在受限环境下有效” | 明确说明研究范围，并解释其依然具备价值的原因 |

## 如何回应审稿人意见

### 反驳的最佳实践

**应做到：**
- 感谢审稿人抽出时间  
- 逐一具体回应每一项疑问  
- 提供证据（如可能，可附上新的实验结果）  
- 表达简洁——审稿人时间宝贵  
- 正视合理的批评意见  

**切勿：**  
- 采取防御态度或忽视问题  
- 承诺无法兑现的事项  
- 忽略尖锐的批评  
- 撰写过长的反驳内容  
- 对主观性评价进行争论  

### 反驳模板

```markdown
We thank the reviewers for their thoughtful feedback.

## Reviewer 1

**R1-Q1: [Quoted concern]**
[Direct response with evidence]

**R1-Q2: [Quoted concern]**
[Direct response with evidence]

## Reviewer 2

...

## Summary of Changes
If accepted, we will:
1. [Specific change]
2. [Specific change]
3. [Specific change]
```

### 何时接受批评意见

有些审稿人的反馈应当直接予以采纳：
- 真实存在的技术错误
- 未提及重要的相关研究
- 解释不够清晰
- 缺少实验细节说明

应以礼貌的态度予以承认：“审稿人的观点确实有道理……我们将对此进行修改……”

### 何时予以反驳

在以下情况下，您可以礼貌地表达不同意见：
- 审稿人误解了论文内容
- 要求进行的实验超出了研究范围
- 批评意见与事实不符

应以建设性的方式表达分歧：“我们感谢您提出的观点。不过，[具体解释]……”

## 提交前审稿人模拟检查

在提交之前，请自问以下问题：

**质量方面：**
- [ ] 如果我看到这些结果，是否会信任它们？
- [ ] 所有的论断都有证据支持吗？
- [ ] 对比基准是否公平且是最新的？

**清晰度方面：**
- [ ] 非该领域专家能否根据论文复现研究结果？
- [ ] 文章表达对非专业读者来说是否清晰易懂？
- [ ] 所有术语和符号都已明确定义了吗？

**重要性方面：**
- [ ] 为什么学术界应该关注这项工作？
- [ ] 人们能够如何应用这项研究成果？
- [ ] 这个问题本身重要吗？

**创新性方面：**
- [ ] 这项研究具体有哪些新之处？
- [ ] 它与最相近的相关研究有何不同？
- [ ] 其贡献具有实际价值吗？
