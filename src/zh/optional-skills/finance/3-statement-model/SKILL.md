# 三表财务模型模板填充指南

需完善并填充集成式财务模型模板，确保损益表、资产负债表与现金流量表之间具备正确的关联关系。

## ⚠️ 重要原则——填充任何模板前请务必阅读

**必须使用公式而非硬编码值（绝对不可违反）：**
- 所有的预测单元格、滚动计算项、关联链接以及小计都必须为 Excel 公式，绝不能是预先计算好的数值
- 使用 Python/openpyxl 时，应编写公式字符串（如 `ws["D15"] = "=D14*(1+Assumptions!$1. 确定用于输入的具体单元格（通常会高亮显示或带有标签）。
2. 先输入历史数据，随后验证相关公式在这些时期的计算结果是否正确。
3. 输入用于驱动预测计算的假设参数。
4. 查看计算结果，确认公式按预期正常运行。
5. 如果必须修改某个公式单元格，请在更改前先记录下原有公式。

**处理预置公式**
- 若公式引用了尚未填入数据的单元格，在所有输入完成之前可能会出现临时错误（如 #REF!、#DIV/0! 错误）。
- 当公式产生异常结果时，通过追溯依赖关系来找出缺失或错误的输入项。
- 在删除行或列之前，务必检查所有工作表中的公式依赖关系。

### 第3步：验证公式

**公式完整性检查**

在依赖模板输出之前，需先验证公式是否正常运行：

| 检查类型 | 方法 |
|----------|------|
| 追溯依赖项 | 选中公式单元格 → 点击“公式”选项 → 选择“追踪依赖项”，以确认其引用的输入项是否正确 |
| 追溯被引用项 | 验证关键输入项是否正确传递至预期的输出单元格 |
| 评估公式 | 使用“公式”选项 → “评估公式”，逐步查看复杂计算过程 |
| 检查硬编码值 | 预测公式应引用假设参数，而非包含硬编码的固定数值 |
| 使用已知值测试 | 输入简单的测试值，确认公式能产生预期结果 |
| 跨工作表一致性检查 | 确保相同的公式逻辑适用于所有预测时期 |

**需注意的常见公式问题**
- 混合使用绝对引用与相对引用，导致在跨时期复制时出现错误结果
- 对外部文件或已删除区域的链接失效（出现 #REF! 错误）
- 在收入尚未增长的前期出现除以零的情况（出现 #DIV/0! 错误）
- 循环引用警告（在计算利息时可能是有意为之）
- 不同预测列中的公式不一致（可使用 Ctrl+\ 查找差异）

**验证跨工作表链接**
- 确保出现在多个工作表中的数值是相互关联的（而非重复录入）
- 验证汇总表的总额是否与主报表中对应的明细项一致
- 检查所有工作表中的时期标签是否对齐

### 第4步：按工作表进行质量检查

在填入模板数据后，需对每个工作表执行以下验证：

**利润表（IS）质量检查**
- 历史时期的收入数值与原始数据一致
- 所有费用项目的总和等于报表中显示的总额
- 小计项（毛利润、息税前利润、息税前亏损、净利润）的计算结果正确
- 税务计算逻辑合理（能正确处理亏损情况）
- 预测参数引用的是“假设参数”工作表中的内容（无硬编码值）
- 不同时期的变化趋势符合逻辑

**资产负债表（BS）质量检查**
- 每个时期的资产总额等于负债总额加上所有者权益总额（核心检查项）
- 现金余额与现金流量表中期末现金余额一致
- 流动资产账户与相应的辅助明细表数据相符（如适用）
- 留存收益的结转正确：期初留存收益 + 净利润 - 股息 ± 调整项 = 期末留存收益
- 债务余额与债务明细表数据一致（如适用）
- 所有资产负债表项目的符号正确（资产为正，大多数负债也为正）

**现金流量表（CF）质量检查**
- 现金流量表顶部的净利润与利润表中的净利润一致
- 非现金加回项（如折旧摊销、无形资产摊销等）与其对应的来源明细表或报表数据一致
- 流动资产的变化符号正确（资产增加意味着现金流出，故为负值）
- 资本支出与固定资产明细表或固定资产结转数据一致
-融资活动与资产负债表中债务和所有者权益账户的变化相对应
- 期末现金余额与资产负债表中的现金余额一致
- 期初现金余额等于上一期的期末现金余额

**辅助明细表质量检查**
- 期初余额等于上一期的期末余额
- 结转逻辑完整（期初余额 + 增加额 - 减少额 = 期末余额）
- 明细表的总额与主报表中的明细项一致
- 计算中使用的假设参数与“假设参数”工作表中的内容一致

### 第5步：跨报表一致性检查

在验证完各个单独的工作表后，需确认这三份报表之间能够正确整合：

| 检查项 | 公式 | 预期结果 |
|--------|------|----------|
| 资产负债表平衡 | 资产 - 负债 - 所有者权益 | = 0 |
| 现金流匹配 | 现金流量表期末现金余额 - 资产负债表现金余额 | = 0 |
| 净利润关联 | 利润表净利润 - 现金流量表期初净利润 | = 0 |
| 留存收益计算 | 期初留存收益 + 净利润 - 股息 - 资产负债表期末留存收益 | = 0（可根据实际情况调整无形资产摊销等项目） |

### 第6步：最终审查

在认为模型已经完成之前，需执行以下操作：
- 若存在多种情景分析，请逐一查看，确认每种情景下的检查均通过
- 检查所有 #REF!、#DIV/0!、#VALUE! 和 #NAME? 错误，并予以修正或记录下来
- 确认所有输入单元格都已填入数据（可查找占位符数值）
- 验证所有工作表中的单位是否一致
- 在进行任何进一步修改之前，先保存一份干净的版本

## 模型验证与审计

本部分汇总了已完成模板的所有验证检查及审计流程。

### 核心关联关系（必须始终成立）

有关所有公式的详细信息，请参阅 [references/formulas.md](references/formulas.md) 文件。

| 检查项 | 公式 | 预期结果 |
|--------|------|----------|
| 资产负债表平衡 | 资产 - 负债 - 所有者权益 | = 0 |
| 现金流匹配 | 现金流量表期末现金余额 - 资产负债表现金余额 | = 0 |
| 月度与年度现金余额对比 | 月度期末现金余额 - 年度期末现金余额 | = 0 |
| 净利润关联 | 利润表净利润 - 现金流量表期初净利润 | = 0 |
| 留存收益计算 | 期初留存收益 + 净利润 + 无形资产摊销 - 股息 - 资产负债表期末留存收益 | = 0 |
| 所有者权益融资变动 | 资产负债表中普通股/权益资本的增加额 - 现金流量表中股权发行带来的资金流入 | = 0 |
| 第0年的所有者权益金额 | 第0年的融资所得金额 - 第1年的期初所有者权益金额 | = 0 |

### 符号约定参考

| 报表类型 | 项目 | 符号约定 |
|----------|------|----------|
| 现金流量表 | 折旧摊销、无形资产摊销 | 正值（加回项） |
| 现金流量表 | 应收账款增加额 | 负值（现金流出） |
| 现金流量表 | 应付账款增加额 | 正值（现金来源） |
| 投资活动现金流量表 | 资本支出 | 负值 |

| 现金流量表 | 债务偿还 | 负值 |
| 现金流量表 | 股息支付 | 负值 |

### 循环引用问题的处理

利息支出会导致循环关系：利息 → 净利润 → 现金 → 债务余额 → 利息

在 Excel 中需启用迭代计算功能：文件 → 选项 → 公式 → 启用迭代计算。将最大迭代次数设置为100，最大变化量设置为0.001。可在“假设参数”工作表中添加一个中断机制开关。

### 检查类别

**第1类：货币一致性**
- 在“假设参数”中明确指定并记录所使用的货币类型
- 所有工作表均使用相同的货币符号及小数位数格式
- 单位行中的数值与模型所使用的货币单位一致

**第2类：资产负债表完整性**
- 每个时期的资产总额等于负债总额加上所有者权益总额
- 公式：资产 - 负债 - 所有者权益，其结果必须为0

**第3类：现金流量表完整性**
- 现金流量与资产负债表中的现金余额相互匹配（现金流量表期末现金余额 = 资产负债表现金余额）
- 月度与年度现金余额一致：月度期末现金余额 = 年度期末现金余额
- 净利润与利润表数据一致（现金流量表净利润 = 利润表净利润）
- 折旧摊销与相关明细表数据一致
- 无形资产摊销与利润表数据一致
- 应收账款、存货、应付账款的变化与流动资产明细表数据一致
- 资本支出与固定资产明细表数据一致

**第4类：留存收益**
- 进行留存收益结转验证：期初留存收益 + 净利润 + 无形资产摊销 - 股息 = 期末留存收益
- 可显示各组成部分的明细，便于调试

**第5类：流动资产管理**
- 应收账款、存货、应付账款与资产负债表数据一致
- 对应收账款周转天数、存货周转天数、应付账款周转天数的合理性进行检查（若超出正常范围则标记异常）

**第6类：债务明细表**
- 总债务额与资产负债表中的总债务（流动负债 + 长期负债）一致
- 利息计算结果与利润表数据一致

**第6b类：所有者权益融资**
- 股权发行所得资金与资产负债表中普通股/权益资本的增加额一致
- 来自股权融资的现金增加额应等于所有者权益账户的增加额（两者必须平衡）
- 股权融资相关平衡验证：资产负债表中普通股/权益资本的增加额 = 现金流量表中股权发行带来的资金流入，其结果必须为0
- 第0年的所有者权益平衡验证：第0年的融资所得金额 = 第1年的期初所有者权益金额

**第6c类：纳税亏损递延明细表**
- 第1年/业务成立初期的纳税亏损余额为0（新成立的企业初始没有纳税亏损）
- 仅当息税前亏损为负数时，才允许产生纳税亏损（亏损必须实际发生才能形成纳税亏损）
- 税盾与资产负债表中的递延所得税资产数据一致
- 纳税亏损的利用比例不得超过息税前亏损的80%（2017年后的联邦税法限制）
- 纳税亏损余额不能为负数（不能利用超过实际存在的亏损额）
- 仅当息税前亏损为负数时，才会产生纳税亏损
- 当应纳税所得额≤0时，税费支出为0

**第7类：情景层级结构**
- 绝对指标：乐观情景 > 基准情景 > 悲观情景（净利润、息税折旧摊销前利润、自由现金流等）
- 利润率指标：乐观情景 > 基准情景 > 悲观情景（毛利率、息税折旧摊销前利润率、净利润率等）
- 信用指标：杠杆率的乐观情景 < 基准情景 < 悲观情景（顺序相反）

**第8类：公式完整性**
- 销售成本、销售与营销费用、一般与管理费用、研发费用、无形资产摊销均按收入的一定比例计算（无硬编码值）
- 不同预测年份之间的公式保持一致
- 不存在 #REF!、#DIV/0!、#VALUE! 等错误

**第9类：信用指标阈值**
- 根据契约规定的阈值，将各项指标标记为绿色/黄色/红色
- 提供所有红色预警项的汇总信息

### 综合检查公式

将所有类别的检查结果汇总为一个综合判断：
- 若所有类别均通过检查 → 显示“✓ 所有检查均通过”
- 若有任何类别未通过检查 → 显示“✗ 检测到错误——请查看下方内容”

### 快速调试流程

当综合状态显示存在错误时：
1. 向下滚动查找被标记为红色的类别
2. 确定是哪一类检查出现了问题
3. 转到对应的工作表进行详细排查
4. 解决根本问题
5. 返回“检查”页面，确认问题已解决

## 数据来源——优先使用MCP，无法使用时再使用网络搜索

下文多处提到“使用S&P Kensho MCP / Daloopa MCP / FactSet MCP”。这些均为源自原有Cowork插件环境的商业金融数据MCP服务。在Hermes系统中：

- **如果已配置任何结构化的金融数据MCP**（Hermes支持MCP功能，参见`native-mcp`技能），建议优先使用它们来获取特定时点的对比数据、历史交易记录及上市公司公告信息。
- **否则**，可采取以下替代方案：
  - 对于美国公司的上市文件，可使用`web_search`/`web_extract`功能搜索SEC EDGAR网站（https://www.sec.gov/cgi-bin/browse-edgar）上的相关资料
  - 查阅公司官网的投资者关系页面，获取新闻稿和业绩演示文稿
  - 使用`browser_navigate`功能访问交互式数据平台
  - 接收用户提供的数据（在上下文信息不足时需主动向用户询问）
- **绝不允许编造数据**。如果无法找到相应的倍数、历史交易记录或文件编号，应将该单元格标记为 `[UNSOURCED]`，并将此情况告知用户。
