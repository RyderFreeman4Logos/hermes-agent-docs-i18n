# 三表财务模型模板填充指南

完善并填充集成化的财务模型模板，确保利润表、资产负债表与现金流量表之间建立正确的关联关系。

## ⚠️ 重要原则——在填充任何模板前请务必阅读

**必须使用公式而非硬编码值（不可妥协）：**
- 所有的预测单元格、滚动计算项、关联引用以及小计均必须是 Excel 公式，绝不能是预先计算好的数值
- 使用 Python/openpyxl 时，应编写公式字符串（如 `ws["D15"] = "=D14*(1+Assumptions! $B $5)"`），而非计算结果（如 `ws["D15"] = 12500`）
- 唯一允许包含硬编码数值的单元格为：(1) 历史实际数据，(2) “假设条件”选项卡中的驱动参数
- 如果您发现自己用 Python 计算出数值后再将其写入单元格，请立即停止，改为直接输入公式
- 原因在于：当场景切换或假设条件发生变化时，模型必须具备灵活性。硬编码值会悄无声息地破坏所有后续的完整性检查。

**需与用户逐步骤进行验证：**
1. **模板映射完成后** → 向用户展示已识别的各标签页/板块，并在修改任何单元格内容前进行确认。  
2. **历史数据填充完成后** → 向用户呈现历史数据区块，确认数值与时间周期与源数据一致。  
3. **编制损益表预测后** → 执行小计校验，向用户展示预测的损益表结果，在进入资产负债表环节前再次确认。  
4. **编制资产负债表后** → 向用户展示各时期的平衡校验（资产 = 负债 + 所有者权益），在进入现金流量表环节前进行确认。  
5. **编制现金流量表后** → 向用户展示现金平衡校验（现金流量表期末现金 = 资产负债表现金余额），在最终定稿前再次确认。  
6. **切勿一次性填满整个模型并直接呈现完整结果** —— 应在每一步报表完成后暂停，展示计算过程，以便尽早发现错误。

## 格式规范 —— 专业蓝灰配色方案（除非模板或用户另有指定，否则默认此方案）

**尽量减少颜色使用。** 单元格填充仅限蓝色和灰色，不得使用绿色、黄色、橙色或其他多种强调色——简洁的模型离不开适度的克制。

| 元素 | 填充颜色 | 字体 |
|---|---|---|
| 板块标题（损益表 / 资产负债表 / 现金流量表） | 深蓝色 `#1F4E79` | 白色加粗 |
| 列标题（FY2024A、FY2025E等） | 浅蓝色 `#D9E1F2` | 黑色加粗 |
| 输入单元格（历史数据、假设参数） | 浅灰色 `#F2F2F2` 或白色 | 蓝色 `#0000FF` |
| 公式单元格 | 白色 | 黑色 |
| 交叉表链接 | 白色 | 绿色 `#008000` |
| 校验行/关键总计 | 中等蓝色 `#BDD7EE` | 黑色加粗 |
**即3种蓝色 + 1种灰色 + 白色。** 如果模板有自定义的颜色方案，则应遵循该模板的规定。

字体颜色用于标识单元格的类型（输入值/公式/链接）。填充颜色则用于指示当前所在位置（表头/数据/校验项）。

## 模型结构

### 识别模板的标签页布局

不同模板的标签页命名规则与布局各不相同。在填入数据之前，请先查看所有标签页，以了解模板的结构。以下是常见的标签页名称及其典型内容：

| 常见标签页名称 | 需要关注的内容 |
|------------------|----------------|
| IS、P&L、利润表 | 利润表 |
| BS、资产负债表 | 资产负债表 |
| CF、CFS、现金流量表 | 现金流量表 |
| WC、营运资本 | 营运资本表 |
| DA、D&A、折旧及固定资产 | 折旧与摊销表 |
| Debt、债务表 | 债务明细表 |
| NOL、Tax、DTA | 净经营亏损表 |
| Assumptions、Inputs、Drivers | 参数假设与输入值 |
| Checks、Audit、Validation | 错误校验面板 |

**模板审查检查清单**
- 确认模板中包含哪些标签页（并非所有模板都包含所有表格）
- 记录上述列表之外、特定于该模板的标签页
- 了解标签页之间的依赖关系（例如，哪些表格为主要报表提供数据）
- 查明每个标签页中的输入单元格与公式单元格的位置

### 理解模板结构

在填充数据之前，先熟悉模板的现有布局，以确保数据被输入到正确的位置，且公式保持完整。

**识别行结构**
- 查看每个标签页顶部的模型名称
- 识别各章节标题及其视觉分隔标识
- 找到标注有“百万美元”、“%”、“倍”等单位的行
- 注意区分显示实际数值与预测数值的列标题
- 确认周期标签（如FY2024A、FY2025E）
- 区分输入单元格与公式单元格（通常通过字体颜色来区分）

**识别列结构**
- 确认最左侧列中的项目标签
- 验证历史年份是否位于预测年份之前
- 注意区分显示历史数据与预测数据的视觉边界
- 检查所有标签页中的列顺序是否一致

**使用命名范围**
模板通常会为关键输入项和输出项设置命名范围。在输入数据之前：
- 查看模板中现有的命名范围（在Excel中可通过“公式”→“名称管理器”查看）
- 常见的命名范围包括：营收增长率、成本百分比、核心指标（净收入、EBITDA、总债务、现金）、情景选择单元格
- 确保将数据输入到这些命名范围所对应的单元格中

### 预测周期
- 模板通常会从最后一个历史年份开始向前预测5年
- 确认历史数据列（A）与预测数据列（E）有明显区分
- 验证各列是否采用财年标识格式（如FY2024A、FY2025E）

## 利润率分析

**注意：仅当用户提出要求或模板明确需要时，才进行以下利润率分析。若无相关指示，请跳过此部分。**

在“损益表”选项卡中计算并显示利润率，以便追踪运营效率并进行同业比较。

### 需包含的核心利润率指标

| 利润率 | 公式 | 衡量内容 |
|--------|---------|----------|
| 毛利率 | 毛利润 / 营业收入 | 定价能力、生产效率 |
| EBITDA利润率 | EBITDA / 营业收入 | 核心运营盈利能力 |
| EBIT利润率 | EBIT / 营业收入 | 扣除折旧与摊销后的运营盈利能力 |
| 净利润率 | 净利润 / 营业收入 | 最终盈利水平 |

### 带有利润率指标的损益表布局

在每一项利润项目下方直接显示对应的百分比：
- 在毛利润下方显示毛利率%
- 在EBIT下方显示EBIT利润率%
- 在EBITDA下方显示EBITDA利润率%
- 在净利润下方显示净利润率%

## 信用指标

**注意：仅在用户提出要求或模板明确指定时，才需进行以下信用分析。若无相关要求，请跳过此部分。**

在“资产负债表”选项卡中计算并显示信用/杠杆指标，用以评估企业的财务健康状况、债务承受能力以及契约履行情况。

### 需包含的核心信用指标

| 指标 | 公式 | 衡量内容 |
|------|------|----------|
| 总债务/EBITDA | 总债务 / 近期12个月EBITDA | 杠杆倍数 |
| 净债务/EBITDA | （总债务 - 现金）/ 近期12个月EBITDA | 扣除现金后的杠杆水平 |
| 利息保障倍数 | EBITDA / 利息支出 | 偿还债务的能力 |
| 债务/总资本 | 总债务 / （总债务 + 股东权益） | 资本结构 |
| 债务/股东权益 | 总债务 / 总股东权益 | 财务杠杆程度 |
| 流动比率 | 流动资产 / 流动负债 | 短期流动性 |
| 速动比率 | （流动资产 - 存货）/ 流动负债 | 即时流动性 |

### 信用指标层级评估

需确保“乐观情景”下的企业信用状况最优：
- 杠杆水平：乐观情景 < 基准情景 < 悲观情景（数值越低越好）
- 利息保障能力：乐观情景 > 基准情景 > 悲观情景（数值越高越好）
- 流动性：乐观情景 > 基准情景 > 悲观情景（数值越高越好）

### 条款合规性监控

若已知债务相关条款，可设置专门的合规性检查机制，将实际指标与条款设定的阈值进行对比。

## 场景分析（基准/乐观/悲观）

可在“假设”选项卡中使用下拉菜单选择场景，并结合CHOOSE函数或INDEX/MATCH函数来实现对应分析。

| 场景 | 描述 |
|------|------|
| 基准情景 | 管理层给出的指引或市场普遍预期 |
| 乐观情景 | 成长速度超出预期，利润率有所提升 |
| 悲观情景 | 成长速度低于预期，利润率面临压力 |

**需重点关注的影响因素**：营收增长、毛利率、销售与管理费用占比、应收账款周转期/应付账款周转期/应付票据周转期、资本支出占比、利率水平、税率。

**情景审计检查**：包含所有报表的切换开关、各情景下的资产负债表余额、现金平衡校验，以及层级约束规则（对于净利润、EBITDA、FCF及利润率而言，顺序为上行值 > 基准值 > 下行值）。

## 完成模型模板

本节提供通用指导，帮助您在完成任何三报表财务模型模板的同时，保留现有公式并确保数据完整性。

### 第一步：分析模板结构

在输入任何数据之前，请先仔细审查模板，了解其架构：

**区分输入单元格与公式单元格**
- 寻找用于区分输入单元格与公式单元格的视觉提示（字体颜色、单元格阴影等）
- 常见规则：蓝色字体表示输入值，黑色字体表示公式，绿色字体表示对其他工作表的链接
- 可使用Excel的“追踪引用/依赖项”功能（公式 → 追踪引用）来了解单元格之间的关联关系
- 检查可能用于控制关键输入值的命名范围（公式 → 名称管理器）

**梳理模板的逻辑流程**
- 明确哪些标签页会为其他部分提供数据（例如：假设条件 → 利润表 → 资产负债表 → 现金流表）
- 记录所有辅助表格及其与主报表的关联关系
- 在填充数据之前，先记录下模板中的具体项目及结构。
### 第2步：填写数据而不破坏公式

**数据输入的黄金准则**

| 准则 | 说明 |
|------|------|
| 仅编辑输入单元格 | 除非有意替换公式，否则切勿覆盖包含公式的单元格 |
| 保留单元格引用 | 复制数据时请使用“粘贴值”功能（Ctrl+Shift+V），以避免因源数据的格式设置而覆盖原有公式 |
| 统一模板中的单位 | 在输入数据之前，先确认模板是采用千位分隔、百万位分隔还是直接显示数值 |
| 遵循符号规范 | 按照模板既定的符号规则操作（例如，将支出标记为正数或负数） |
| 检查循环引用 | 如果模板涉及迭代计算，请确保已开启“启用迭代计算”选项 |

**安全的数据输入流程**
1. 确定指定的输入单元格位置（通常会有高亮显示或标签标识）
2. 先输入历史数据，随后验证对应时期的公式计算是否正确
3. 输入用于预测计算的假设参数
4. 查看计算结果，确认公式按预期正常运行
5. 如果必须修改公式单元格，请在更改前记录下原有的公式内容

**处理预置公式**
- 若公式引用了尚未填写的单元格，在所有数据输入完成之前，可能会出现临时性错误（如#REF!、#DIV/0!）
- 当公式产生异常结果时，需追溯相关数据源，找出缺失或错误的输入项
- 在删除行或列之前，务必检查所有工作表中的公式依赖关系，避免引发问题
### 第3步：公式验证

**公式完整性检查**

在依赖模板输出之前，需先确认公式能够正常运行：

| 检查类型 | 方法 |
|----------|------|
| 追溯引用来源 | 选中公式单元格 → 点击“公式”选项卡 → 选择“追踪引用来源”，以验证其引用的输入数据是否正确 |
| 追溯依赖项 | 确认关键输入数据已正确传递至预期输出单元格 |
| 计算公式值 | 使用“公式”选项卡中的“计算公式”功能，逐步执行复杂计算过程 |
| 检查硬编码值 | 投影公式应基于假设条件，而非包含硬编码的固定数值 |
| 使用已知值测试 | 输入简单的测试数值，验证公式能否生成预期结果 |
| 跨表格一致性检查 | 确保所有预测周期均采用相同的公式逻辑 |

**需注意的常见公式问题**
- 混合使用绝对引用和相对引用，导致在跨周期复制时出现错误结果
- 对外部文件或已删除区域的链接失效（出现#REF!错误）
- 在收入尚未增长的早期阶段出现除以零的情况（出现#DIV/0!错误）
- 循环引用警告（在计算利息时可能是有意为之）
- 不同预测列中的公式逻辑不一致（可使用Ctrl+\查找差异）

**验证跨表格链接**
- 确认出现在多个表格中的数值为链接关系而非重复数据
- 验证汇总数据是否与主报表中的对应明细项一致
- 检查所有表格中的周期标签是否对齐

### 第4步：按工作表进行质量检查

在填入模板后，需对每张报表执行以下验证检查：

**利润表质量检查**
- 各期收入数值与原始数据一致
- 所有费用项目之和等于报表中显示的总额
- 小计项（毛利润、息税前利润、息税前利润、净收入）的计算正确
- 税务计算逻辑合理（能正确处理亏损情况）
- 预测参数引用假设选项卡中的数值（无硬编码）
- 不同周期间的变动趋势合理

**资产负债表质量检查**
- 所有时期的资产等于负债加上所有者权益（核心检查项）
- 现金余额与现金流量表末尾的现金余额一致
- 流动资产账户与相关附表数据相符（如适用）
- 留存收益的结转正确：期初留存收益 + 净收入 - 股息 +/- 调整项 = 期末留存收益
- 债务余额与债务明细表数据一致（如适用）
- 所有资产负债表项目的符号正确（资产为正，大多数负债也为正）

**现金流量表质量检查**
- 现金流量表顶部的净收入与利润表的净收入一致
- 非现金加回项（折旧与摊销、无形资产摊销等）与其对应的原始附表或报表数据相符
- 流动资产变动的符号正确（资产增加意味着现金流出，故为负值）
- 资本支出与固定资产明细表或固定资产结转数据一致
- 筹资活动与资产负债表中债务和所有者权益账户的变动相关联
- 期末现金余额与资产负债表中的现金余额一致
- 期初现金余额等于上一期的期末现金余额

**附表质量检查**
- 期初余额与上一期间的期末余额一致  
- 结转逻辑正确（期初余额 + 增加额 - 扣除额 = 期末余额）  
- 日程表汇总金额与主报表的各项目相符  
- 计算中所使用的假设与“假设”选项卡中的内容一致  

### 第5步：跨报表一致性检查  

在验证完各个报表后，需确认这三份报表已正确整合：  

| 检查项 | 公式 | 预期结果 |
|-------|---------|-----------------|
| 资产负债表余额 | 资产 - 负债 - 所有者权益 | = 0 |
| 现金一致性检查 | 现金流量表期末现金余额 - 资产负债表现金余额 | = 0 |
| 净利润关联检查 | 利润表净利润 - 现金流量表期初净利润 | = 0 |
| 留存收益计算 | 上一期留存收益 + 净利润 - 股息支出 - 资产负债表期末留存收益 | = 0（必要时可调整SBC及其他项目） |

### 第6步：最终审核  

在认定模型已完成之前，请执行以下操作：  
- （如适用）逐一测试所有场景，确保每种情况下的校验都能通过  
- 检查所有#REF!、#DIV/0!、#VALUE!和#NAME?错误，并予以解决或做好记录  
- 确认所有输入单元格均已填入数据（检查是否有占位符值）  
- 验证所有报表中的单位是否一致  
- 在进行任何进一步修改之前，先保存一份干净版本的文件  

## 模型验证与审计  

本部分汇总了已完成模板的所有验证检查及审计流程。  

### 核心关联关系（必须始终成立）

### 循环引用处理

利息支出会导致循环引用问题：利息 → 净利润 → 现金 → 债务余额 → 利息

在 Excel 中启用迭代计算功能：文件 → 选项 → 公式 → 启用迭代计算。将最大迭代次数设置为100，最大变化量设置为0.001。同时可在“假设”选项卡中添加中断机制开关。

### 校验类别

**第1类：货币一致性**
- 在“假设”选项卡中明确指定并记录所用货币
- 所有选项卡均使用统一的货币符号和小数位数格式
- 单位行所标注的货币单位与模型中的设定一致
**第2节：资产负债表一致性检查**
- 资产 = 负债 + 所有者权益（各会计期间均需满足）
- 公式：资产 - 负债 - 所有者权益（结果必须为0）

**第3节：现金流一致性检查**
- 现金流与资产负债表相关联（期末现金 = 资产负债表中的现金余额）
- 月度与年度现金流对比：月度期末现金 = 年度期末现金
- 净利润与损益表相互关联（现金流中的净收入 = 损益表中的净利润）
- 折旧与摊销需与相关明细表保持一致
- 营业资本变动与损益表相关联
- 应收账款变动、存货变动、应付账款变动需与营运资金明细表对应
- 资本支出需与折旧明细表保持一致

**第4节：留存收益管理**
- 留存收益结转验证：期初留存收益 + 净利润 + 营业资本变动 - 股息 = 期末留存收益
- 提供各构成项的详细拆解以便调试

**第5节：营运资金分析**
- 应收账款、存货、应付账款需与资产负债表保持一致
- 对应收账款周转期、存货周转期、应付账款周转期的合理性进行验证（若超出正常范围则标记异常）

**第6节：债务计划表**
- 总债务额需与资产负债表中的流动负债及长期负债之和相符
- 利息计算需与损益表相关联

**第6b节：股权融资**
- 股权发行所得资金需反映在资产负债表的普通股及资本公积增加项中
- 来自股权融资的现金增加额必须等于股东权益账户的增加额（两者需保持平衡）
- 股权融资差额验证：资产负债表中普通股/资本公积的变动额 = 股权发行带来的现金流量（结果必须为0）
- 第0年的股权融资关联验证：第0年的股权融资额 = 第1年的期初股东权益

**第6c节：税务亏损递延计划表**
- 初始净亏损额（第一年/成立初期）= 0（新业务启动时的净亏损额为零）
- 仅当息税前利润为负时，净亏损额才会增加（必须出现亏损才能形成净亏损额）
- 税盾与资产负债表相关联（净亏损额相关的税盾项 = 资产负债表中的递延所得税资产）
- 净亏损额的利用比例不得超过息税前利润的80%（2017年后的联邦税法限制）
- 净亏损额余额必须为非负值（不得超出可用额度进行使用）
- 仅当息税前利润为负时才会产生净亏损额
- 当应纳税所得额≤0时，税费为0

**第7节：情景层级结构**
- 绝对指标：乐观情景 > 基准情景 > 悲观情景（净利润、EBITDA、自由现金流）
- 利润率指标：乐观情景 > 基准情景 > 悲观情景（毛利率、EBITDA利润率、净利润率）
- 杠杆率相关信用指标：由于逻辑关系相反，呈现为乐观情景 < 基准情景 < 悲观情景

**第8节：公式完整性**
- 成本、销售与营销费用、一般与管理费用、研发费用以及销售业务成本均按收入比例计算（无硬编码值）
- 各预测年度的公式保持一致
- 不得出现#REF!、#DIV/0!、#VALUE!等错误

**第9节：信用指标阈值**
- 根据契约设定的阈值将各项指标标记为绿色/黄色/红色
- 提供所有红色预警指标的汇总信息

### 综合检查公式

将所有章节的状态汇总为一项综合检查结果：
- 若所有章节均通过检查 → “✓ 所有检查均通过”
- 若有任何章节未通过 → “✗ 检测到错误——请查看下方内容”

### 快速调试流程

当综合状态显示存在错误时：
1. 滚动页面查找标有红色的章节
2. 确定是哪一类检查出现了问题
3. 转到源数据标签页进行详细核查
4. 解决根本问题
5. 返回检查标签页确认问题已解决

## 数据来源——优先使用MCP，网络连接失败时备用

以下内容中多处提到“使用 S&P Kensho MCP / Daloopa MCP / FactSet MCP”。这些均为源自原有 Cowork 插件体系的商业金融数据 MCP 工具。在 Hermes 中：

- **如果您已配置了任何结构化的金融数据 MCP**（Hermes 支持 MCP 功能，详见 `native-mcp` 技能），则优先使用它们来获取特定时间点的财务数据、历史交易记录及监管文件信息。
- **若未配置此类 MCP**，可采取以下替代方案：
  - 对于美国市场的监管文件，可通过 SEC EDGAR 网站（`https://www.sec.gov/cgi-bin/browse-edgar`）使用 `web_search` / `web_extract` 功能进行检索；
  - 从公司的投资者关系页面获取新闻稿和业绩展示材料；
  - 对于交互式数据门户，则可使用 `browser_navigate` 功能；
  - 也可以使用用户提供的数据（当上下文信息不足时，应主动向用户询问）。
- **绝不可编造数据**。如果无法找到相关倍数、历史交易记录或文件编号，应将对应单元格标记为 `[UNSOURCED]`，并将其展示给用户。
