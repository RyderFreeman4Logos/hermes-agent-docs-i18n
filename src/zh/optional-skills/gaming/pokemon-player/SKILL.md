# 宝可梦游戏模拟器

通过 `pokemon-agent` 包利用无头仿真技术来运行宝可梦游戏。

## 适用场景
- 用户说出“玩宝可梦”、“开始宝可梦游戏”等类似指令
- 用户询问关于《宝可梦红》《蓝》《黄》《火红》等相关游戏
- 用户希望观看 AI 玩宝可梦游戏
- 用户提及 ROM 文件（.gb、.gbc、.gba 格式）

## 启动流程

### 1. 首次设置（克隆仓库、创建虚拟环境、安装软件）
该项目的 GitHub 地址为 NousResearch/pokemon-agent。首先克隆该仓库，然后创建一个 Python 3.10+ 版本的虚拟环境。推荐使用 uv 工具来快速创建虚拟环境，并以可编辑模式安装包含 pyboy 扩展功能的包。如果未安装 uv，则可使用 python3 -m venv + pip 的方式替代。

在本机上，相关设置已准备好，位于 /home/teknium/pokemon-agent 目录下，只需进入该目录并执行 .venv/bin/activate 即可。此外还需要一个 ROM 文件，需向用户索取。本机上的 ROM 文件存放在该目录下的 roms/pokemon_red.gb 文件中。**切勿自行下载或提供 ROM 文件，务必始终询问用户**。

### 2. 启动游戏服务器
在已激活虚拟环境的 pokemon-agent 目录下，运行 `pokemon-agent serve` 命令，同时指定 --rom 参数指向 ROM 文件路径，并设置端口为 9876。可使用 & 符号将命令在后台运行。若要从保存的游戏中继续，可添加 --load-state 参数并指定保存文件名。等待约 4 秒让服务器启动完成，随后通过访问 GET /health 接口验证服务器状态。

### 3. 设置实时控制面板供用户查看
通过 localhost.run 提供的 SSH 反向隧道功能，让用户能够在浏览器中查看控制面板。使用 ssh 连接到 nokey@localhost.run，将本地的 9876 端口映射到远程的 80 端口。将输出结果重定向到日志文件中，等待 10 秒后，通过 grep 命令查找 .lhr.life 格式的网址。最终将带有 /dashboard/ 后缀的网址提供给用户。由于隧道地址每次重启都会变化，因此需要在新启动时将新地址告知用户。

## 保存与加载

### 何时保存
- 每进行 15-20 轮游戏后
- 在参加道馆对战、遭遇对手或进行高风险战斗之前务必保存
- 进入新城镇或地下城之前
- 在执行任何不确定的操作之前

### 如何保存
发送 POST /save 请求，并附上具有描述性的文件名。例如：before_brock、route1_start、mt_moon_entrance、got_cut 等。

### 如何加载
发送 POST /load 请求，并提供保存时的文件名。

### 查看所有可用保存状态
发送 GET /saves 请求即可获取所有已保存的游戏状态。

### 在服务器启动时自动加载保存状态
在启动服务器时使用 --load-state 参数，即可自动加载之前的保存状态。这种方式比启动后再通过 API 加载要快得多。

## 游戏流程循环

### 第一步：观察——检查游戏状态并截图
发送 GET /state 请求，获取角色位置、生命值、战斗状态及对话内容。随后发送 GET /screenshot 请求，将截图保存到 /tmp/pokemon.png 文件中，再使用 vision_analyze 工具进行分析。**这两步必不可少**——内存状态只能提供数值信息，而视觉分析则能帮助了解空间环境。

### 第二步：确定方向
- 根据屏幕上的对话或文字内容决定下一步行动
- 处于战斗状态时，选择进攻或逃跑
- 队友受伤时，前往宝可梦中心治疗
- 接近目标地点时，需谨慎移动

### 第三步：做出决策
决策优先级为：对话处理 > 战斗行动 > 治疗 > 完成剧情目标 > 训练 > 探索

### 第四步：执行行动——每次最多移动 2-4 步，然后再次检查
发送 POST /action 请求，提供简短的行动列表（2-4 个动作，而非 10-15 个）。

### 第五步：验证——每完成一系列移动后截图确认
每次移动完成后都需截取屏幕画面，并使用 vision_analyze 工具确认是否确实移动到了预期位置。**这是最关键的一步**，如果没有视觉反馈，很容易迷路。

## 动作指令参考
- press_a — 确认、对话、选择
- press_b — 取消、关闭菜单
- press_start — 打开游戏菜单
- walk_up/down/left/right — 向上/下/左/右移动一格
- hold_b_N — 按住 B 键 N 帧（用于快速浏览文字）
- wait_60 — 等待约 1 秒（60 帧）
- a_until_dialog_end — 不断按 A 键，直到对话框消失

## 根据经验总结的关键提示

### 持续使用视觉分析功能
- 每移动 2-4 步后务必截图
- 内存状态只能显示位置和生命值，无法反映周围环境
- 悬崖边缘、围栏、指示牌、建筑物门、NPC 等元素，只有通过截图才能看到
- 可以向视觉分析模型提出具体问题，例如：“我正北方向一格处有什么？”
- 当陷入困境时，务必先截图，再尝试随机方向移动

### 穿过门或楼梯时需要额外等待时间
在穿过门或楼梯时，地图切换过程中屏幕会变黑。**必须等待该过程完全结束**。在每次通过门或楼梯后，需额外添加 2-3 次 wait_60 操作。如果不等待，角色位置信息可能会失效，导致你误以为自己仍在旧地图中。

### 离开建筑物时的陷阱
离开建筑物后，角色会直接出现在建筑物正前方。如果向北移动，实际上会回到建筑物内部。**务必先向左或向右移动两格绕行，然后再按原方向前进**。

### 对话处理技巧
第一代游戏中的对话是逐字缓慢滚动的。若想快速浏览对话，可按住 B 键 120 帧，然后按 A 键。根据需要重复此操作。按住 B 键可使对话以最快速度显示，之后再按 A 键切换到下一行。虽然 a_until_dialog_end 动作会检测内存中的对话状态，但该机制无法覆盖所有对话场景。如果发现对话卡住，建议手动使用按住 B 键再加按 A 键的技巧，并通过截图确认情况。

### 悬崖边缘只能向下跳跃
悬崖边缘（小型陡坡）只能向下跳跃，无法向上攀爬。如果前方有悬崖阻挡，必须向左或向右移动以找到绕行路径。可利用视觉分析功能确定缺口所在方向，也可直接向视觉分析模型询问。

### 导航策略
- 每次移动 2-4 步后截图，确认位置是否正确
- 进入新区域后立即截图，以便判断方向
- 可向视觉分析模型询问：“去[目标地点]应该往哪个方向走？”
- 如果尝试多次仍无法找到路径，需截图并重新全面评估情况
- 避免一次性执行 10-15 次移动，否则很容易超出目标范围或陷入困境

### 从战斗菜单中快速选择“逃跑”选项
在战斗菜单中，“逃跑”选项位于右下角。从默认光标位置（左上角的“战斗”选项）到达该选项，需先向下再向右移动光标，然后按 A 键。若想快速浏览文字和动画，可按住 B 键。

### 战斗操作说明
在战斗菜单中，“战斗”选项位于左上角（即默认光标位置）。按 A 键进入动作选择界面，再次按 A 键即可使用第一个动作。之后按住 B 键，可以加快攻击动画和文字的显示速度。

## 战斗策略

### 决策树
1. 如果想捕捉对手的宝可梦 → 先削弱其实力，再使用精灵球捕捉
2. 如果不需要的野生宝可梦 → 立即逃跑
3. 如果自己的宝可梦在属性上具有优势 → 使用超有效攻击招式
4. 如果没有属性优势 → 使用最强且与对手属性相克的招式
5. 如果自己宝可梦的生命值较低 → 更换宝可梦或使用药水

### 第一代宝可梦属性相克表（关键对战关系）
- 水属性能克制火、地面、岩石属性
- 火属性能克制草、虫、冰属性
- 草属性能克制水、地面、岩石属性
- 电属性能克制水、飞行属性
- 地面属性能克制火、电、岩石、毒属性
- 心灵属性在第一代游戏中极具优势，能克制格斗、毒属性！

### 第一代游戏的特殊规则
- 特殊招式的攻击力和防御力都由“特殊属性值”决定
- 心灵属性过于强势（幽灵属性存在漏洞）
- 临界伤害取决于速度属性值
- “缠绕”和“束缚”技能可以阻止对手行动
- “能量集中”技能存在漏洞：实际上会降低临界伤害率，而非提升它

## 停止游戏
1. 通过发送 POST /save 请求，使用具有描述性的文件名保存游戏
2. 使用 PKM:PROGRESS 更新内存中的进度记录
3. 告诉用户：“游戏已保存为 [文件名]！如需继续游戏，请说‘play pokemon’。”
4. 终止服务器及隧道相关的后台进程

## 常见问题与注意事项
- **切勿自行下载或提供 ROM 文件**
- 在未通过视觉分析确认之前，不要连续发送超过 4-5 个动作指令
- 离开建筑物后，无论向哪个方向移动，都务必先绕行
- 每次通过门或楼梯后，必须额外添加 2-3 次 wait_60 操作
- 仅依赖内存中的对话检测结果并不可靠，务必通过截图进行确认
- 在面临高风险战斗之前务必先保存游戏
- 每次重启隧道服务后，其网址都会发生变化
