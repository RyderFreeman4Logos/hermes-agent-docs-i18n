# 站点专用操作方案（预录制的处理流程）

这些经过实地验证的处理方案旨在让代理**直接执行**既定步骤，而无需每次都重新探索：例如浏览器内搜索或取消选项是否有效、存在哪些数据删除途径、哪种方式最为高效，以及常见的陷阱或最终结果是什么。对于那些没有自己独立的 `references/brokers/<id>.json` 记录的站点，这些方案就起到了持久存储的作用（而那些拥有该文件的站点则依赖对应的 broker JSON 文件作为记忆载体）。

**相关策略定义在 `methods.md` 文件中**，内容包括默认的自动取消选项设置、被阻止表单时的备用邮件处理顺序以及验证码策略。该文件还包含了站点矩阵、跳过列表以及后端集群信息。一旦你掌握了某个站点的处理规则，只需在此处添加或修改相应行即可（如果该站点频繁成为删除目标，还可将其升级为独立的 broker JSON 文件）。

## 被阻止数据的处理矩阵（截至 2026-07-03 的有效数据）

| 站点 | 支持浏览器内搜索？ | 最佳处理途径 | 实地验证的陷阱/最终结果 |
|---|---|---|---|
| **PropertyRecs** | 是（展示真实房源信息） | 浏览器内**一键删除** | 表单仅包含一个**全名**字段和一个**城市/州**字段（并非分别填写姓名和地址），无需邮箱验证，也无验证码。操作成功后会显示“信息已删除”的提示，是该批次中最简便的删除方式。 |
| **CheckPeople** | 搜索流程即为处理流程 | 浏览器内**引导式流程** | 首先发送邮件，随后提供验证链接 `/opt-out/dob/<token>`（发件人为 `info@checkpeople.com`），接着需要输入出生日期（该信息不可更改），再填写法定姓名，最后系统会匹配相关记录。若显示“未找到与您的姓名和出生日期匹配的记录”，则属于明确的**未找到结果**（因为该平台的匹配器已进行了独立检测）。 |
| **InfoTracer** | 需通过表单访问 | 发送邮件至 `privacy@infotracer.com`（在 `/optout` 页面有说明） | 表单地址为 `members.infotracer.com/removeMyData`，其中包含一个**滑动验证滑块**（切勿尝试绕过该机制）。官方提供的联系邮箱可通过 Zendesk 系统获得回复，并会附上处理工单编号。该平台使用 **InfoPay 后端系统**。 |
| **SpyFly** | 需通过表单访问 | 发送邮件至 `deletemyinfo@spyfly.com` | 页面 `/help-center/remove-my-public-record` 前置有**Cloudflare 防护机制，无法直接通过**。其隐私政策仅提及可通过表单或电话处理，但实际上 `deletemyinfo@` 这个邮箱是有效的删除渠道。 |
| **ZoomInfo** | 需通过邮件验证 | 提交邮箱地址（若无对应档案则无需操作） | 系统会提示“如果您的邮箱与某份档案匹配，我们将发送操作指引”。若未收到任何指引，则说明该邮箱没有对应的档案。该平台主要存储企业**工作联系人**信息，普通居民的记录通常不会被匹配到。 |
| **UnMask** | 采用引导式流程（但存在问题） | **需人工干预** | 该平台属于 PeopleConnect 系列，数据由 Suppression Center 处理；第一步会显示“邮件已发送”，但实际**从未有验证邮件送达**（经 2 小时多次检查，包括垃圾邮件文件夹，均无结果），这说明是平台端发送失败，需要人工重新尝试发送验证邮件。 |
| **PrivateRecords** | 需通过表单处理 | **已被阻止** | 访问 `/api/helper/optOutLight/search` 后需通过**双重验证码验证**（先是扭曲文字图像验证码，然后是算术题），但最终仍会以“验证码验证失败”为由被拒绝（实际上系统是在识别自动化操作，而非判断答案对错）。该平台没有提供相关的权利申诉邮箱，政策中仅包含取消订阅链接。 |
| **SearchQuarry** | 任何搜索方式均无效 | **切勿尝试处理**（需人工决策） | 其验证流程与 InfoTracer 类似，也使用**滑动验证滑块**。其常见问题解答明确指出，该平台仅接受通过邮件或传真提交的表单，以及政府颁发的身份证明复印件作为删除申请。由于该做法违反了最小信息披露原则，因此必须由人工决策处理，不得自动尝试。 |

此外，通过操作员手动检查（`operator_manual_check` 证据记录），本次检查还发现了以下属于**未找到结果**的站点：**ClustrMaps、PeekYou、NeighborReport**（页面显示 404 错误或已关闭），**USA People Search**（无匹配结果），以及 **BeenVerified**（同样无结果；不过当时曾考虑向相关机构发送一封可选的预防性删除邮件，但最终未实施）。任何无法访问的站点或经操作员确认无匹配结果的搜索，均属于有效的**未找到结果**。

## 后端集群机制（一个操作员的行为可推断其他站点的处理方式）

- **InfoPay 后端系统**同时服务于 **InfoTracer 和 SearchQuarry** 等平台：这些平台的表单字段均为相同的 `InfoPay_Core_Components_OptOuts_*` 格式，且都配有同样的**滑动验证滑块**。如果某个平台出现了该滑块，其他平台很可能也有，此时可直接使用对应的邮件处理方式（如文档中所述），或直接跳过该平台。
- **PeopleConnect / Intelius 的前端界面**与 **addresses.com** 的处理方式类似：相关报告链接会指向 `tracking.intelius.com`。这两个平台被归入同一集群进行统一管理（因为 `addresses.com` 属于 `intelius.owns` 范围），因此无需单独设置取消选项。详情可参考 `brokers/intelius.json` 和 `brokers/addresses.json` 文件。

## 元搜索/链接聚合平台——无需提交取消请求（无需操作）

这类平台**不存储任何第一方数据**，它们只是将姓名插入到社交搜索网址中，并展示指向我们已处理的合作平台的关联链接（如 Spokeo、TruthFinder、BeenVerified 等）。当这些平台的底层系统完成数据清除后，这些聚合平台也会随之处理。对于这类平台，只需记录“未找到结果”并继续处理，**无需**将其添加为独立的 broker 记录或提交删除请求：

> **IDCrawl、Lullar、Yasni、WebMii、Namesdir、iTools、Skipease。**

## 扫描前的分类筛选（分类体系）

在核查任何外部“人员信息开源情报”列表时（例如 OSINT Radar 目录），请先进行如下分类：

1. **第一方数据经纪商**——视为删除目标，需进行扫描或自动取消操作。
2. **元搜索/链接聚合平台**——无需操作，可参考上文的跳过列表。
3. **集群式前端平台**——已由上级平台覆盖处理（例如 addresses.com 对应 Intelius），无需重复提交请求。
4. **非经纪商工具/API或属于错误管辖区域的平台**——直接跳过：如 PhoneInfoga（一种工具）、People Data Labs（开发用 API）、Truecaller（需登录才能使用的应用）、Canada411 / 192.com（分别属于加拿大和英国的管辖范围）。
