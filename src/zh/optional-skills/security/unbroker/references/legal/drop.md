# 加州 DROP 平台（最高效的解决方案）

加州**删除请求与选择退出平台**（`privacy.ca.gov/drop`）允许加州居民通过一次经过验证的请求，免费向所有已注册的数据经纪人提出删除个人信息的要求。该平台已于**2026年正式启用**，各注册数据经纪人必须从**2026年8月1日**开始处理相关请求。其覆盖范围为**加州数据经纪人登记名录**（2025年约有545家经纪商），本智能体通过`pdd.py registry`模块将其作为独立处理范畴——只需提交一份DROP请求即可覆盖所有机构，这也使得该智能体的服务范围能够媲美甚至超越各类商业服务。

## 适用场景

对于`residency_jurisdiction`字段值为`US-CA`的查询对象，应**首先使用DROP平台**：执行`pdd.py next`命令后会生成一个涵盖整个登记名录的`drop_submit`操作。之后再处理各个个人信息搜索网站（这些网站也支持直接处理，因为它们会提供免费的索引列表）。提交请求后，运行`pdd.py drop <subject> --filed`命令即可让循环停止再次处理该对象。对于非加州地区的查询对象，DROP平台不适用，应通过定向发送CCPA/GDPR删除邮件的方式来处理登记名录中的数据经纪人（先执行`pdd.py registry --search`，再执行`pdd.py send-email`）。

## 处理流程（由智能体协助，主要依赖人工验证）

1. 操作员创建或验证DROP账户（该州要求进行身份验证，此步骤需由人工完成——状态为`human_task_queued`）。
2. 提交一份涵盖所有注册数据经纪人的删除请求。
3. 创建一个名为`case_<subject>_drop`的记录以跟踪处理进度，状态依次为`submitted` → `awaiting_processing`。注册数据经纪人必须按照州政府规定的时间表处理删除请求。
4. 在完成DROP流程后，重新扫描个人信息搜索网站的剩余数据，仅对仍显示相关信息的网站采取进一步措施。

## 注意事项

- DROP平台仅覆盖**已注册的数据经纪人**，并不包括所有个人信息搜索网站。对于未注册的网站，仍需逐一进行选择退出操作。
- 身份验证的要求意味着该流程的部分环节无法（也不应）完全自动化处理。
- 遵循FCRA法规管理的经纪商（在登记名录中标记为`optout.fcra`）所持有的消费者报告数据适用不同规则；此类数据的删除可能受到限制，反而可能需要通过争议处理或账户冻结的方式来解决。
