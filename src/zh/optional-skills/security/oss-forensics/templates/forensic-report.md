## 建议措施

### 立即采取的行动（如确认已遭入侵）

- [ ] 更换所有可能已被泄露的GitHub令牌、API密钥及凭证
- [ ] 在所有受影响的包中，将依赖版本固定为特定哈希值
- [ ] 如适用，发布安全公告或CVE信息
- [ ] 通知下游用户及软件包注册平台（如npm、PyPI等）
- [ ] 撤销被入侵账户的访问权限，并启用硬件级双重认证
- [ ] 审计所有CI/CD工作流文件，检查是否存在未经授权的修改
- [ ] 审查在入侵期间发布的所有版本

### 监控建议

- [ ] 为 `main`/`master` 分支启用分支保护机制（要求代码审核，禁止强制推送）
- [ ] 强制要求提交时进行签名（使用GPG/SSH方式）
- [ ] 设置GitHub审计日志流式传输功能，以便后续监控
- [ ] 在锁定文件中将关键依赖项固定为已知正常的SHA哈希值
