# 对抗性用户体验测试

为你的产品扮演最糟糕的用户——那种厌恶技术、不想要你的软件，并且会找尽理由抱怨的人。然后通过务实性过滤层来筛选他们的反馈，从而区分真正的用户体验问题与“我讨厌电脑”这类无意义的抱怨。

可以将其视为一种自动化的“妈妈测试”——只不过是更愤怒的那种。

## 为何这种方法有效

大多数质量检测只能发现漏洞，而这种方法能找出**使用障碍**。一个在技术上完全正确的应用，对普通用户来说仍可能难以使用。对抗性角色能够识别出：
- 对开发者有意义但对用户而言令人困惑的术语
- 完成基本任务所需的步骤过多
- 缺乏引导流程或“顿悟时刻”
- 可访问性问题（字体大小、对比度、点击区域）
- 启动阶段的问题（空白界面、无演示内容）
- 会阻碍转化率的付费墙或注册流程障碍

**务实性过滤层**（第三阶段）正是让这项测试具备实际价值而非仅具娱乐性的关键。如果没有它，你可能因为爷爷看不懂PDF文件，就不得不在每个页面上都加上“打印此页”的按钮。

## 使用方法

告诉智能体：
```
"Run an adversarial UX test on [URL]"
"Be a grumpy [persona type] and test [app name]"
"Do an asshole user test on my staging site"
```

你可以自行设定角色画像，或者让智能体根据产品的目标用户群体自动生成一个。

## 第一步：定义角色画像

如果未提供角色画像，则需通过回答以下问题来创建一个：
1. **对于该产品而言，最难使用的用户是谁？**（50岁以上、非技术背景、长期习惯用传统方式操作）
2. **他们的技术使用熟练度如何？**（越低越好——仅会使用WhatsApp、依赖纸质笔记本、甚至由妻子帮忙设置邮箱）
3. **他们最需要完成的一件事是什么？**（是他们核心的工作任务，而非产品功能列表中的内容）
4. **什么会让他们放弃使用？**（操作步骤过多、充斥专业术语、速度过慢或界面混乱）
5. **他们感到沮丧时会如何表达？**（直率粗鲁、满口脏话、不屑一顾或不断叹气）

### 典型的优质角色画像示例
> **“大米克”·麦卡利斯特**——58岁的体育教练。只使用WhatsApp，他的“电子表格”就是纸质笔记本。“如果10秒内搞不定，我就回去用笔记本。”他需要为25名运动员记录训练数据，极其厌恶小字体、专业术语和密码。

### 反面的劣质角色画像示例
> “一个不喜欢这款应用的用户”——描述过于模糊，没有任何具体限制条件，也缺乏真实特征。

角色画像必须足够具体，才能在20分钟的测试过程中始终保持该角色的行为特征。

## 第二步：代入角色进行实操测试

1. 阅读所有可获取的项目文档，了解应用背景及相关网址
2. **完全融入该角色的视角**——理解他们的挫败感、局限性及目标
3. 使用浏览器工具访问该应用
4. **尝试完成角色实际需要执行的任务**（而非功能浏览）：
   - 他们能否完成原本想要做的事？
   - 需要点击多少次或切换多少页面才能完成？
   - 有哪些地方让他们感到困惑？
   - 什么会让他们生气？
   - 他们在哪些环节会迷失方向？
   - 什么会让他们放弃，转而回到原来的操作方式？

5. 测试以下各类使用障碍：
   - **第一印象**——他们是否会愿意继续浏览，而不会直接离开首页？
   - **核心工作流程**——他们最常需要执行的那项任务
   - **错误处理机制**——当他们操作出错时会发生什么？
   - **可读性**——字体大小、对比度以及信息密度
   - **速度**——该应用的操作速度是否比他们现有的方式更快？
   - **术语使用**——是否存在他们无法理解的专业术语？
   - **导航功能**——他们能否找到返回路径？是否清楚当前所在位置？

6. 为每一个痛点截图保存
7. 检查每个页面的浏览器控制台，查看是否有JavaScript错误

## 第三步：以角色身份撰写反馈

需以该角色的口吻和真实感受来撰写反馈——这并非故障报告，而是真实用户的情感宣泄。

```
[PERSONA NAME]'s Review of [PRODUCT]

Overall: [Would they keep using it? Yes/No/Maybe with conditions]

THE GOOD (grudging admission):
- [things even they have to admit work]

THE BAD (legitimate UX issues):
- [real problems that would stop them from using the product]

THE UGLY (showstoppers):
- [things that would make them uninstall/cancel immediately]

SPECIFIC COMPLAINTS:
1. [Page/feature]: "[quote in persona voice]" — [what happened, expected]
2. ...

VERDICT: "[one-line persona quote summarizing their experience]"
```

## 第4步：务实性筛选（至关重要——切勿跳过）

跳出角色设定，以产品负责人的视角来评估每一条反馈：

- **红色：真正的用户体验缺陷**——任何用户都会遇到此问题，而不仅仅是那些爱抱怨的人。必须修复。
- **黄色：合理但优先级较低**——确实存在问题，但仅影响极少数用户。予以记录。
- **白色：角色扮演产生的无意义内容**——类似“我讨厌电脑”之类的言论，并非产品问题。可直接忽略。
- **绿色：功能需求建议**——反馈中隐含着不错的创意。值得考虑。

### 筛选标准
1. 一位35岁、能力出众但时间紧张的用户是否也会遇到同样的问题？→ 归类为红色。
2. 这是否属于真正的无障碍性问题（如字体大小、对比度、点击区域等）？→ 归类为红色。
3. 这是否是“我希望它像纸质产品那样使用”的数字化抗拒心理？→ 归类为白色。
4. 这是否是该角色在日常工作中实际遇到的效率低下问题？→ 归类为黄色或红色。
5. 修复此问题是否会增加80%使用正常的用户的操作复杂度？→ 归类为白色。
6. 该反馈是否揭示了产品中缺失的引导环节？→ 归类为绿色。

**此筛选步骤是强制性的。** 绝对不能直接将角色扮演产生的原始反馈作为工单提交。

## 第5步：创建工单

仅针对**红色**和**绿色**类别的问题：
- 填写清晰、具有可操作性的标题。
- 包含该角色的原话引用（需有趣且易记）。
- 指出其背后真正的用户体验问题（需客观描述）。
- 提出可行的解决方案。
- 添加标签/标记：“ux-review”。

对于**黄色**类别的问题：创建一个汇总工单，将所有记录放入其中。

**白色**类别的问题仅出现在报告中，无需创建工单。

**每次测试最多创建10个工单**——重点处理最严重的问题。

## 第6步：生成报告

需包含以下内容：
1. 角色扮演的吐槽内容（第3步）——需生动且具象。
2. 经过筛选后的评估结果（第4步）——需务实且具备可操作性。
3. 已创建的工单列表（第5步）——附上对应链接。
4. 关键问题的截图。

## 实用建议

- **每次测试仅使用一个角色设定**。避免混杂不同视角的反馈。
- **在步骤2至3期间需保持角色形象**。仅在步骤4时打破角色设定。
- **优先测试核心工作流程**。不要被设置页面分散注意力。
- **空状态是发现问题的重要线索**。新用户的体验最能暴露问题所在。
- **最佳发现往往是角色在尝试完成其他任务时偶然发现的红色问题**。
- **如果角色没有任何反馈，说明该角色过于精通技术**。可将其设定为年龄更大、耐心更差、固执己见的人。
- **可在产品演示、发布前或批量功能上线后进行此测试**。
- **尽可能以新用户身份登录测试**。避免使用预置的管理员账户——冷启动体验往往存在最多问题。
- **完全没有白色类别的问题并非失败，而是一种信号**。如果务实性筛选未发现任何无意义内容，说明产品确实存在真实的用户体验问题，而非只是角色过于爱抱怨。
- **测试完成后，请查阅项目文档中的已知问题列表**。如果角色发现的缺陷已在列表中，那反而是最严重的发现——这意味着团队早已知晓该问题，却从未真正体会过用户的困扰。
- **订阅/付费墙功能测试至关重要**。不仅要使用正常账户测试，还需使用过期账户进行测试。“无法支付时会发生什么”这一场景能体现产品是否尊重用户，还是将用户数据当作筹码。
- **统计角色完成某项任务所需的点击次数**。如果点击次数超过5次，那么无论角色的技术水平如何，几乎都可以判定为红色问题。

## 各行业角色设定示例

这些仅为参考，需根据您的具体产品进行定制：

| 产品类型 | 角色设定 | 年龄 | 核心特征 |
|---------|---------|-----|-----------|
| 客户关系管理软件 | 养老院院长 | 68岁 | 将文件柜视为当前的客户关系管理系统 |
| 摄影类SaaS产品 | 农村地区的婚礼摄影师 | 62岁 | 通过电话记录客户信息，用纸质方式开具账单 |
| AI/机器学习工具 | 百货公司采购员 | 55岁 | 曾因3家失败的科技初创公司而心生疑虑 |
| 健身应用 | 传统健身房教练 | 58岁 | 使用纸质笔记本记录，手指粗大，视力不佳 |
| 会计软件 | 家族面包店主 | 64岁 | 用鞋盒存放收据，极度反感订阅服务 |
| 电子商务平台 | 市场摊位商贩 | 60岁 | 仅接受现金支付，智能手机仅用于打电话 |
| 医疗健康应用 | 资深全科医生 | 63岁 | 通过口述记录病情，由护士操作电脑 |
| 教育类应用 | 资深教师 | 57岁 | 依靠粉笔和口头讲解，使用活页夹存放作业 |

## 规则说明- 在第2步至第3步的操作中，请始终保持角色设定不变。  
- 行为需真实恶劣但公平公正——应找出实际存在的问题，而非刻意捏造的故障。  
- 第4步中的务实性过滤机制是**必须遵守**的。  
- 每次投诉都必须附上截图。  
- 单次会话最多可提交10个工单。  
- 请在测试环境或已部署的应用上开展测试，而非本地开发环境。  
- 每个角色设定、每次会话只能生成一份报告。
