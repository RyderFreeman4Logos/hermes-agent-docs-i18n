# 设置向导生成器

该工具可生成交互式的 Bash **向导**：这是一种脚本，能够引导用户逐步完成那些手动操作繁琐、且每次都需要重复说明的流程。它会自动打开各个 URL，明确指示用户需要点击和复制的内容，捕获输入的值并将其保存到指定位置（如 `.env` 文件或 GitHub 密钥中），在每个步骤结束后进行确认，并显示还剩多少步骤。

该功能基于 mattpocock/skills 项目中的 MIT 许可版 `wizard` 技能开发而来。

## 适用场景

- 部署基础设施或第三方服务（如 Stripe、Supabase、DNS、OAuth 应用），这类操作需要人工在控制台逐项完成；
- 设置凭证、CI 密钥或仓库变量；
- 需要人工干预且无法回退的一次性迁移或系统切换任务；
- 任何需要用户转交给同事执行的操作。

**注意：** 不建议用于那些机器人可以自行完成的步骤——这类操作应直接由机器人执行。

## 先决条件

- `bash`；仅当步骤涉及将 GitHub 密钥/变量写入文件时才需要 `gh` CLI；
- 该技能目录下的模板文件：`templates/template.sh`。

## 操作步骤

### 1. 明确操作范围

详细列出用户需要执行的每一步手动操作以及过程中需要捕获的所有值。建议先阅读仓库相关文档，而非直接开始询问：

- **设置阶段**：需考虑 `.env`、`.env.example`、`README`、`docker-compose*` 文件、框架配置文件，以及 `.github/workflows/*` 中的内容（所有 `secrets.*`/`vars.*` 的引用都是向导需要生成的值）；
- **迁移/切换阶段**：需明确当前状态、目标状态，以及两者之间那些无法回退的操作。
向用户展示有序的阶段列表以及每个阶段产生的值；用户可以对这些阶段进行添加、删除或重新排序。当所有阶段都按顺序命名，且对于每一个捕获到的值，都能明确知道：(a) 用户从何处获取该值，(b) 该值被保存在何处（`.env` 文件、GitHub 密钥、两者皆有或根本不存在），以及 (c) 该值是保密的（隐藏条目）还是公开的，此时任务即告完成。

### 2. 规划每个阶段的操作流程

针对每个阶段，详细记录用户需要遵循的操作路径：需打开哪个网址、在该页面上执行什么操作、值将显示在何处——例如“控制面板 → 开发者 → API 密钥 → 显示测试密钥 → 复制”。如果不确定当前的界面或确切命令，请如实说明，并查阅文档或寻求帮助——切勿编造可能并不存在的操作步骤。

### 3. 编写向导脚本

将 `templates/template.sh`（位于该技能的目录中）复制到目标路径。用按依赖顺序排列的各个“阶段”替换示例中的阶段内容。并将 `TOTAL_STAGES` 设置为你所定义的阶段总数。

可使用的库函数包括：`stage`、`say`/`step`/`note`/`warn`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`、`banner`、`finish`。位于 `STAGES` 标记之后的库代码在所有向导中都是相同的——切勿手动修改它，正是这种一致性才是该机制的核心所在。

请遵循模板设定的规范：在获取某个值之前先打开对应的 URL；处理敏感信息时使用 `ask_secret`，保存任何持久化值时使用 `write_env`，仅将 CI 实际需要的内容通过 `set_secret` 设置，并在执行任何不可逆操作前使用 `confirm`。每个 `stage` 都会清空屏幕——请确保每个阶段只专注处理一项任务，避免用户需要查看的内容被滚动掉。

向导默认为临时存在：可将其保存到临时目录或 `scripts/` 路径中，在任务完成后删除。只有当用户希望将可重复使用的配置路径存入代码仓库时，才将其提交。

### 4. 验证与交接

- 使用 `bash -n <script>` 进行语法检查；如果可用的话，还可运行 `shellcheck`；最后执行 `chmod +x <script>` 赋予执行权限。
- 请勿自行从头到尾运行该脚本：它会打开浏览器并等待人工输入。应通过静态方式追踪其执行过程：确保第一步中的所有值都能被正确捕获并出现在预定的位置，且每个 `set_secret` 的名称都与 CI 中的 `secrets.*` 参考项完全匹配。
- 告诉用户如何运行该脚本。如果它是可重复执行的，应将其提交并喺 README 中给出相关链接。

## 常见陷阱

1. **编辑库相关部分。** `STAGES` 标记以上的所有内容都属于向导库，其下方的内容才是作者自定义的内容。  
2. **确定仪表板路径。** 第三方用户界面可能会发生变化。如果不确定点击路径，应参考最新文档，或将其标记为近似路径。  
3. **仅对 CI 系统未使用的值使用 `set_secret`。** 只有工作流实际引用的信息才需添加到 GitHub Secrets 中。  
4. **自行运行向导。** 该向导需要人工输入才能继续执行；可通过静态追踪结合 `bash -n` 命令来进行验证。  
5. **避免使用过大的阶段。** 每完成一个阶段就清空屏幕会导致较长的阶段中关键指令被滚动遮挡，因此应拆分阶段。

## 验证清单

- [ ] 在编写内容前已与用户确认阶段列表  
- [ ] `bash -n` 命令执行成功；脚本具备可执行性  
- [ ] 所有捕获的值均能追溯到其指定的目标位置  
- [ ] 所有的 `set_secret` 名称都与 CI 系统中的 `secrets.*` 引用相匹配  
- [ ] 库相关部分未对模板进行任何修改
