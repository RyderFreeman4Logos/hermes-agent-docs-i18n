# 角色原型

专为视频制作设计的角色原型库。**请从该列表中组合团队，无需复制固定的角色配置**。大多数视频需要4到7个角色配置。导演角色始终存在；其他角色的设置则取决于项目需求。

按照惯例，每个角色配置的名称均采用“kebab-case”格式（例如 `creative-director`、`image-generator`）。当同一角色需要承担不同职责时，会为其添加描述性后缀（例如 `renderer-ascii`、`renderer-3d`）。

如需查看各角色的工具集与技能对应关系，请参阅 [tool-matrix.md](tool-matrix.md)。

## 始终存在的角色

### 导演

项目的愿景制定者。负责阅读项目需求与品牌指南，将其拆解为任务结构图，通过评论指导创作方向，并最终审核成片。

- **工具集**：看板、终端、文件
- **技能**：无需额外技能——看板任务编排指南（包括拆解流程规范以及“先拆解而非直接执行”的原则）会自动注入到每个负责看板任务的智能体的系统提示词中。如果项目需求较为宽泛且需要框架设计方面的帮助，可添加 `creative-ideation` 技能。
- **性格特征**：需与品牌调性保持一致——详情参见 `assets/soul.md.tmpl` 文件。

导演与其他角色使用相同的工具集，但其 `SOUL.md` 规则**禁止**直接执行任务。 “先拆解而非直接执行”的原则是通过性格设定以及自动注入的看板编排指南来强制执行的，而非因为缺少相应工具。

## 前期制作角色

需根据项目需求选择合适的角色。

### 编剧 / 电影编剧

用于编写脚本、对话内容、旁白文案以及解说词。适用于任何包含标语之外口头或文字内容的视频。

- **工具集：** 看板、文件
- **技能：** `humanizer`（用于后期处理，去除人工智能痕迹）
- **输出文件：** `script.md`、`narration.md`、`dialogue/scene-NN.md`

### 文案撰写师

与“编写器”类似，但专门用于创作营销文案：标语、行动号召语以及产品视频的旁白脚本。

- **工具集：** 看板、文件
- **技能：** `humanizer`
- **输出文件：** `copy.md`

### 概念艺术家/视觉设计师

负责打造视觉识别体系：包括情绪板、风格参考图、色彩方案说明以及字体选择。需制定一份所有生成工具都需遵循的`visual-spec.md`文件。通常还会利用图像生成API或本地技能来制作静态参考图。

- **工具集：** 看板、终端、文件
- **技能：** 任何与项目相关的设计技能——`claude-design`（UI/网页设计）、`sketch`（快速制作原型）、`popular-web-designs`（模仿知名网页风格）、`pixel-art`（复古风格）、`ascii-art`（终端/复古风格）、`excalidraw`（手绘参考图）、`design-md`（基于文本的设计文档）
- **输出文件：** `visual-spec.md`、`taste/style-frames/*.png`

### 分镜师

根据需求将策划方案转化为包含时间节点的详细分镜表。对于叙事类电影和音乐视频而言至关重要，通常会搭配图表工具使用。

- **工具集：** 看板、文件  
- **技能：** 图表绘制技能——`excalidraw`（草图绘制）、  
  `architecture-diagram`（技术/系统类图表）、`concept-diagrams`（教育/科学类图表）  
- **输出结果：** 每个场景/镜头对应一行的 `storyboard.md` 文件，可选提供分镜草图  

### 摄影师/视觉指导

负责设计整体的视觉风格：构图、色彩、动作效果及转场方式。会检查生成结果以确保视觉一致性，并将每个场景的详细视觉规范写入 `VISUAL_SPEC.md` 文件。  

- **工具集：** 看板、终端、文件、视频处理、视觉分析工具  
- **技能：** 根据项目需求选择相应的视觉生成技能（例如，用于ASCII艺术创作的 `ascii-video`、用于讲解类内容的 `manim-video`、用于实时视觉效果的 `touchdesigner-mcp` 等）  
- **输出结果：** 每个场景对应的 `scenes/scene-NN/VISUAL_SPEC.md` 文件，以及对渲染任务的审核意见  
- **审核方式：** 使用 `video_analyze`（将完整视频片段发送给多模态大语言模型进行专业审核）、`vision_analyze` 进行帧级抽查，以及通过 ffprobe 生成汇总报告  

## 制作角色  

### 渲染器（通用型）

负责为一个或多个场景生成视觉内容的任务节点。它会根据场景风格加载相应的创意技能。多个渲染器可并行运行，每个渲染器可通过其配置文件中的 `always_load` 参数或任务指令中的 `--skill` 参数指定要使用的特定技能。  

- **工具集：** 看板、终端、文件  
- **技能：** 一种创意技能（具体类型见下文专用版本）  
- **输出结果：** 每个场景对应的 `scenes/scene-NN/clip.mp4` 视频文件  

### 专用型渲染器版本

当不同场景需要截然不同的工具时，建议创建专门的渲染器配置文件，而非让单个渲染器承担过多功能。每种配置文件都会加载不同的创意技能。

| 变体 | 技能 | 最佳适用场景 |
|---------|-------|--------------|
| `renderer-ascii` | `ascii-video` | 终端风格、复古像素风、音频驱动的网格效果、视频转ASCII格式 |
| `renderer-manim` | `manim-video` | 数学内容、算法讲解、类似3Blue1Brown风格的演示、方程推导 |
| `renderer-p5js` | `p5js` | 生成艺术、粒子效果、着色器应用、自然流畅的运动效果、网页画布内容 |
| `renderer-comfyui` | `comfyui` | 使用本地ComfyUI工作流生成的AI静态图及视频（如图像转图像、图像转视频等） |
| `renderer-touchdesigner` | `touchdesigner-mcp` | 实时交互、音频驱动效果、装置艺术、VJ风格内容 |
| `renderer-3d` | Blender (`blender -b`脚本) | 3D建模、动画制作、逼真场景渲染、角色动画 |
| `renderer-pixel` | `pixel-art` | 具有对应时代色彩调色的复古游戏风格 |
| `renderer-comic` | `baoyu-comic` | 以知识漫画形式呈现的叙事场景 |
| `renderer-meme` | `meme-generation` *(可选)* | 用于讽刺或社交内容的模因风格静态图 |
| `renderer-procedural` | （无——直接使用Python结合PIL与ffmpeg） | 无法用现有技能实现的定制化程序化内容 |
| `renderer-video` | （外部图像转视频API：Runway / Kling / Luma） | 在叙事电影中为静态图片添加动画效果 |
| `renderer-motion-graphics` | （外部工具——Remotion CLI） | 动态图形设计、动态文字效果、用户界面动画 |
对于外部 API 渲染器，其配置文件中包含 API 客户端逻辑；无需加载额外的技能（每个工作节点都会自动注入看板控制功能），同时还包含终端工具集与 API 密钥。

### image-generator

专为文本转图像生成设计。通常会生成静态图片，这些图片随后会被传输至 `renderer-video` 模块以进行动画处理。

- **工具集：** 看板、终端、文件
- **技能：** 可选地使用 `comfyui`（用于驱动本地的 ComfyUI 安装以实现图像生成）
- **外部 API（作为本地 ComfyUI 的替代方案）：** FAL、Replicate、OpenAI Images、Midjourney
- **输出文件：** `scenes/scene-NN/stills/*.png`

### image-to-video-generator

该模块可接收静态图片，并通过 Runway/Kling/Luma API 或本地的 ComfyUI 图像转视频工作流将其转化为动画。在故事片制作流程中，它几乎总是紧随 `image-generator` 之后使用。

- **工具集：** 看板、终端、文件
- **技能：** 可选地使用 `comfyui`（用于实现诸如 AnimateDiff 或 WAN 这样的本地图像转视频工作流）
- **外部 API：** Runway、Kling、Luma、Pika
- **输出文件：** `scenes/scene-NN/clip.mp4`

### music-supervisor

该模块负责获取、分析并处理音乐音轨。对于音乐视频，它还会生成节拍/BPM 图谱以及关键帧时间戳。当编辑人员或渲染器需要直观了解音频的节奏强度时，它会借助 `songsee` 工具生成频谱图。

- **工具集：** kanban、终端、文件  
- **技能：** `songsee`（音频可视化），此外还需具备以下其中一项：  
  - `songwriting-and-ai-music` —— 用于委托创作歌词并生成 Suno 提示词  
  - `heartmula` —— 用于使用开源本地模型生成音乐  
  - `spotify` —— 用于查找现有歌曲  
- **输出文件：** `audio/track.mp3`、`audio/beats.json`（可选）、`audio/track-spectrogram.png`  

### 旁白/解说员

用于生成旁白音频。该角色直接调用 TTS API，无需使用 Hermes 技能（每个 kanban 工作节点都会自动注入相关指导）。用户也可选择使用预先录制的旁白音轨，而非自行生成。  
- **工具集：** kanban、终端、文件  
- **技能：** 无 —— 每个 kanban 工作节点都会自动注入相关指导  
- **外部 API：** ElevenLabs、OpenAI TTS 等  
- **输出文件：** `audio/voiceover/line-NN.mp3`、`audio/voiceover/timeline.mp3`  

### 音效设计师

负责设计音效与环境音。除非任务要求专门进行音效设计，否则该角色通常为可选配置。  
- **工具集：** kanban、终端、文件  
- **技能：** 在为现有曲目设计音效时，可使用 `songsee` 进行音频特征可视化  
- **输出文件：** `audio/sfx/*.mp3`  

## 后期制作角色

### 编辑

负责将各个片段整合为最终版本。通过 ffmpeg 工具实现片段拼接、淡入淡出及转场效果。在整合之前，还会逐一检查每个片段的节奏与质量。

- **工具集：**看板、终端、文件操作  
- **技能要求：**无——看板工作节点会自动注入相关指导说明  
- **外部工具：**ffmpeg、ffprobe  
- **输出文件：**`output/final.mp4`、`output/final-noaudio.mp4`  

### 色调师

负责视频的色彩分级处理。通常为可选步骤——若渲染工具已能生成符合品牌风格的输出，且后期剪辑仅进行简单拼接，则无需额外使用色调师功能。但对于需要精彩特写镜头的叙事影片，这一功能十分重要。

- **工具集：**看板、终端、文件操作  
- **技能要求：**无——看板工作节点会自动注入相关指导说明  
- **输出文件：**`output/final-graded.mp4`  

### 音频混音师

将旁白、音乐及音效混合为最终的音频轨道，可调节各声道的音量，让音乐在旁白播放时自动减弱，并对音频响度进行标准化处理（LUFS）。

- **工具集：**看板、终端、文件操作  
- **技能要求：**无——看板工作节点会自动注入相关指导说明  
- **外部工具：**带有`loudnorm`滤镜的ffmpeg，可选使用sox  
- **输出文件：**`audio/final-mix.mp3`  

### 字幕生成器

负责将字幕嵌入视频、生成SRT格式的字幕文件，并处理无障碍观看需求。此外，还可通过Whisper技术从音频中自动提取字幕。

- **工具集：**看板、终端、文件操作  
- **技能要求：**无——看板工作节点会自动注入相关指导说明  
- **外部工具：**Whisper（命令行或API）、ffmpeg字幕处理滤镜  
- **输出文件：**`output/captions.srt`、`output/final-captioned.mp4`  

### 最终编码师

负责视频的最终编码及不同格式的输出转换。会根据目标平台的要求生成相应的交付文件——如Instagram用方形格式、TikTok用竖屏格式、YouTube用全高清格式等。

- **工具集：** 看板、终端、文件  
- **技能要求：** 无——看板系统会自动为每位任务执行者提供相关指导  
- **输出文件：** `output/final-1080.mp4`、`output/final-9x16.mp4` 等  

## 质量管控角色

### 审核员

作为中立的质量把关人，负责阅读任务简述、观看剪辑内容，并针对节奏、同步性、品牌一致性及技术质量等方面提出具体意见。该角色与在拍摄过程中审核画面的摄影师以及负责整体剪辑的编辑不同。

- **工具集：** 看板、终端、文件、视频、视觉分析工具  
- **技能要求：** 无——看板系统会自动为每位任务执行者提供相关指导  
- **审核工具：** `video_analyze`（通过多模态大语言模型进行片段审核）、`vision_analyze`（帧/缩略图审核）、ffprobe  
- **输出文件：** `review-notes.md`、针对各项任务的反馈意见  

### 品牌合规审核员

专门负责检查颜色、字体及语音风格等是否符合品牌规范。当品牌指南十分详细时，普通审核员可能会遗漏某些违规之处，此时可启用此角色。

- **工具集：** 看板、文件  
- **技能要求：** 无——看板系统会自动为每位任务执行者提供相关指导  
- **输出文件：** 审核意见及 `brand-review.md`  

## 剪辑团队组建——决策准则

- **标准配置：** 1名导演 + 至少1名渲染器 + 1名编辑。  
- 若剧本中的对白、旁白或屏幕文字量超过简短标语的长度，则需添加**文案撰写员**。  
- 若任务需求包含5个以上不同的情节节点，且导演尚未制定节点清单，则需添加**故事板设计师**。  
- 若需要多个渲染器实例保持统一的视觉风格，则需添加**摄影指导**（对于仅使用单一工具制作视频的情况，该渲染器的自带技能配置即可满足需求）。  
- 对于需要逼真视觉效果的叙事电影，需添加**图像生成器**与**图像转视频生成器**组合。  
- 若提供了音乐且节奏至关重要（音乐视频必选，说明类视频视情况而定），则需添加**音乐监督**。  
- 任何旁白或叙事对白都需要添加**配音演员**。  
- 当存在2个及以上音频源（如人声与音乐、音乐与音效）时，需添加**音频混音师**。  
- 对于注重无障碍体验的项目（如说明视频、教程，或默认静音播放的所有平台内容），需添加**字幕生成员**。  
- 针对高要求项目，需添加**审核人员**；快速实验性测试则可省略此步骤。  
- 若需要为多个平台输出不同格式的最终作品，则需添加**音频后期处理师**。  

## 常见错误配置

- **单一渲染器处理所有任务。** 如果场景需要使用截然不同的工具（如ASCII图形、3D模型以及动态图形），则应选用专门的渲染器版本。该渲染器每次仅加载一种创意技能；在同一个渲染器中混用多种风格会导致性能严重下降。
- **每个场景应使用独立的配置文件。** 错误。配置文件是按角色划分的，而非按场景。通常一个场景只需使用一两个渲染器配置文件，而非八个。
- **使用能处理一切任务的“通用”配置文件。** 这比没有专门化处理更糟糕。如果所有任务都适用于同一个配置文件，看板任务分配机制就会失效。
- **重要交付物无需审核流程。** 虽然能节省一小时的流程处理时间，但却会导致缺陷产品被交付。
