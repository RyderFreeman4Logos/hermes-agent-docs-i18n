# 角色原型

用于视频制作的角色原型库。**请从该列表中组建团队，无需复制固定的角色配置**。大多数视频需要4到7个角色。导演角色始终存在；其他角色的设置则取决于项目需求。

按照惯例，每个角色的名称都采用“驼峰式”命名（例如 `creative-director`、`image-generator`）。当同一角色需要承担不同职责时，会通过添加描述性后缀来区分（例如 `renderer-ascii`、`renderer-3d`）。

关于各角色的工具集与技能对应关系，请参阅 [tool-matrix.md](tool-matrix.md) 文档。

## 始终存在的角色

### 导演

项目的创意核心。负责阅读项目需求与品牌指南，将其拆解为任务结构图，通过评论指导创作方向，并最终审批成片。

- **工具集**：kanban、终端、文件管理
- **技能**：无需额外技能——关于任务拆解的指导原则（即“先拆解，再执行”的准则）会自动注入到每个负责任务处理角色的系统提示词中。如果项目需求较为宽泛且需要创意构思方面的帮助，可额外添加 `creative-ideation` 技能。
- **性格设定**：需与品牌风格保持一致——详情参见 `assets/soul.md.tmpl` 文件。

导演与其他角色使用相同的工具集，但其 `SOUL.md` 规则**禁止**直接执行任务。所谓“先拆解，再执行”的准则是通过性格设定以及自动注入的任务拆解指导来强制执行的，而非因为缺少相应工具。

## 前期制作角色

根据项目需求选择合适的角色。

### 编剧 / 电影剧本作者

负责撰写脚本、对白、旁白文案及叙事文本。适用于任何需要口语或文字内容的视频，尤其是那些仅有标语的简单视频。

- **工具集**：kanban、文件管理
- **技能**：`humanizer`（用于后期处理，去除AI生成的痕迹）
- **输出文件**：`script.md`、`narration.md`、`dialogue/scene-NN.md`

### 广告文案撰写人

与编剧类似，但专门负责撰写营销文案，如标语、行动号召语以及产品视频的旁白脚本。

- **工具集**：kanban、文件管理
- **技能**：`humanizer`
- **输出文件**：`copy.md`

### 概念艺术家 / 视觉设计师

负责打造项目的视觉识别系统，包括情绪板、风格参考图、色彩方案说明以及字体选择等。还会编写一份 `visual-spec.md` 文件，作为所有内容生成工具的参考依据。该角色通常会使用图像生成API或本地技能来创建静态参考图。

- **工具集**：kanban、终端、文件管理
- **技能**：任何与项目相关的设计技能，例如 `claude-design`（用于UI/网页设计）、`sketch`（快速制作设计草图）、`popular-web-designs`（模仿知名网页风格）、`pixel-art`（复古风格）、`ascii-art`（终端/复古风格）、`excalidraw`（手绘风格帧图）、`design-md`（基于文本的设计文档）
- **输出文件**：`visual-spec.md`、`taste/style-frames/*.png`

### 分镜师

负责将项目需求转化为包含时间标注的逐镜头分镜表。这对于叙事类电影和音乐视频尤为重要，通常会配合图表工具使用。

- **工具集**：kanban、文件管理
- **技能**：图表绘制技能，例如 `excalidraw`（用于草图绘制）、`architecture-diagram`（用于技术/系统设计）、`concept-diagrams`（用于教育/科学类图表）
- **输出文件**：`storyboard.md`，每场景/每镜头占一行；可选地还会提供分镜草图

### 摄影指导 / 摄影师

负责设计视觉语言，包括构图、色彩、动作表现及转场效果。还会检查内容生成工具的输出结果，确保视觉风格一致，并为每个场景提供 `VISUAL_SPEC.md` 文件作为参考。

- **工具集**：kanban、终端、文件管理、视频处理工具、视觉分析工具
- **技能**：与项目需求匹配的视觉相关技能，例如用于ASCII风格内容的 `ascii-video`、用于讲解类内容的 `manim-video`、用于实时视觉效果的 `touchdesigner-mcp` 等
- **输出文件**：`scenes/scene-NN/VISUAL_SPEC.md`，以及对内容生成任务的审核意见
- **审核工具**：`video_analyze`（将完整视频片段发送给多模态大语言模型进行专业审核）、`vision_analyze`（用于检查单帧画面）、ffprobe（用于生成分析摘要）

## 制作阶段角色

### 通用渲染器

负责为一个或多个场景生成视觉内容的任务执行者。会根据场景风格加载相应的创意技能。多个渲染器可以并行运行，每个渲染器通过其角色配置中的 `always_load` 设置或任务参数中的 `--skill` 指令指定要使用的技能。

- **工具集**：kanban、终端、文件管理
- **技能**：一种创意技能（具体类型见下方的专用版本）
- **输出文件**：`scenes/scene-NN/clip.mp4`

### 专用渲染器版本

当不同场景需要完全不同的处理工具时，可创建专用渲染器角色，而非让一个通用渲染器承担所有任务。每个专用渲染器会加载不同的创意技能。

| 版本 | 技能 | 适用场景 |
|------|------|----------|
| `renderer-ascii` | `ascii-video` | 终端风格、复古像素风格、随音频变化的网格效果、视频转ASCII格式 |
| `renderer-manim` | `manim-video` | 数学内容、算法讲解、类似3Blue1Brown风格的教程、方程推导过程 |
| `renderer-p5js` | `p5js` | 生成艺术、粒子效果、着色器应用、有机动态效果、网页画布内容 |
| `renderer-comfyui` | `comfyui` | 使用本地ComfyUI工作流生成AI静态图和视频（包括图像转图像、图像转视频等功能） |
| `renderer-touchdesigner` | `touchdesigner-mcp` | 实时动态效果、随音频变化的视觉效果、装置艺术风格、VJ风格内容 |
| `renderer-3d` | `blender-mcp`（可选） | 3D建模、动画制作、真实感场景渲染、角色动画 |
| `renderer-pixel` | `pixel-art` | 复古游戏风格，搭配符合时代特征的色彩方案 |
| `renderer-comic` | `baoyu-comic` | 以知识漫画风格呈现叙事场景 |
| `renderer-meme` | `meme-generation`（可选） | 用于讽刺或社交内容的模因风格静态图 |
| `renderer-procedural` | 无——直接使用Python结合PIL和ffmpeg实现 | 对于无法用现有技能实现的定制化程序化内容 |
| `renderer-video` | （外部图像转视频API：Runway / Kling / Luma） | 为叙事电影中的静态图片添加动画效果 |
| `renderer-motion-graphics` | （外部工具：Remotion CLI） | 动态图形设计、动态排版、UI动画效果 |

对于使用外部API的渲染器，其角色配置中会包含API客户端逻辑；无需额外加载技能（因为任务拆解指导会自动注入到每个任务处理角色中），同时还会配备终端工具集及API密钥。

### 图像生成器

专门用于文本转图像功能。通常会生成静态图片，之后再由 `renderer-video` 工具将其转化为动画。

- **工具集**：kanban、终端、文件管理
- **技能**：可选地可添加 `comfyui`（用于驱动本地ComfyUI实例进行图像生成）
- **外部API（作为本地ComfyUI的替代方案）**：FAL、Replicate、OpenAI Images、Midjourney
- **输出文件**：`scenes/scene-NN/stills/*.png`

### 图像转视频生成器

负责将静态图片通过Runway/Kling/Luma API或本地ComfyUI的图像转视频工作流转化为动画。在叙事类电影的制作流程中，它通常会在图像生成器之后执行任务。

- **工具集**：kanban、终端、文件管理
- **技能**：可选地可添加 `comfyui`（用于本地实现如AnimateDiff或WAN之类的图像转视频工作流）
- **外部API**：Runway、Kling、Luma、Pika
- **输出文件**：`scenes/scene-NN/clip.mp4`

### 音乐监制

负责寻找、分析并准备音乐曲目。对于音乐视频，还会制作节拍/BPM图表以及关键帧时间戳。当剪辑师或渲染器需要了解音频的节奏强度时，该角色会使用 `songsee` 工具生成频谱图作为参考。

- **工具集**：kanban、终端、文件管理
- **技能**：`songsee`（用于音频可视化），此外还需具备以下其中一项技能：
  - `songwriting-and-ai-music`：用于委托他人创作歌词并使用Suno生成音乐提示词
  - `heartmula`：用于使用开源本地模型生成音乐
  - `spotify`：用于寻找现有的音乐曲目
- **输出文件**：`audio/track.mp3`、`audio/beats.json`，可选地还会生成 `audio/track-spectrogram.png` 文件

### 旁白演员 / 叙述者

负责生成旁白音频。该角色会直接调用TTS API生成音频，无需使用Hermes的任何技能（因为任务拆解指导会自动注入到每个任务处理角色中）。用户也可以直接提供预先录制的旁白音频，而无需通过AI生成。

- **工具集**：kanban、终端、文件管理
- **技能**：无需额外技能——任务拆解指导会自动注入到每个任务处理角色中
- **外部API**：ElevenLabs、OpenAI TTS等
- **输出文件**：`audio/voiceover/line-NN.mp3`、`audio/voiceover/timeline.mp3`

### 音效设计师

负责设计音效及环境音。除非项目需求明确要求进行音效设计，否则该角色通常是可选的。

- **工具集**：kanban、终端、文件管理
- **技能**：在为特定音乐曲目设计音效时，可使用 `songsee` 工具进行音频特征可视化
- **输出文件**：`audio/sfx/*.mp3`

## 后期制作角色

### 剪辑师

负责将各个片段拼接成最终成片。使用ffmpeg工具进行视频拼接、淡入淡出处理及转场效果处理。在拼接之前，还会逐一检查每个片段的节奏与质量。

- **工具集**：kanban、终端、文件管理
- **技能**：无需额外技能——任务拆解指导会自动注入到每个任务处理角色中
- **外部工具**：ffmpeg、ffprobe
- **输出文件**：`output/final.mp4`、`output/final-noaudio.mp4`

### 调色师

负责视频的色彩分级处理。这一角色通常是可选的——如果渲染器已经能够生成符合品牌风格的输出，而剪辑师仅负责拼接视频，那么调色师的作用就会显得多余。不过，对于包含大量特写镜头的叙事类电影来说，配备调色师则是很有必要的。

- **工具集**：kanban、终端、文件管理
- **技能**：无需额外技能——任务拆解指导会自动注入到每个任务处理角色中
- **输出文件**：`output/final-graded.mp4`

### 音频混音师

负责将旁白、音乐及音效混合成最终的音频轨道。该角色会调整各元素的音量，确保音乐不会盖过旁白，并统一音频的响度（LUFS标准）。

- **工具集**：kanban、终端、文件管理
- **技能**：无需额外技能——任务拆解指导会自动注入到每个任务处理角色中
- **外部工具**：带有 `loudnorm` 滤镜的ffmpeg，可选地也可使用sox工具
- **输出文件**：`audio/final-mix.mp3`

### 字幕生成师

负责为视频添加字幕、生成SRT格式的字幕文件，并确保视频具备无障碍观看功能。该角色也可以通过Whisper工具从音频中提取字幕。

- **工具集**：kanban、终端、文件管理
- **技能**：无需额外技能——任务拆解指导会自动注入到每个任务处理角色中
- **外部工具**：Whisper（命令行或API接口）、ffmpeg的字幕处理插件
- **输出文件**：`output/captions.srt`、`output/final-captioned.mp4`

### 最终编码师

负责对视频进行最终编码，并根据不同平台的要求生成对应格式的文件——例如Instagram需要正方形格式，TikTok需要竖屏格式，YouTube则需要全高清格式等。

- **工具集**：kanban、终端、文件管理
- **技能**：无需额外技能——任务拆解指导会自动注入到每个任务处理角色中
- **输出文件**：`output/final-1080.mp4`、`output/final-9x16.mp4`等

## 质量控制角色

### 审核员

作为中立的品质把控角色。负责阅读项目需求，观看成片，并针对节奏、同步性、品牌一致性及技术质量等方面提出具体意见。该角色与拍摄指导（在制作过程中负责检查视觉效果）以及剪辑师（在后期拼接阶段进行审核）是不同的。

- **工具集**：kanban、终端、文件管理、视频处理工具、视觉分析工具
- **技能**：无需额外技能——任务拆解指导会自动注入到每个任务处理角色中
- **审核工具**：`video_analyze`（通过多模态大语言模型对完整视频片段进行专业审核）、`vision_analyze`（用于检查单帧画面或缩略图）、ffprobe
- **输出文件**：`review-notes.md`，以及针对各项任务的审核意见

### 品牌合规审核员

专门负责检查内容是否符合品牌规范，包括色彩、字体及声音风格等方面。当品牌指南非常详细时，普通审核员可能会遗漏某些违规之处，此时就需要该角色来确保一切符合品牌要求。- **工具集：** 看板任务、文件处理  
- **技能：** 无——看板任务的相关指导会自动注入到每个处理看板任务的智能体中  
- **输出结果：** 评论内容 + `brand-review.md` 文件  

## 团队组建——最佳实践建议  

- **标准配置：** 1名导演 + 至少1名渲染器 + 1名编辑。  
- 若脚本中的对话、旁白或屏幕文字量超过简短标语的长度，需额外添加**文案撰写员**。  
- 若项目需求包含5个以上不同的剧情节点，且导演尚未制定节点清单，则需添加**故事板设计师**。  
- 若需要多个渲染器实例保持一致的视觉风格，需添加**摄影指导**。（对于仅使用单一工具制作的视频，该渲染器自身的技能配置即可满足需求。）  
- 对于需要逼真视觉效果的叙事类电影，需同时添加**图像生成器**与**图像转视频生成器**。  
- 若项目配有音乐且节奏至关重要（音乐视频必加，说明类视频视情况而定），需添加**音乐监制**。  
- 任何需要旁白或叙事对话的场景，都需添加**配音演员**。  
- 当存在2种及以上音频源时（如人声与音乐、音乐与音效），需添加**音频混音师**。  
- 对于注重无障碍访问的项目（如说明视频、教程，或是默认静音播放的所有平台内容），需添加**字幕生成员**。  
- 对于高重要性项目，需添加**审核员**；快速实验性创作可跳过此步骤。  
- 若需要为多个平台输出不同版本的内容，需添加**最终处理师**。  

## 常见错误做法  

- **让单个渲染器承担所有工作。** 若场景需要使用截然不同的工具（如ASCII图形、3D模型、动态图形），应选用专用类型的渲染器。单个渲染器一次仅能加载一种创意技能，若混用多种风格会导致性能严重下降。  
- **为每个场景单独创建配置文件。** 错误——配置文件是按角色划分的，而非按场景。8个场景通常只需1到2种渲染器配置，而非8种。  
- **创建一个能处理所有任务的“通用”配置文件。** 这比没有专业化配置更糟糕——若所有任务都适用同一配置文件，看板任务分配机制将失效。  
- **重要输出内容不设置审核环节。** 虽然能节省1小时的流程处理时间，但会导致成品存在缺陷。
