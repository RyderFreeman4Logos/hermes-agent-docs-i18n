# twozero MCP 工具参考手册

涵盖 twozero MCP v2.774+（2026年4月版本）中的36种工具。针对多TD实例场景，所有工具均支持可选的`target_instance`参数。

## 执行与脚本编写

### td_execute_python

在TouchDesigner内部执行Python代码并返回结果。该工具可完全访问TD的Python API（如op、project、app等对象）。它会捕获打印语句及最后一个表达式的计算结果。最适合用于：连接线路配置（inputConnectors）、设置表达式（par.X.expr/mode）、查询参数名称，以及编写包含5个及以上操作符的批量创建脚本。若只需创建1-4个操作符，建议使用td_create_operator。

| 参数 | 类型 | 是否必填 | 说明 |
|------|------|----------|------|
| `code` | 字符串 | 是 | 需在TouchDesigner中执行的Python代码 |

## 网络结构

### td_get_network

获取TouchDesigner中指定路径下的操作符网络结构。返回格式为简洁的列表：名称、操作符类型及标志位。首行即为所查询操作符的完整路径。标志位含义如下：ch:N=子节点数量，!cook=禁止Cooking处理，bypass=跳过，private=是否为私有操作符，blocked:reason=被阻塞原因，"comment text"=注释文本。depth参数默认值为0，仅显示当前层级；设置为1时则显示一层子节点（缩进显示）。如需查看更深的层级，可针对具体的COMP路径再次调用该函数。系统操作符（/ui、/sys）默认会被隐藏。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `path` | 字符串 | 否 | 需要检查的网络路径，例如 `/` 或 `/project1` |
| `depth` | 整数 | 否 | 递归的深度层级。0 表示仅当前层级（推荐），1 表示包含 COMP 的直接子节点 |
| `includeSystem` | 布尔值 | 否 | 是否包含系统操作符（/ui、/sys）。默认值为 false |
| `nodeXY` | 布尔值 | 否 | 是否包含 nodeX、nodeY 坐标信息。默认值为 false |

### td_create_operator

在 TouchDesigner（TD）中创建新的操作符（节点）。这是创建操作符的首选方式——可自动处理视图窗口定位、查看器标志以及固定式操作符的显示问题。若需批量创建（5 个及以上操作符），可使用 td_execute_python 配合脚本实现，但需先调用 td_get_hints('construction') 以获取正确的参数名称和布局规则。该功能支持所有 TD 操作符类型：TOP、CHOP、SOP、DAT、COMP、MAT。若未指定父节点，则会在用户当前视图窗口位置处的已打开网络中创建该操作符。在构建容器时，应先创建无父节点的 baseCOMP，然后再以 parent=compPath 的方式创建子节点。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `type` | 字符串 | 是 | 操作符类型，例如 ‘textDAT’、‘constantCHOP’、‘noiseTOP’、‘transformTOP’、‘baseCOMP’ |
| `parent` | 字符串 | 否 | 上级操作符的路径。若未指定，则使用 TD 中当前打开的网络。 |
| `name` | 字符串 | 否 | 新操作符的名称（可选，若不指定则由 TD 自动命名） |
| `parameters` | 对象 | 否 | 需要设置在该操作符上的参数键值对 |

### td_find_op

按名称和/或类型在整个项目中查找操作符。返回 TSV 格式的数据：路径、OPType、标志位。标志位含义：bypass、!cook、private、blocked:reason。如需在代码/表达式中搜索，请使用 td_search；若要查找操作符本身，则使用 td_find_op。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `name` | 字符串 | 否 | 操作符名称中需要匹配的子字符串（不区分大小写）。例如 ‘noise’ 可匹配 noise1、noise2、myNoise。 |
| `type` | 字符串 | 否 | OPType 中需要匹配的子字符串（不区分大小写）。例如 ‘noiseTOP’、‘baseCOMP’、‘CHOP’。使用精确类型可实现精准匹配，使用部分内容则可进行更广泛的搜索。 |
| `root` | 字符串 | 否 | 开始搜索的根操作符路径。默认值为 ‘/project1’。 |
| `max_results` | 数字 | 否 | 需要返回的最大结果数量。默认值为 50。 |
| `max_depth` | 数字 | 否 | 从根节点开始的最大递归深度。默认为无限制。 |
| `detail` | `basic` / `summary` | 否 | 结果的详细程度。‘basic’ 表示仅显示名称/路径/类型（查询速度快）；‘summary’ 表示额外显示连接关系、非默认解析方式及表达式内容。默认值为 ‘basic’。 |
### td_search

在 TD 项目中的所有代码（DAT 脚本）、参数表达式以及字符串参数值中搜索文本。返回格式为 TSV，包含路径、类型（代码/表达式/参数/引用）、行号和文本内容；当 `context` 参数大于 0 时则返回 JSON 格式。单词之间为或运算关系。如需精确匹配短语，请使用引号，例如：'GetLogin "op('login')"'. 若只需快速检查某内容是否被引用而无需获取完整结果，可设置 `count_only=true`。

| 参数 | 类型 | 是否必填 | 描述 |
|------|------|----------|-------------|
| `query` | 字符串 | 是 | 搜索查询词。多个单词表示或运算（满足任意一个即可）。如需精确匹配短语，请用引号括起。例如：'GetLogin getLogin' 可匹配其中任意一个。 |
| `root` | 字符串 | 否 | 搜索的起始操作符路径。默认值为 '/project1'。 |
| `scope` | `all` / `code` / `editable` / `expressions` / `parameters` | 否 | 搜索范围。'code' 仅搜索 DAT 脚本（速度较快，约 0.05 秒）；'editable' 仅搜索可编辑的代码（跳过继承或引用的 DAT 文件）；'expressions' 仅搜索参数表达式；'parameters' 仅搜索字符串参数值；'all' 搜索所有内容（速度较慢，因需扫描所有参数，约 1.5 秒）。默认值为 'all'。 |
| `case_sensitive` | 布尔值 | 否 | 是否区分大小写。默认值为 false。 |
| `max_results` | 数字 | 否 | 返回的最大结果数量。默认值为 50。 |
| `context` | 数字 | 否 | 每个匹配项前后显示的行数，可减少对 td_read_dat 的调用次数。默认值为 0。 |
| `count_only` | 布尔值 | 否 | 仅返回匹配数量而不返回具体结果，适用于快速检查是否存在。 |
| `max_depth` | 数字 | 否 | 从起始路径开始的最大递归深度。默认值为无限制。 |

### td_navigate_to

将 TouchDesigner 网络编辑器视图窗位移动以显示特定的操作符。该功能会打开该操作符所属的父网络，并将视图聚焦在该操作符上。可用于向用户指出问题所在，或在修改操作符之前先导航至该操作符。

| 参数 | 类型 | 是否必填 | 描述 |
|------|------|----------|-------------|
| `path` | 字符串 | 是 | 要导航到的操作符路径，例如 `/project1/noise1` |

## 操作符检查

### td_get_operator_info

获取 TouchDesigner（TD）中特定操作符（节点）的信息。<br>detail='summary'：显示连接关系、非默认参数、表达式以及 CHOP 通道（简化版）。<br>detail='full'：显示上述所有信息，再加上所有带有值/默认值/标签的参数。

| 参数 | 类型 | 是否必填 | 描述 |
|------|------|----------|-------------|
| `path` | 字符串 | 是 | 操作符的完整路径，例如 `/project1/noise1` |
| `detail` | `summary` / `full` | 否 | 详细程度。'summary' = 连接关系、表达式、非默认参数、自定义参数（标有脉冲符号的参数）、CHOP 通道。<br>'full' = summary + 所有参数。默认值为 'full'。 |

### td_get_operators_info

一次调用即可获取多个操作符的信息。会返回一个操作符信息对象数组。建议使用此函数，而非多次调用 td_get_operator_info。

| 参数 | 类型 | 是否必填 | 描述 |
|------|------|----------|-------------|
| `paths` | 数组 | 是 | 操作符的完整路径数组，例如 `/project1/null1`, `/project1/null2` |
| `detail` | `summary` / `full` | 否 | 详细程度。默认值为 'summary'。 |
### td_get_par_info

用于获取 TouchDesigner 操作符类型的参数名称及详细信息。若未指定参数，则返回包含所有参数的简略列表，列明其名称、类型及菜单选项；若指定了参数，则返回这些特定参数的完整详情（包括帮助文本、菜单值及样式设置）。在需要先知晓参数确切名称后再进行设置时，可使用此函数。

| 参数 | 类型 | 是否必填 | 描述 |
|------|------|----------|-------------|
| `op_type` | 字符串 | 是 | TD 操作符类型名称，例如 ‘noiseTOP’、‘blurTOP’、‘lfoCHOP’、‘compositeTOP’ |
| `pars` | 数组 | 否 | 可选参数列表，用于指定需获取完整详情的特定参数名称 |

## 参数设置

### td_set_operator_pars

用于在 TouchDesigner（TD）中设置操作符的参数及相关标志。对于简单的参数更改而言，该函数比 td_execute_python 更为安全。无需编写 Python 代码即可设置参数值、切换旁路/查看器状态等。

| 参数 | 类型 | 是否必填 | 描述 |
|------|------|----------|-------------|
| `path` | 字符串 | 是 | 操作符的路径 |
| `parameters` | 对象 | 否 | 需要设置的参数键值对 |
| `bypass` | 布尔值 | 否 | 设置操作符的旁路状态（复合节点不支持此功能） |
| `viewer` | 布尔值 | 否 | 设置操作符的查看器状态 |
| `allowCooking` | 布尔值 | 否 | 为复合节点设置处理标志。设置为 False 时，内部网络将停止处理（占用 0 CPU）。仅适用于复合节点。 |

## 数据读写

### td_read_dat

读取 TouchDesigner（TD）中 DAT 操作器的文本内容。返回包含行号的完整内容，可用于读取脚本、插件、GLSL 着色器以及表格数据。

| 参数 | 类型 | 是否必填 | 描述 |
|------|------|----------|-------------|
| `path` | 字符串 | 是 | DAT 操作器的路径 |
| `start_line` | 整数 | 否 | 起始行号（从 1 开始计数）。如需从开头读取则可省略该参数。 |
| `end_line` | 整数 | 否 | 结束行号（包含该行）。如需读取到文件末尾则可省略该参数。 |

### td_write_dat

向 TouchDesigner（TD）中的 DAT 操作器写入或替换文本内容。支持完全替换，也可采用类似 StrReplace 的替换方式（old_text -> new_text）。可用于编辑脚本、插件及着色器。但不会自动重新初始化插件。

| 参数 | 类型 | 是否必填 | 描述 |
|------|------|----------|-------------|
| `path` | 字符串 | 是 | DAT 操作器的路径 |
| `text` | 字符串 | 否 | 完整的替换文本。只需使用此项，或同时使用 old_text+new_text，不可同时使用两者。 |
| `old_text` | 字符串 | 否 | 需要查找并替换的文本（在 DAT 文件中必须唯一）。 |
| `new_text` | 字符串 | 否 | 替换后的文本 |
| `replace_all` | 布尔值 | 否 | 若设置为 true，则替换所有出现的 old_text（默认值为 false，要求匹配项唯一）。 |

### td_read_chop

读取 CHOP 的通道采样数据。以数组形式返回各通道的值。当需要获取实际的采样值（如动画曲线、查找表、波形）而非仅通过 td_get_operator_info 获取汇总信息时，可使用此功能。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `path` | 字符串 | 是 | CHOP 操作器的路径 |
| `channels` | 数组 | 否 | 需要读取的通道名称。如省略则读取所有通道。 |
| `start` | 整数 | 否 | 起始样本索引（基于 0）。如省略则从开头开始读取。 |
| `end` | 整数 | 否 | 结束样本索引（包含该索引）。如省略则读取到文件末尾。 |

### td_read_textport

用于读取 TouchDesigner（TD）日志/文本端口（控制台输出）中的最后 N 行内容。可通过此功能查看 TD 中的错误信息、警告以及打印输出。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `lines` | 整数 | 否 | 需要返回的最近行数 |

### td_clear_textport

用于清空 MCP 文本端口日志缓冲区。在开始调试会话或编辑-运行-检查循环之前使用此功能，可确保 td_read_textport 的输出更加集中且简洁。

无参数（可选参数 `target_instance` 除外）。

## 视觉捕获

### td_get_screenshot

在 TouchDesigner（TD）中获取操作符视图的截图功能。该功能会将图像保存为文件，并返回文件的路径，您可使用相应的文件读取工具来查看该图片。截图会展示操作符在其视图中的界面内容，包括 TOP 输出、CHOP 波形图、SOP 几何结构、DAT 表格以及参数用户界面等。您可以利用此功能对任意操作符进行可视化检查，或通过 TD 生成图像以用于您的项目中。该功能的异步两步使用流程如下：第一步——传入“路径”参数启动请求，系统将返回 {'status': 'pending', 'requestId': '...'}；第二步——传入“request_id”参数获取结果，系统将返回 {'file': '/tmp/.../opname_id.jpg'}，随后即可读取该文件查看图像。如果第二步仍返回“pending”状态，请再次调用相关工具后再尝试。

| 参数 | 类型 | 是否必填 | 说明 |
|-------|------|----------|-------------|
| `path` | 字符串 | 否 | 截图操作员的完整路径，例如 `/project1/noise1`。步骤 1 中必须提供此参数。 |
| `request_id` | 字符串 | 否 | 来自步骤 1 的请求 ID，用于获取已生成的截图。 |
| `max_size` | 整数 | 否 | 图像长边的最大像素尺寸（默认值为 512）。设置为 0 可保持操作员的原始分辨率（适用于需要精确控制像素的 UI 工作）。数值越大（如 1024），图像细节越丰富。 |
| `output_path` | 字符串 | 否 | 图像保存的可选绝对路径（例如 `/Users/me/project/render.png`）。若未指定，则保存至 /tmp/pisang_mcp/screenshots/。请使用绝对路径——TD 的工作目录可能与代理程序的不同。 |
| `as_top` | 布尔值 | 否 | 若设置为 true，将直接以 TOP 格式捕获操作员图像（绕过查看器渲染器），从而保留透明度信息。此功能仅适用于 TOP 类型的操作员；如果目标不是 TOP 类型，则会自动切换到查看器模式。当您需要带有透明度的纯净 PNG 图像，例如为其他项目保存生成的图像时，可使用此参数。 |
| `format` | `auto` / `jpg` / `png` | 否 | 图像格式。'auto'（默认值）：在查看器模式下为 JPEG 格式，当 `as_top=true` 时为 PNG 格式。'jpg'：始终为 JPEG 格式（文件体积较小）。'png'：始终为 PNG 格式（无损压缩）。 |

### td_get_screenshots

可一次性获取多个操作符的截图。系统会将图像保存为文件并返回文件路径，您可使用文件读取工具查看这些图片。**两步异步使用流程**：第一步——传入 `paths` 数组启动任务，返回结果为 `{‘status’: ‘pending’, ‘batchId’: ‘...’, ‘total’: N}`；第二步——传入 `batch_id` 获取结果，返回结果为 `{‘files’: [{op, file}, ...]}`，随后即可读取文件查看图片。若仍在处理中，则会返回 `{‘status’: ‘pending’, ‘ready’: K, ‘total’: N}`。

| 参数 | 类型 | 是否必填 | 说明 |
|------|------|----------|------|
| `paths` | 数组 | 否 | 需截取截图的操作符完整路径列表，第一步必需。 |
| `batch_id` | 字符串 | 否 | 第一步生成的批次编号，用于获取已处理完成的截图。 |
| `max_size` | 整数 | 否 | 图像长边的最大像素尺寸（默认为512）。设为0则保持原始分辨率。 |
| `as_top` | 布尔值 | 否 | 若设为true，则直接截取最顶层的操作符（保留透明度），非顶层操作符将转由查看器处理。 |
| `output_dir` | 字符串 | 否 | 可选的目录绝对路径。每个截图会以<opname>.jpg或.png格式保存在该目录中并留存于磁盘。 |
| `format` | `auto` / `jpg` / `png` | 否 | 图像格式。`auto`（默认）：查看器模式下为JPEG格式，`as_top=true`时为PNG格式；`jpg`：始终为JPEG格式（文件较小）；`png`：始终为PNG格式（无损）。 |

### td_get_screen_screenshot

可通过 TD 的 screenGrabTOP 功能截取实际屏幕的截图。该功能会将图像保存为文件，并返回文件的路径，您可使用文件读取工具来查看该图片。与 td_get_screenshot（操作员视图）不同，此功能能够展示用户在显示器上实际看到的内容——包括 TD 窗口、UI 面板等所有元素。在模拟鼠标/键盘输入以验证屏幕上发生的操作时，可选用此功能。典型工作流程为：td_get_screen_screenshot → 读取文件 → td_input_execute → 等待空闲状态 → 再次执行 td_get_screen_screenshot。该功能还支持两步异步处理模式：第一步调用时不传入 request_id，返回值为 {'status':'pending','requestId':'...'}；第二步调用时传入 request_id，返回值为 {'file': '/tmp/.../screen_id.jpg', 'info': '...metadata...'}，随后即可读取该文件查看图像。此外，该 request_id 还可用于后续的 td_screen_point_to_global 操作以进行坐标查询。crop_x/y/w/h 参数所对应的值均为实际屏幕像素值（而非图像像素值），超出屏幕边界的裁剪区域会自动被限制在有效范围内。该功能还具备智能默认设置：若未指定 max_size，则默认为全屏尺寸 1920 像素（便于整体查看）；对于裁剪后的图像，max(crop_w,crop_h) 会被用作最大尺寸限制，从而确保图像保持 1:1 的比例。在 1:1 比例模式下，screen_coord 的计算公式为 crop_origin + image_pixel；否则则依据元数据中的公式进行计算。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `request_id` | 字符串 | 否 | 用于获取已完成截图的请求 ID，该 ID 来自第一步。 |
| `max_size` | 整数 | 否 | 图像长边的最大像素尺寸。若未指定则自动设置为：全屏时为 1920，1:1 比例裁剪时为 `crop_w` 和 `crop_h` 中的较大值。可手动指定该值以覆盖默认设置。 |
| `crop_x` | 整数 | 否 | 屏幕坐标中的左边缘像素值。 |
| `crop_y` | 整数 | 否 | 屏幕坐标中的上边缘像素值（y=0 对应屏幕顶部）。 |
| `crop_w` | 整数 | 否 | 图像宽度，以像素为单位。 |
| `crop_h` | 整数 | 否 | 图像高度，以像素为单位。 |
| `display` | 整数 | 否 | 显示器索引（默认值为 0，即主显示器）。 |

## 上下文与重点说明

### td_get_focus

用于获取 TouchDesigner（TD）中当前用户的焦点信息：已打开的网络、选中的操作符、当前正在使用的操作符，以及鼠标悬停对象（即鼠标光标下方的元素）。重要提示：当用户提到“这个操作符”或“вот этот”时，指的是已被选中/当前正在使用的操作符，而非鼠标悬停对象。鼠标悬停位置仅是随机的鼠标坐标，不应用于判断用户意图。若需立即为所有选中的操作符批量截取截图，可传入 `screenshots=true` 参数——响应结果中将包含一个包含 `batchId` 的 `screenshots` 字段，可通过 `td_get_screenshots(batch_id=...)` 函数来获取该批截图。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `screenshots` | 布尔值 | 否 | 若值为 true，则为所有选定的操作符启动截图批处理。可通过 td_get_screenshots(batch_id=...) 获取截图结果。 |
| `max_size` | 整数 | 否 | 当 screenshots=true 时截图的最大尺寸（默认值为 512）。 |
| `as_top` | 布尔值 | 否 | 当 screenshots=true 时传递给截图批处理功能。 |

### td_get_errors

用于查找 TouchDesigner (TD) 操作符中的错误与警告信息。它会检查操作符的错误、警告，以及无效的参数表达式（如通道缺失、引用错误等）。同时还会汇总并去重日志中的近期脚本错误（包括回溯信息）——例如，1000 个相同的鼠标移动错误会汇总为 1 条记录，显示为 ×1000。若指定了路径，则会检查该操作符及其子节点；若未指定路径，则会检查当前打开的网络项目。若需检查整个项目，可使用 `/` 符号。当用户反馈某功能出错、存在错误、节点显示为红色或出现“горит ошибка”等提示时，可使用此函数。提示：在重现错误之前先调用 td_clear_textport，以便让日志界面保持清晰。提示：当用户抱怨程序“тупит/лагает”（运行卡顿）时，可结合使用 td_get_perf 函数来同时检查错误与性能问题。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `path` | 字符串 | 否 | 需要检查的路径。若省略，则检查当前网络；使用 `/` 可扫描整个项目。 |
| `recursive` | 布尔值 | 否 | 是否递归检查子节点（默认为 true）。 |
| `include_log` | 布尔值 | 否 | 是否包含日志中按唯一签名分类的最新脚本错误信息（默认为 true）。若需重现错误以聚焦结果，可在之前使用 `td_clear_textport`。 |

### td_get_perf

从 TouchDesigner（TD）获取性能数据。返回格式为 TSV：首行为包含帧率/预算/内存概要的表头，随后按处理时间从长到短排序的最慢运算节点。列包括：路径、OPType、cpu/处理时间（毫秒）、gpu/处理时间（毫秒）、cpu/每秒处理数、gpu/每秒处理数、速率、标志位。当用户反馈出现卡顿、帧率过低、性能迟缓等问题时可使用此功能。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `path` | 字符串 | 否 | 需要分析的性能数据路径。若省略，则分析当前网络；使用 `/` 可分析整个项目。 |
| `top` | 整数 | 否 | 需要返回的最慢运算节点数量 |

## 输入自动化

### td_input_execute

向 TouchDesigner 发送一系列鼠标/键盘指令。这些指令会以平滑的贝塞尔曲线轨迹依次执行。函数会立即返回——在继续操作之前，需不断调用 td_input_status()，直至状态变为 ‘idle’。指令类型包括：‘focus’——将 TouchDesigner 置于前台；‘move’——实现平滑鼠标移动：参数为 {type,x,y,duration,easing}；‘click’——执行点击操作：参数为 {type,x,y,button,hold,duration,easing}，其中 hold 表示按住键的时间（单位：秒），duration 表示点击前的平滑移动时间；‘dblclick’——双击操作：参数为 {type,x,y,duration}；‘mousedown’/‘mouseup’——分别用于模拟鼠标按下和释放操作：参数为 {type,x,y,button}；‘key’——模拟按键输入：参数为 {type,keys}，例如 ‘ctrl+z’、‘tab’、‘escape’、‘shift+f5’。在 macOS 系统上，此功能需要开启无障碍访问权限；‘type’——模拟人类打字行为：参数为 {type,text,wpm,variance}，支持与布局无关的 Unicode 字符，且打字速度可变；‘wait’——暂停操作：参数为 {type,duration}；‘scroll’——模拟滚动操作：参数为 {type,x,y,dx,dy,steps}，首先将鼠标移动到 (x,y) 位置，随后以自然的时间间隔分多次发送垂直方向（dy，+向上）和水平方向（dx，+向右）的移动指令，默认步数为 4。鼠标指令可指定坐标空间，选项为 ‘logical’（默认值）或 ‘physical’。在 macOS 上，‘physical’ 指的是通过 td_get_screen_screenshot 获取的实际屏幕像素值，这类坐标会自动转换为 CGEvent 的逻辑坐标。未另有指定的指令将适用顶层的坐标空间。错误处理选项方面，默认值为 ‘stop’，即出现错误时清空指令队列；而 ‘continue’ 则会跳过失败的指令。重要提示：首次使用该功能前，请先调用 td_get_hints('input_simulation')，以了解焦点恢复机制、坐标系统以及相关测试流程。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `commands` | 数组 | 是 | 需按顺序执行的命令字典列表。 |
| `coord_space` | `logical` / `physical` | 否 | 未指定自身坐标空间的鼠标命令所使用的默认坐标空间。`logical` 直接使用 CGEvent 坐标；`physical` 使用从 `td_get_screen_screenshot` 获取的实际屏幕像素，在 macOS 上会自动转换。 |
| `on_error` | `stop` / `continue` | 否 | 出现错误时的处理方式。默认值为 `stop`。 |

### td_input_status

获取 `td_input` 命令队列的当前状态。在调用 `td_input_execute` 后持续轮询，直到状态变为 `idle`。返回值包括：状态（`'idle'`/`'running'`）、当前命令、队列中剩余命令数量以及上次出现的错误信息。

无参数（可选参数 `target_instance` 除外）。

### td_input_clear

清空 `td_input` 命令队列，并立即停止当前执行。

无参数（可选参数 `target_instance` 除外）。

### td_op_screen_rect

获取网络编辑器中某个操作节点的屏幕坐标。返回值为 `{x,y,w,h,cx,cy}`，其中 `cx` 和 `cy` 表示点击的中心点坐标。可利用该功能确定需要在特定操作节点上的点击位置。仅当该操作节点的父网络当前在网络编辑器面板中打开时才有效。

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `path` | 字符串 | 是 | 操作节点的完整路径，例如 `/project1/myComp/noise1` |

### td_click_screen_point

定位到先前由 `td_get_screen_screenshot` 返回的截图中的某一点并点击该点。需传入截图的 `request_id`，以及标准化的横坐标 `u`/`v` 或像素坐标 `image_x`/`image_y`。该功能会使用物理屏幕坐标来排队执行点击操作，因此可直接与从截图中获取的点坐标配合使用。还可通过设置持续时间及缓动效果来控制鼠标在点击前的移动速度。

| 参数 | 类型 | 是否必填 | 描述 |
|------|------|----------|-------------|
| `request_id` | 字符串 | 是 | 由 `td_get_screen_screenshot` 返回的请求标识符。 |
| `u` | 数字 | 否 | 截图区域内的标准化水平位置（0=左侧，1=右侧）。需与 `v` 一起使用。 |
| `v` | 数字 | 否 | 截图区域内的标准化垂直位置（0=顶部，1=底部）。需与 `u` 一起使用。 |
| `image_x` | 数字 | 否 | 返回的截图图像中的水平像素坐标。需与 `image_y` 一起使用。 |
| `image_y` | 数字 | 否 | 返回的截图图像中的垂直像素坐标。需与 `image_x` 一起使用。 |
| `button` | `left` / `right` / `middle` | 否 | 要点击的鼠标按钮。默认为左键。 |
| `hold` | 数字 | 否 | 按下鼠标按钮后保持的时间（秒）。 |
| `duration` | 数字 | 否 | 鼠标在点击前移动到目标位置所需的时间（秒）。 |
| `easing` | `linear` / `ease-in` / `ease-out` / `ease-in-out` | 否 | 鼠标在点击前移动时的缓动效果。 |
| `focus` | 布尔值 | 否 | 若设置为 `true`，则会在点击前将 TD 推至前台，并稍作等待直至获得焦点。 |

### td_screen_point_to_global

将先前通过 td_get_screen_screenshot 获取的截图中的某一点转换为绝对屏幕坐标。需传入截图的 request_id，以及该点在截图区域内的标准化 u/v 值（范围为 0~1），或是返回图像中的实际像素坐标 image_x/image_y。函数会返回绝对物理屏幕坐标、逻辑坐标，以及可直接使用的 td_input_execute 数据包。系统会保留最新截图的元数据，以便后续多个智能体能够根据 request_id 定位对应点。

| 参数 | 类型 | 是否必填 | 说明 |
|------|------|----------|------|
| `request_id` | 字符串 | 是 | 由 td_get_screen_screenshot 返回的请求编号。 |
| `u` | 数值 | 否 | 截图区域内的标准化水平位置（0 表示左侧，1 表示右侧），需与 v 一起使用。 |
| `v` | 数值 | 否 | 截图区域内的标准化垂直位置（0 表示顶部，1 表示底部），需与 u 一起使用。 |
| `image_x` | 数值 | 否 | 返回截图图像中的水平像素坐标，需与 image_y 一起使用。 |
| `image_y` | 数值 | 否 | 返回截图图像中的垂直像素坐标，需与 image_x 一起使用。 |

### td_test_session

| 参数 | 类型 | 是否必填 | 描述 |
|-------|------|----------|-------------|
| `action` | `export_chat_id` / `export_chat` / `submit_report` / `start` / `note` / `import_chat` / `end` / `list` / `pull` | 是 | 操作类型：export_chat_id / export_chat / submit_report / start / note / import_chat / end / list / pull |

| `tags` | 数组 | 否 | （用于 start 操作）用于分类的标签，例如 ['ui', 'layout'] |
| `text` | 字符串 | 否 | （用于 note 操作）观察结果文本；（用于 import_chat 操作）完整对话文本 |
| `outcome` | `success` / `partial` / `failure` | 否 | （用于 end 操作）操作结果：success / partial / failure |
| `summary` | 字符串 | 否 | （用于 end 操作）对所发生事件的简要总结 |
| `result_op` | 字符串 | 否 | （用于 end 操作）用于将结果保存为 result.tox 文件的运算符路径 |
| `session` | 字符串 | 否 | （用于 pull 操作）用于下载的会话名称或子字符串 |
