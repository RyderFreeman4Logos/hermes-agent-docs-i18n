# 避免平庸内容规则

该规则适用于该技能生成的所有输出内容。“平庸内容”指的是模型在基于训练数据分布进行平均处理时产生的结果；而“避免平庸”则是指通过刻意打破这种平均状态来提升输出质量。

## 平庸内容的特征（出现即需拒绝）

- **当前流行的组合表述**。例如“AI驱动的Y”、“区块链X”、“Z领域的Uber”、“运用机器学习技术的健康平台”等——将两个热门名词简单拼接在一起。
- **生产力/健身/食品/旅游领域的内容**。这四个领域是最容易产生平庸内容的类别，比如习惯追踪工具、饮食记录应用、旅行行程规划器、健身指导服务。如果某个创意仅属于这些领域且缺乏独特性，应予以拒绝。
- **模糊的抽象概念**。例如“一个将需要X的人与能提供X的人联系起来的平台”——这只是个分类，而非具体的创意。
- **先找问题再想解决方案的思路**。比如“如果我们用增强现实技术来……”或“想象一个这样的聊天机器人……”。
- **过时且常见的创业项目模板**。比如双边市场、订阅盒服务、零工经济、垂直领域社交网络等。
- **流行营销用语**。如“赋能”、“无缝”、“充分利用”、“创新”、“尖端”、“革命性”、“解锁”、“整体化”、“生态系统”、“旅程”、“颠覆性”、“强大”等——这类词汇绝不应出现在创意描述中。
- **适用于小说或散文的通用设定**。比如“一个小镇”、“一段难以置信的友谊”、“数字时代X领域的变化”等。
- **长度完全相同的5个条目列表**。这种结构很可疑，应使用3个或7个条目，绝不能出现5个结构完全相同的创意。
- **类似Y Combinator项目名的命名方式**。两音节的自造词、省略元音的词汇，以及以.ai为后缀的名称。
- **营销式的语气**。比如“这个创意很棒，因为……”或“它的独特之处在于……”。优秀的创意描述应简洁平实，就像在职艺术家向同行介绍自己的作品那样。

平庸内容的本质特征是：只需修改一个名词，这个创意就可能适用于完全不同的提示词。

## 五项检测标准

生成创意后，需逐一检查以下内容：

1. 是否只需修改一个名词，这个创意就能适用于其他提示词？→ 若是，则为平庸内容。
2. 是否提到了真实存在的人名、地名、材料、机制或作品？→ 若没有，则为平庸内容。
3. 是否至少有一个元素具有新颖性，需要进一步解释？→ 若没有，则为平庸内容。
4. 是否能用具体的感官描述来说明使用、阅读或体验该创意时的感受？→ 若不能，则为平庸内容。
5. 如果将该创意展示给该领域的专业人士，他们是否会觉得尴尬？→ 若会，则为平庸内容。

若通过全部五项检测，则不属于平庸内容；若有两项及以上未通过，则需重新创作。

## 避免平庸的内容技巧

### 1. 先拒绝前三个创意

先在内部生成三个创意并舍弃，再生成另外三个，最终输出后三个。前三个代表常规的生成结果，而后三个则是通过刻意调整才产生的结果。

对于高风险易产生平庸内容的领域（如“AI相关创意”、“创业项目创意”、“习惯追踪工具”、生产力/健身/食品/旅游类内容），则应拒绝前**五个**创意。

### 2. 强制增加具体性

用专有名词替代抽象概念。不要用“一座城市”，而要用里斯本、拉各斯、札幌、马法等具体地名；不要用“一个工作流工具”，而要用以17世纪英国一种刑罚命名的`git`子命令；不要用“一个用户社区”，而要用那230位专门修复复古Tannoy扬声器的爱好者群体。

检验标准：创意中的每个名词都能回答“具体是哪一个？”的问题。

**简单提及技术栈并不算具体**。比如“使用React Native、SQLite、GPT-4、Pinecone、Stripe构建”虽然听起来很具体，但实际上非常泛化——这些技术几乎可以用于任何产品。列出技术栈只是平庸内容的伪装，用来规避简单的具体性检查。真正的具体性应体现在具体的*机制*上，或是真实存在的人名/地名/作品名称，或是某种独特且罕见的材料或限制条件——这类元素能将创意固定到*特定场景*中，无法被替换到其他提示词中。比如“使用嵌入模型”只是简单提及技术，而“根据用户30天内打开过的内容，按语义相似度对未读标签页进行排序”则是一种具体的机制。

### 3. 设置“奇特度预算”

每个创意至少应包含一个需要解释的元素。这个元素不一定是核心部分——有时可以是呈现方式、目标受众、可能出现的问题或衡量标准。如果所有元素都过于常规，应予以拒绝；如果所有元素都过于奇特，则说明创意走到了极端。

### 4. 避免使用热门技术组合

如果你的创意是“X + Y”的形式，且X和Y在过去的18个月内都频繁出现在科技媒体上，那么该创意很可能属于平庸内容。应至少将其中一个元素替换为冷门、过时或与当前领域关联不大的元素。

同时应避免将以下技术概念随意组合：AI/LLM/机器学习、区块链/web3/加密货币、增强现实/虚拟现实/空间计算、物联网/智能家居、可持续发展/气候问题、健康/正念、社区/社交平台、无代码工具、创作者经济、零工经济。

### 5. 使用真实的专有名词

引用真实存在的作品、人物、地点和数据。基于具体细节的创意更难被平均化处理。

| 平庸内容 | 具体内容 |
|---|---|
| “一款帮助作家追踪手稿修改进度的工具” | “一款为小说家设计的、类似`git`的版本控制系统，灵感来自托妮·莫里森在《宠儿》中使用的带编号的活页夹，该系统还包含一个名为`morrison diff`的子命令，能够以朗读形式显示两个活页夹之间的差异” |
| “一款专为跑步者设计的应用” | “一款心率音效转换工具，能将用户的第二区间跑步速度转化为史蒂夫·赖希《18位音乐家的音乐》的节奏——当你放慢速度时，音乐节奏也会随之变缓” |

### 6. 接受创意中的缺陷

平庸的内容往往让人感觉“一切尽在掌控”。而真正的创意往往存在内在问题。应明确指出这些问题，比如“这个方案很难实现，因为……”、“它很可能会在……环节失败”、“有趣的问题是……”。那些没有明确指出缺陷的创意，通常都是未经深入思考的产物。

### 7. 避免使用整数数量的条目

理想的条目数量很少是5或10。建议使用3个（这是能体现差异的最小数量）或7个（这个数字会让人感觉不太对称）。绝不能使用5个结构完全相同的条目。

### 8. 摒弃营销式语气

避免使用“令人兴奋”、“创新”、“革命性”、“颠覆性”、“强大”、“无缝”等词汇。描述创意时应像在职艺术家或工程师向同行介绍作品那样——平实、具体，有时带点自嘲，绝不能带有推销意味。

### 9. 明确说明呈现方式和材料

每个创意都应能回答“它实际上是由什么构成的？”这个问题——是某种语言编写的代码，还是某种格式的纸张？是乐器发出的声音，还是特定尺寸空间中的艺术装置？“一款应用”并不能算作具体的呈现方式，而“一个包含SQLite数据库和Textual TUI界面的200行Python脚本”则属于具体描述。

### 10. 避免使用小说或散文的通用设定

如果小说的创意局限于“小镇”、“难以置信的友谊”、“成长故事”等常见主题，或者散文的内容围绕“X领域的变化”、“技术如何改变Y”等陈词滥调展开，那么这些都属于平庸内容。应将场景设定在鲜有人涉足的地方：俄勒冈州东部的一座废弃谷物仓库、比利时皇家图书馆的手稿修复室，或是里诺市一家本田汽车经销商店周二时的店内场景。

## 输出前的自我检查清单

- [ ] 未使用禁止列表中的营销用语
- [ ] 每个创意都包含至少一个具体的专有名词
- [ ] 每个创意都包含至少一个奇特元素
- [ ] 所有创意的结构都不相同
- [ ] 不存在数量为整数的条目列表
- [ ] 未使用“因为这很令人兴奋”之类的表述
- [ ] 明确说明了呈现方式和材料
- [ ] 小说/散文的场景并非通用设定
- [ ] 产品/创业项目并非Y Combinator式的典型模板
- [ ] 技术层面：描述的是具体的机制，而非抽象的分类

如果有三项及以上检查未通过，则需重新生成创意。

## 当用户要求“简单”创意时

不要提供平庸的内容，而应给出一个经过限制但相对简单的创意（可参考wttdotm的“高概念低投入”理念：创意本身很出色，但实现方式较为随意，可能仅需半天时间即可完成）。以简单为名的平庸内容依然属于平庸内容。
