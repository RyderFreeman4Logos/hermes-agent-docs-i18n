# ohmsha预设——运用视觉隐喻的科普漫画风格

## 基础配置

| 维度 | 值 |
|------|-----|
| 艺术风格 | 漫画 |
| 语气风格 | 中性 |
| 页面布局 | 网络连环画（默认） |

对应参数为：art=manga, tone=neutral

## 特殊规则

该预设除了艺术风格与语气风格外，还包含其他特殊规则。一旦选择`ohmsha`预设，以下所有规则都必须严格执行。

### 视觉隐喻要求（至关重要）

每一个技术概念都必须通过视觉隐喻来呈现：

| 概念类型 | 可视化方式 |
|---------|------------|
| 算法 | 用于演示处理流程的装置/机器 |
| 数据结构 | 角色可以进入并探索的实体空间 |
| 数学公式 | 在环境中可见的变换过程 |
| 抽象过程 | 粒子/物体的实体化流动 |

**错误示例**：角色指向黑板进行讲解  
**正确示例**：角色使用“概念可视化装置”，进入隐喻空间

### 视觉隐喻示例

| 概念 | 错误表现（对话式） | 正确表现（视觉隐喻） |
|---------|-------------------|----------------------|
| 注意力机制 | 角色指向黑板上的公式 | “注意力手电筒”装置在黑暗房间中照亮关键词 |
| 梯度下降 | “该算法可最小化损失” | 角色乘坐球体从山谷中滚下 |
| 神经网络 | 带有箭头的示意图 | 由发光生物构成的动态网络，彼此传递信息 |
| 过拟合 | “模型记住了数据” | 角色穿着只能保持单一姿势的服装 |

### 角色设定（必须包含）

**默认设置：使用哆啦A梦系列角色**，除非用户明确要求自定义角色。

| 角色类型 | 默认角色 | 外貌特征 | 性格特点 |
|---------|----------|----------|----------|
| 学生（角色A） | 大雄（Nobita） | 男孩，10岁，戴圆框眼镜，黑色头发，黄色衬衫，深蓝色短裤 | 困惑不解，会提出基础但关键的问题，代表读者 |
| 导师（角色B） | 哆啦A梦（Doraemon） | 蓝色机器猫，白色肚子，4D口袋，红色鼻子，金色铃铛 | 学识渊博且耐心，善于利用各种装置作为技术概念的隐喻 |
| 障碍角色（角色C） | 胖虎（Gian） | 矮胖男孩，小眼睛，橙色衬衫 | 代表误解或数据中的“噪声”因素 |
| 辅助角色（角色D） | 静香（Shizuka） | 可爱的女孩，黑色短发，粉色连衣裙 | 会提出澄清性问题，提供不同的视角 |

**重要提示**：这些哆啦A梦系列角色是`ohmsha`预设的默认角色。除非用户另有要求，否则必须使用这些特定角色来生成角色定义。

如需使用自定义角色：请让用户提供角色与角色的对应关系（例如：`Student:小明, Mentor:教授`）。

### 页面标题规范

每一页都必须有叙事性标题（而非章节标题）：

**错误示例**：“第1章：Transformer简介”  
**正确示例**：“大雄无法理解任何人的那一天”

### 装置呈现方式

在介绍某个概念时，需遵循以下步骤：

1. 学生通过视觉符号（？、螺旋状眼睛）表达困惑
2. 导师以戏剧化的方式，伴随闪光效果展示装置
3. 用粗体显示装置名称并加以说明
4. 开始演示——学生进入隐喻空间

### 结尾要求

最后一页必须包含以下元素：

1. 学生展示其对概念的理解（实际应用该概念）
2. 回扣开篇提出的问题（现已解决）
3. 导师露出满意的表情
4. 可选：暗示下一个主题

### 禁止对话式场景

**至关重要**：角色必须通过行动来展现内容，而非仅靠对话解释。

每个分镜都应展示：
- 正在进行的动作
- 正在演示的隐喻
- 角色与概念空间的互动
- **禁止**：两个角色面对面对话的场景

### 特殊视觉元素

| 元素 | 使用方式 |
|------|----------|
| 装置展示 | 通过闪光效果进行戏剧化的呈现 |
| 概念空间 | 采用圆角边框及发光边缘，营造“想象模式”氛围 |
| 信息显示 | 用全息界面风格呈现技术细节 |
| 领悟时刻 | 使用放射状线条与光爆效果 |
| 困惑状态 | 显示螺旋状眼睛，角色头顶上方出现问号 |

## 质量评估标准

- ✓ 每一个概念都通过视觉隐喻呈现
- ✓ 角色始终在行动，而非仅限于对话
- ✓ 学生与导师的角色关系清晰明确
- ✓ 通过装置与道具辅助解释概念
- ✓ 具有富有表现力的漫画风格情绪表达
- ✓ 依靠视觉设计而非大量文字来传递信息密度
- ✓ 每页都有叙事性标题
