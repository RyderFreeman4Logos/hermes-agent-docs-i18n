# Ohmsha漫画风格指南

使用`ohmsha`预设制作教育类漫画的指导方针。

## 角色设定

| 角色 | 默认值 | 特点 |
|------|---------|------|
| 学生（角色A） | 大雄 | 困惑，会提出基础但关键的问题，代表读者 |
| 导师（角色B） | 哆啦A梦 | 博学且耐心，常将道具作为技术概念的隐喻 |
| 反派（角色C，可选） | 胖虎 | 代表误解或数据中的“干扰因素” |

自定义角色：需向用户询问角色与名称的对应关系（例如：`学生：小明，导师：教授，反派：Bug怪`）。

## 角色参考表风格

对于Ohmsha风格，应采用漫画/动画风格，具体要求包括：
- 通过夸张的表情提升表达清晰度
- 简洁且具有辨识度的轮廓设计
- 鲜艳、饱和度高的色彩搭配
- 为搞笑反应添加Q版/超变形版本角色

## 大纲规范模块

所有Ohmsha风格的大纲都必须以以下内容开头：

```markdown
【漫画规格单】
- Language: [Same as input content]
- Style: Ohmsha (Manga Guide), Full Color
- Layout: Vertical Scrolling Comic (竖版条漫)
- Characters: [List character names and roles]
- Character Reference: characters/characters.png
- Page Limit: ≤20 pages
```

## 视觉隐喻规则（至关重要）

**绝不可**使用“对话框式”面板。每一个技术概念都必须通过以下方式呈现：

1. **具体的小装置/道具**——让角色能够手持、操作或用来演示
2. **动作场景**——通过角色的行为来直观展现该概念
3. **视觉化环境**——让角色置身于象征性的空间之中

### 示例

| 概念 | 错误示范（对话框式） | 正确示范（视觉隐喻） |
|------|---------------------|------------------------|
| 词嵌入 | 角色们讨论向量概念 | 哆啦A梦拿出“词向量压缩机”，将书本压缩成彩色小球 |
| 梯度下降 | 解释数学公式 | 大雄在类似山谷的地形上滚球，寻找最低点 |
| 神经网络 | 黑板上的示意图 | 角色们走进由发光节点构成的网络迷宫 |

## 页面标题规范

避免使用类似AI生成的“标题：副标题”格式，应采用叙事性描述：

- ❌ “第3页：神经网络简介”
- ✓ “第3页：海量单词将大雄淹没，哆啦A梦拿出‘词向量压缩机’”

## 结尾要求

- **禁止**使用通用结尾语，如“你会做出什么选择？”、“感谢阅读”
- 结尾应为：技术要点总结，或角色实现一个小目标
- 最后一幅画面：应体现完成感，而非悬而未决的问题

### 合格的结尾示例

- 学生成功应用所学概念
- 以视觉方式呼应开篇的问题，并将其解决
- 导师进行总结，同时学生展示自己的理解程度

### 不合格的结尾示例

- “你认为如何？”这类开放式问题
- “感谢阅读本教程”
- 未给出解决方案的悬念结尾

## 布局偏好

Ohmsha风格通常采用以下布局：
- `webtoon`（垂直滚动）——首选格式
- `dense`——适用于信息量较大的章节
- `mixed`——用于节奏多变的内容

在教育类内容中，请避免使用`cinematic`和`splash`布局。
