# 社交媒体内容日历规划

用于在选定的社交媒体平台上制定详细的发布计划。该功能负责管理活动结构、帖子需求文档、不同平台的适配方案、内容审核流程以及发布验证；而诸如 `xurl` 这类平台专用功能则负责处理相应的 API 命令。对于没有对应连接器的平台，验证后的内容仅会以已通过审核的草稿形式提交给用户的日程管理工具，而非直接完成发布。

## 适用场景

- “规划下个月的社交媒体发布日历。”
- “将此次产品发布转化为适用于 X、领英、Instagram 和 TikTok 的帖子。”
- “起草并安排营销活动的发布时间。”
- “将这些文章或视频转换为适合社交平台的内容。”

**不推荐用于**：单次性的临时发布（此类场景可直接使用平台专用功能）。

## 操作步骤

### 1. 明确活动约束条件

需记录活动的目标、目标受众、宣传信息/产品亮点、涉及的平台、时间范围、发布频率、风格定位、允许或禁止使用的声明内容、链接地址、追踪规则、本地化要求，以及内容审核和发布的权限归属。只有当每条拟发布的帖子都具备明确的商业目的时，此步骤才算完成。

### 2. 整理素材资源

使用 `read_file` 和 `web_extract` 工具收集经过核实的产品信息、新品发布资讯、相关文章、媒体资料、经授权的客户评价、品牌资产以及关键日期等信息。同时需标注各信息的责任人和有效期。只有当发现无依据的声明或缺失的素材时，才需要执行此步骤。

### 3. 制定主题与发布时间表

打造内容组合的平衡性，涵盖教育类、实据类、产品类、社区互动类、活动资讯类、幕后花絮类以及对话交流类内容。同时需结合各平台的发布节奏与营销活动的里程碑节点。当所有内容的日期、平台、主题及目标能够形成有序的日程安排，且避免重复发布相同内容时，即视为完成。

### 4. 撰写针对不同平台的文案要点

针对每篇帖子，需明确其吸引点、核心信息、格式要求、文案长度、行动号召、链接地址、素材尺寸/内容规格、无障碍文本说明、标签及提及对象，以及成功评估指标。应根据不同平台的特点进行针对性调整，而非直接复制粘贴。当创作者无需依赖额外背景信息即可完成素材制作时，即视为完成。

### 5. 起草文案与准备素材

使用 `humanizer` 工具来设定内容风格；在需要视觉素材时，通过 `image_generate` 工具生成相关图片。在确保内容事实准确、保持整体营销风格一致的前提下，还需遵循各平台的规范要求。当每个日程时段都对应着已起草的文案及素材准备状态时，即视为完成。

### 6. 进行编辑与风险审核

需检查内容的真实性、语气表达、重复程度、版权许可情况、无障碍性、披露要求、链接指向、内容时效性以及应对危机的能力。需为每篇内容标注“草稿”“需审核”或“已通过”，严禁直接从草稿状态发布内容。当所有帖子都明确其处理状态及负责人后，即视为完成。

### 7. 安排发布或移交处理

展示已通过审核的帖子列表。仅使用平台支持的技能（如 X 平台的 `xurl`）来发布或安排已通过审核的帖子；对于没有相应连接器的平台，则将已通过审核的帖子内容、相关资源及发布时间等信息传递给用户的排程工具，并将这些时段标记为“已移交”状态而非“已发布”。对于实际已发布的帖子，需反馈其排程时间、账号信息、内容预览以及服务提供商提供的帖子/任务编号。当日历中每个时段都显示出已确认的发布或移交状态时，即表示流程完成。

## 常见问题

- 在所有平台上使用完全相同的帖子内容。
- 用低价值的重复性帖子填满发布节奏。
- 发布未经核实的数据、用户评价或未来承诺的内容。
- 将生成的资源准备完成误认为是帖子已安排发布。
- 对于那些帖子仅在草稿阶段就已完成移交的平台，却声称其处于“已排程”状态。

## 核实要点

- [ ] 每篇帖子都对应着具体的营销目标以及经过核实的声明清单。
- [ ] 没有任何帖子是从“草稿”或“需审核”状态直接发布的。
- [ ] 已发布的帖子具有服务提供商确认的编号，而已移交的帖子也会被明确标注为此类状态。
- [ ] 在进行任何发布操作之前，都必须检查相关权限、许可及披露要求。
