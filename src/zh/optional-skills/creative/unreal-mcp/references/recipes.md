# Unreal MCP — 已验证的配方

从简明的英文需求描述到最终渲染结果的完整构建流程。这些配方均基于发现契约编写，因为实际可用的工具集会因项目而异：每一步都会明确指定**用于定位的工具能力**（通过 `list_toolsets` / `describe_toolset` 实现）以及需输入的**确切参数值**——而非硬编码的工具名称，因为在插件仍处于测试阶段时，工具名称可能会发生变化。

## 配方语法

每个步骤包含四个部分：

    **意图**：说明该步骤要实现的目标  
    **发现**：指定要使用的工具集或工具能力（通过 `describe_toolset` 定位）  
    **参数值**：确切的参数或数值（来自 `scene-craft.md`）  
    **验证**：用于证明步骤已成功的查询结果或截图  

调用格式为：`call_tool`，传入 `toolset_name`、`tool_name` 以及符合指定结构的 `arguments` 对象——结果会在同一轮处理中返回。

所有配方都需遵循以下光照规则：为生成的每个光源设置 **Mobility = Movable**（可移动）——Lumen 光照系统会忽略 Static/Stationary 类型的光源，而这正是导致光照效果异常的常见原因。

每个配方都需要执行一次会话初始化步骤：

1. 调用 `list_toolsets`，记录所有工具集的完整名称（例如 `editor_toolset.toolsets.scene.SceneTools`、`EditorToolset.EditorAppToolset`）。  
2. 对后续需要使用的每个工具集调用 `describe_toolset`，将对应的结构信息缓存起来。  
3. 查询当前关卡（通过 `SceneTools.get_current_level`），并遍历场景中的所有元素：使用 `find_actors` 查找 DirectionalLight、SkyAtmosphere、SkyLight、ExponentialHeightFog、PostProcessVolume、VolumetricCloud 等对象。**先配置已存在的场景元素，仅生成缺失的部分**——模板关卡通常已包含大部分此类元素，若重复添加则会导致画面过曝。  
4. 读取现有太阳的 `intensity` 值——该数值可反映场景的曝光校准情况（模板关卡的曝光值通常设置为 `intensity: 10`，而非实际物理单位“勒克斯”；在应用 `scene-craft` 中的绝对数值之前，请先参考注意事项 12b）。  
5. 确定验证方式：使用 `EditorAppToolset.CaptureViewport` 并结合 `captureTransform` 作为虚拟摄像机——无需手动操作视口。

在标有 💾 的每个阶段结束后，需保存当前关卡及所有相关资源包。整个过程中每次只能调用一个工具函数，严禁批量调用。

## 配方 A — 日间户外空地（先构建遮挡物）

**需求描述**：“一个阳光充足的空地，有一些岩石和一条小路”

**阶段 1 — 构建场景基础结构**

- **意图**：创建天空、太阳及大气层，并确保它们之间能够相互关联。  
- **发现**：用于生成场景元素的工具能力（按对象类型生成）。  
- **参数值**：生成 `SkyAtmosphere`、`SkyLight`（用于实时渲染）、旋转角度为 (0, −55, 40) 的 `DirectionalLight`（对应滚转、俯仰、偏航角度），强度设为 90,000 勒克斯，温度为 5,800 开尔文，并开启“大气阳光”效果；同时生成密度为 0.008 的 `ExponentialHeightFog`。  
- **验证**：检查场景元素列表，确认这四种元素均存在；截图应显示为白天景象而非纯黑色（若为黑色，则需检查曝光设置——参见阶段 3）。

**阶段 2 — 构建地面与遮挡物**

- **意图**：创建可行走的地面平面。  
- **发现**：从资源文件中生成对象的工具能力。  
- **参数值**：使用 `/Engine/BasicShapes/Plane.Plane` 在坐标 (0,0,0) 处生成地面，尺寸设为 100×100 米，并为其添加标签 `Ground`。  
- **意图**：用基础几何体构建岩石群与小路轮廓（若项目中没有合适的模型，可先用这些几何体作为临时替代）。  
- **参数值**：生成 5–9 个 `/Engine/BasicShapes/Cube.Cube` 对象，将它们随机分布在以原点为中心、半径为 ±2,000 厘米的范围内，尺寸在 (1.5,1.5,1) 到 (4,3,2) 之间随机变化，偏航角度在 0–360° 之间随机分布，同时将它们向下压低 10–30 厘米，确保没有物体悬空。小路则由 6–10 个扁平化的立方体构成，尺寸约为 (1.2,0.8,0.05)，呈蜿蜒状铺设在地面之上。  
- **验证**：从与地面平齐的高度（摄像机 Z 值约为 165）沿小路方向拍摄截图，确认岩石形态各异、无物体悬空，且其尺寸与 180 厘米的参考标准相符（可临时放置一个高 180 厘米的圆柱体作为参照物，检查完成后删除）。💾

**阶段 3 — 调整曝光与氛围**

- **意图**：实现稳定的曝光效果。  
- **发现**：用于生成 PostProcessVolume 并设置其属性的工具能力。  
- **参数值**：将 PPV 的 `unbound` 参数设置为 true，曝光模式设为 Manual，EV100 对应的亮度值为 14.5。  
- **验证**：截图应显示画面明亮但不过曝，阴影清晰可辨。

**阶段 4 — 生成最终结果**

- **意图**：输出主体物体的高清静态图像。  
- **参数值**：从预定的拍摄视角生成 `HighResShot 3840x2160` 格式的图像（拍摄视角规则参见配方 C 的阶段 2）。  
- **验证**：确认 `Saved/Screenshots` 目录中存在该图像文件，并使用 `vision_analyze` 工具对照需求描述进行检查；若画面过于平淡，可再次调整光照的偏航角度或雾效强度。💾 最后需报告所有场景元素的标签及位置信息。

## 配方 B — 氛围感强的实用照明室内场景

**需求描述**：“夜晚的昏暗舒适房间，有温暖的灯光，窗外透进蓝色的月光”

**阶段 1 — 用基础几何体构建房间框架**

- **参数值**：地面使用一个位于 (0,0,−10) 坐标、尺寸为 (6,6,0.2) 的立方体，对应 6×6 米的房间大小。四面墙则分别由尺寸为 (6,0.2,3) 和 (0.2,6,3) 的立方体构成，将它们放置在相应轴向上的 ±300 厘米位置，Z 值设为 140（即墙高为 280 厘米，紧贴地面；墙顶的 Z 值约为 290）。天花板则使用尺寸为 (6,6,0.2) 的立方体，Z 值也设为 290——建议最后生成天花板，这样在拍摄时可以看到房间内部的结构。房间设置一扇窗户：在某面墙上留出开口，可通过两个较短的墙段构成，开口大小为 120×120 厘米，窗台高度为 90 厘米。  
- **验证**：从上方及房间内部拍摄截图，确认门和窗的高度符合预期。

**阶段 2 — 设置照明（本配方的核心步骤）**

- **意图**：消除太阳光源，使场景呈现夜间氛围。  
- **参数值**：如果模板关卡中已有 `DirectionalLight`，则将其强度降至 0.05 勒克斯，温度设为 4,300 开尔文，俯仰角度设为 −20°，并调整偏航角度使其光线能穿过窗户——这部分光线可模拟月光效果。同时将 `SkyLight` 的强度降低到约 0.05–0.1 勒克斯。  
- **意图**：添加温暖的实用照明。  
- **参数值**：在灯光所在位置（例如角落的桌子上，Z 值约为 120）放置一个 `PointLight`，亮度设为 800 流明（或约 64 坎德拉），温度为 2,700 开尔文，衰减半径设为 600 厘米，光源半径设为 10 厘米，这样能产生更柔和的阴影。  
- **意图**：在窗户边缘添加冷色调的光线。  
- **参数值**：在窗外放置一个 `SpotLight`，使其光线能够穿过窗户照射进来：亮度设为 2,000 流明，温度设为 6,500–8,000 开尔文（若不使用月光效果，则可省略此步骤）；光束的内锥角和外锥角分别设为 25° 和 50°。  
- **意图**：根据昏暗的室内环境调整曝光参数。  
- **参数值**：将 PPV 的 `unbound` 参数设置为 true，曝光模式设为 Manual，EV100 对应的亮度值为 4.5；同时添加雾效，使用密度为 0.015 的 `ExponentialHeightFog`，并开启体积雾效；此外还将实用灯光的体积散射强度设置为 2–4，以增强灯光的发光效果。  
- **验证**：从房间角落、Z 值约为 160 的位置拍摄截图，应能看到灯光周围形成温暖的照明区域，窗外则有冷色调的光线照射进来，阴影深邃但依然清晰可辨。温暖与冷色调的对比正是该场景的核心效果——可通过调整各光源的强度来优化效果（切勿同时调整两种光源的强度），直到达到理想效果。💾

**阶段 3 — 完善细节并输出最终结果**

- **参数值**：如果项目中包含 Starter Content，可替换基础几何体为 `/Game/StarterContent/Props/SM_TableRound`、`SM_Chair`、`SM_Lamp_Ceiling` 等模型，并为地面和墙面分别应用 `M_Wood_Pine` 和 `M_Basic_Wall` 材质。若没有这些资源，可为基础几何体分配具有温暖中性色调的 MaterialInstances。  
- **验证**：最终生成 `HighResShot 3840x2160` 格式的图像，再次使用 `vision_analyze` 工具进行检查，💾 然后报告结果。

## 配方 C — 黄金时刻风格的电影级静态图像（摄像机构图技巧）

**需求描述**：“营造出黄金时刻的氛围，并为 <主体对象> 拍摄一张电影风格的静态图像”

**阶段 1 — 调整光线以呈现黄金时刻效果**

- **参数值**：使用 `DirectionalLight`，将其强度设置为 12,000 勒克斯，温度设为 3,200 开尔文，俯仰角度设为 −8°，并调整偏航角度，使太阳光位于摄像机轴线的后方、距离摄像机 30–60° 处，位于主体对象的背后——这样能形成边缘光和长阴影，避免从摄像机正面直接照射。同时添加密度为 0.02 的雾效及体积雾效，太阳光的体积散射强度设置为 2–6。将 PPV 的 EV100 值设为 11。  
- **验证**：截图应显示明显的长阴影，以及主体对象边缘的温暖边缘光效果。

**阶段 2 — 设置摄像机**

- **意图**：在不干预用户视口的情况下，拍摄出具有完美构图的静态图像。  
- **发现**：使用 `EditorAppToolset.CaptureViewport` 并结合 `captureTransform` 作为虚拟摄像机——对于静态图像而言，无需使用 CineCamera 或手动操作视口。  
- **参数值**：首先确定拍摄位置——根据镜头等效视角计算主体对象与摄像机的距离，若拍摄的是模型或纪念碑类物体，建议将摄像机置于距离物体约 500–800 厘米处，物体高度为 120–160 厘米；随后调整摄像机旋转角度，使主体对象位于画面的三分线交叉点上，地平线则位于上三分之一或下三分之一位置。为了增强画面的气势，可让摄像机略微向上倾斜（角度在 +2° 到 +5° 之间），这样既能确保天空和地平线都出现在画面中，又能避免画面过于平视。若用户希望在实际关卡中使用带有景深效果的 CineCameraActor，或需要使用序列拍摄功能，则需先生成 `/Script/CinematicCamera.CineCameraActor` 对象，通过 ObjectTools 调整其 CineCameraComponent 的焦距、光圈及对焦参数，然后再使用与摄像机变换矩阵相匹配的 `captureTransform` 进行渲染。  
- **验证**：首先以视口分辨率进行渲染测试；之后可快速调整构图参数，最终确定最佳拍摄参数后生成最终图像。

**阶段 3 — 输出最终结果**

- **参数值**：通过已设置好的摄像机生成 `HighResShot 3840x2160` 格式的图像（或用户指定的其他分辨率）。若需要制作序列或转盘式动画而非静态图像，则需使用包含 Camera Cut 轨道的 Level Sequence 以及 Movie Render Queue 进行渲染——这属于独立的任务，需特别注意首次渲染时可能出现的着色器编译延迟问题。  
- **验证**：读取生成的图像文件，使用 `vision_analyze` 工具进行检查：确认是否存在边缘光效果？焦点是否在正确的平面上？地平线位置是否偏移？最多可调整两次参数，之后即可输出最终结果，同时需提供文件的存储路径以及所有已进行的修改信息。💾

## 配方 D — 导入资源并填充场景

**需求描述**：“这里有一个 model.fbx 文件或 Fab 格式的资源——请在喷泉周围放置一圈这样的资源”

**阶段 1 — 导入资源**

- **意图**：将资源文件导入到 `/Game/Imported` 目录中，且导入过程不会导致界面卡顿。  
- **发现**：用于资源导入的工具能力（如果系统中没有现成的导入工具，则需要编写自定义工具集，该工具集需基于 `unreal.AssetImportTask` 并设置 `automated=True` 参数——相关细节参见 tool-surface.md；正是这个 `automated` 参数能够防止模态式导入对话框阻塞整个 MCP 工作流程）。  
- **参数值**：将资源保存到 `/Game/Imported` 目录中，并确保自动保存。  
- **验证**：通过查询生成的较长资源文件名来确认资源是否已成功导入；在原点位置生成一个该资源的实例，拍摄截图，并将其尺寸与 180 厘米的参考标准进行对比——因为大多数 DCC 软件输出的模型尺寸通常会有 100 倍的误差（单位混淆，即使用米而非厘米）。可通过调整场景元素的缩放比例或重新导入时进行单位转换来解决此问题。

**阶段 2 — 在场景中分布资源**

- **意图**：在中心点 C 的周围均匀分布 N 个该资源实例，形成一圈。  
- **参数值**：对于 i 从 0 到 N−1 的每个数值，计算角度 θ = 360·i/N，然后确定位置坐标为 C + (r·cosθ, r·sinθ, 0)，其中 r 为喷泉的半径加上一定的间距（例如 350 厘米）；同时将每个实例的偏航角度设置为 θ + 90°，这样每个实例都会朝向中心方向（若希望面向外部，则可将偏航角度改为 θ + 270°——建议先生成一个实例并检查其朝向）。依次生成每个实例，确认其朝向正确后，再逐个生成剩余的实例。  
- **验证**：通过查询实例数量来确认实际生成的实例数是否与预期值 N 相符；从上方（摄像机 Z 值约为 1,500，从上往下俯视）拍摄截图，检查各实例之间的间距是否均匀；同时从与地面平齐的高度拍摄截图，确认所有实例的尺寸是否合理。💾

**阶段 3 — 输出最终结果**

- **报告内容**：包括资源的存储路径、带有标签前缀的 N 个实例信息、已保存的关卡文件，以及作为 MEDIA 文件路径的场景概览图和从不同角度拍摄的截图。

## 当某个配方缺少所需的功能时

如果发现某个步骤没有可用的工具功能（例如没有用于导入资源的工具，也没有用于生成 `HighResShot` 图像的命令行工具等）：

1. 直接明确说明情况，切勿强行模拟该步骤。  
2. 提供自定义工具集的路径（参见 tool-surface.md）——通常一个包含约 20 行 Python 代码的工具集即可填补功能空白；该工具集需要先调用 `RefreshTools` 函数并重启会话，才能在 MCP 系统中生效。  
3. 或者直接将用户可在编辑器 Python 控制台或命令行中直接运行的单行代码提供给他们，确保代码内容完全准确。

绝不能在没有对应验证结果的情况下声称某个阶段已经完成。用户无法替你检查编辑器中的设置——截图才是他们能够直接看到的真实画面。
